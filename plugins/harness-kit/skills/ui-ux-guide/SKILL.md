# ui-ux-guide — 사용자가 다음 단계로 넘어가게 만드는 절차

좋은 화면은 **사용자가 지금 무엇을 해야 하는지 한눈에 알고, 그것을 하면 다음으로 넘어가는** 화면이다.
이 스킬은 그 상태를 만들기 위한 **6단계**이고, 각 단계는 **완료 기준**을 채워야 다음으로 간다.
원칙 본문은 [PRINCIPLES.md](PRINCIPLES.md) 에, 완료 게이트는 [CHECKLIST.md](CHECKLIST.md) 에, 레포 계층 초안은 [REPO_TEMPLATE.md](REPO_TEMPLATE.md) 에 있다.

**계층 규칙** — 공용(이 스킬) → 레포 문서 → 디렉토리 `CLAUDE.md` 순으로 좁아지고, **좁은 쪽이 이긴다.**
공용은 "무엇이 좋은가", 레포는 "이 제품의 사용자에게는 무엇이 좋은가"다. 레포 문서 없이 공용만으로 화면을 만들지 않는다.

**작업 크기와 무관하다.** 버튼 하나를 옮겨도 6단계를 지난다. 해당 없는 단계는 "해당 없음 — 이유" 한 줄로 통과한다. 건너뛴 단계는 보고에 적는다.

## 프로필 — 프로젝트 고유값을 읽는 곳

이 스킬은 프로젝트 고유값을 본문에 갖지 않는다. 레포 루트 `harness.config.mjs` 의 `project` 블록에서 읽는다(슬롯 정의는 harness-kit README 「프로젝트 프로필」).

- 이 스킬이 읽는 슬롯: `docs.uiUxRules` · `commands.fe.dev` · `commands.fe.devMock`
- **값이 없으면 지어내지 않는다.**
  - 슬롯 키가 없으면 그 자리에서 멈추고 사용자에게 묻는다.
  - `null` 은 "해당 없음으로 판단됨"이다.
  - 예: `docs.uiUxRules: null` 은 아직 문서가 없다는 판단이다. 그러면 Stage 0 의 초안 경로로 간다.

---

## Stage 0 — 자리 잡기: 누가, 어디서, 무엇을

1. 레포 계층 문서를 연다. `docs.uiUxRules` 가 가리키는 문서다.
   - 슬롯 키가 아예 없으면 관례 위치(`docs/rules/ui-ux.md` → `docs/UX.md` → `docs/ui-ux.md`)를 찾아본다. 찾은 경로는 사용자에게 확인받는다.
   - **문서가 없으면** `REPO_TEMPLATE.md` 를 채워 초안을 만든다. 이 초안을 이번 작업의 첫 산출물로 사용자에게 보인다.
   - 초안의 빈칸은 코드(토큰 파일·공통 컴포넌트·라우트)에서 채운다. 코드로 알 수 없는 것(주 사용자·기기·어투)만 묻는다.
2. 이번 화면의 **사용자·기기·과업**을 한 줄로 적는다.
   - 예: "고객센터 상담원이 데스크톱에서 전화를 받으며 30초 안에 주문을 접수한다."
3. 이 과업이 **끝났다고 사용자가 아는 순간**이 무엇인지 적는다. 그것이 흐름의 종점이다.

**완료 기준:** 레포 문서가 열려 있고(또는 초안이 만들어졌고), "누가·어디서·무엇을·언제 끝나나" 네 가지가 한 줄씩 적혔다.

## Stage 1 — 흐름: 점진적 공개로 단계를 자른다

사용자가 한 번에 하나만 결정하도록 과업을 단계로 나눈다. **한 화면(또는 한 영역) = 한 결정.**

단계표를 만든다:

| 단계 | 사용자가 보는 것 | 사용자가 하는 것 | 다음으로 넘어가는 조건 | 되돌아가는 길 | 막혔을 때 보이는 말 |
| - | - | - | - | - | - |

규칙:
- **다음 행동은 항상 하나가 눈에 띈다.**
  - 주 행동 버튼은 단계마다 하나를 둔다. 나머지는 보조로 낮춘다.
- **어디까지 왔는지 보인다.**
  - 3단계 이상이면 진행 표시(N/M·단계명)를 둔다.
  - 2단계 이하는 다음 행동 버튼의 이름이 진행 표시를 대신한다("다음" 대신 "주문 확정").
- **넘어가는 조건은 화면이 먼저 말한다.**
  - 조건이 안 찼으면 버튼을 잠그기보다 무엇이 비었는지 그 자리에 적는다.
  - 잠근다면 왜 잠겼는지 붙인다.
- **되돌아가기는 값을 지우지 않는다.**
  - 이전 단계로 가도 입력이 남는다.
- **막힘에는 출구가 있다.**
  - 실패·비어 있음·권한 없음 상태마다 문구를 미리 적는다. 문구에는 "무엇이·왜·다음에 할 일"이 있다.
  - 코드값·스택·내부 용어는 사용자 문구가 아니다.
- **숙련자 경로를 따로 둔다.**
  - 숙련자 경로는 단축키·최근 항목·기본값이다.
  - 초심자 흐름을 늘려서 숙련자를 느리게 만들지 않는다.
- **레포 문서가 "숨기지 말 것"을 정한 정보는 점진적 공개의 예외다.**
  - 예: 일정표의 모든 일정은 항상 보인다.
  - 그 정보는 접지 않고 밀도로 푼다.

**완료 기준:** 단계표의 모든 칸이 찼고, 각 단계에 주 행동이 정확히 하나이며, 막힘 상태마다 문구 초안이 있다.

## Stage 2 — 구조: 계층·근접성·정렬

각 단계 화면에서:
- **먼저 보는 것 하나를 정한다.**
  - 크기·굵기·위치·여백으로 그것이 먼저 읽히게 한다.
  - 두 개가 같은 무게면 아직 안 정한 것이다.
- **같이 쓰는 것은 붙이고, 다른 일은 뗀다.**
  - 관련 컨트롤은 한 묶음으로 둔다.
  - 파괴적 행동(삭제·취소·초기화)은 주 행동 묶음 밖에 둔다.
- **하나의 그리드에 맞춘다.**
  - 레포 토큰의 간격 단위만 쓴다. 눈대중 픽셀은 쓰지 않는다.
- **스크롤 아래로 내려가는 정보는 내려가도 되는 정보인지 확인한다.**
  - 결정에 필요한 것은 첫 화면 안에 있어야 한다.

**완료 기준:** 화면마다 "먼저 보는 것" 하나가 지정됐고, 파괴적 행동이 주 행동과 떨어져 있고, 간격이 전부 토큰 단위다.

## Stage 3 — 표현: 일관성·대비

- **있는 것을 쓴다.**
  - 레포 문서의 공통 컴포넌트·토큰·용어 사전을 먼저 본다.
  - 같은 뜻의 버튼은 제품 전체에서 같은 모양·같은 자리·같은 말이다.
- **새 패턴은 등록하고 쓴다.**
  - 새 색·새 컴포넌트·새 용어가 필요하면 레포 문서에 먼저 적는다.
    - 이유: 등록 없는 새 패턴은 다음 사람이 세 번째 변형을 만든다.
  - 왜 기존 것으로 안 되는지도 함께 적는다.
  - 그다음 코드에 넣는다.
- **대비는 중요한 곳에만 쓴다.**
  - 강조가 여럿이면 강조가 없는 것이다.
  - 파괴적 행동은 색·위치·확인 절차 셋 중 둘 이상으로 구분한다.
- **문구는 하나의 어투로 쓴다.**
  - 레포 문서의 어투(예: 합니다체)와 용어 사전을 따른다.
  - 같은 개념에 두 단어를 쓰지 않는다.

**완료 기준:** 이번 변경으로 생긴 새 색·새 컴포넌트·새 용어가 0 이거나 전부 레포 문서에 등록됐다.

## Stage 4 — 접근성

CHECKLIST 의 접근성 절을 항목마다 **예 / 해당 없음(이유)** 로 채운다. 핵심:
- 마우스 없이 전부 할 수 있다. 포커스가 보이고, 순서가 읽는 순서다.
- 아이콘만 있는 컨트롤에 이름이 있다. 상태 변화(저장됨·실패·진행 중)는 색 말고 글이나 아이콘으로도 전달된다.
- 글자·배경 대비가 충분하다. 애니메이션은 줄이기 설정을 따른다.
- 한 글자 단축키는 입력 중에 발동하지 않는다.

**완료 기준:** 접근성 절 전 항목이 "예" 또는 "해당 없음(이유)"다. "나중에"는 없다.

## Stage 5 — 검증: 눈으로, 다른 사람의 눈으로

1. **눈검증** — 레포 문서의 검증 도구로 실제 화면을 연다.
   - 검증 도구는 개발 서버 `commands.fe.dev` · mock `commands.fe.devMock` · 브라우저다.
   - 브라우저를 건드리기 전에 대상 브라우저를 사용자에게 확인받는다.
2. **초심자로 한 번, 키보드만으로 한 번** 지나간다. 레포에 페르소나 에이전트가 있으면 그것을 돌린다.
3. **문구 재독** — 사용자에게 보이는 모든 새 문구를 한 번 더 읽는다(깨진 글자·오타·어투).
4. [CHECKLIST.md](CHECKLIST.md) 전 항목을 채워 보고에 붙인다.
5. 레포 문서를 갱신한다 — 새로 등록한 패턴, 바뀐 용어, 이번에 발견한 함정.

**완료 기준:** 체크리스트 전 항목이 채워졌고, 레포 문서에 이번 변경이 반영됐고, 눈검증 결과(스크린샷 또는 "무엇을 봤다")가 보고에 있다.

## 보고 형식

각 단계의 산출물을 짧게 남긴다. 긴 것은 단계표(Stage 1)와 체크리스트(Stage 5) 둘뿐이다.

```
Stage 0  누가·어디서·무엇을·종점 — 한 줄
Stage 1  단계표
Stage 2  화면별 "먼저 보는 것"
Stage 3  새 패턴 등록 0건 / N건(문서 위치)
Stage 4  접근성 — 예 N · 해당 없음 N(이유)
Stage 5  눈검증 결과 · 체크리스트 · 레포 문서 갱신 위치
```

건너뛴 단계는 "해당 없음 — 이유"로 남긴다. 빈 줄로 두지 않는다.
