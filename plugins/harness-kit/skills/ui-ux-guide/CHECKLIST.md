# UI/UX 완료 체크리스트

Stage 5 에서 채워 보고에 붙인다. 각 항목은 **예 / 아니오 / 해당 없음(이유)** 셋 중 하나다. "나중에"는 없다.
아니오가 하나라도 있으면 완료가 아니다 — 고치거나, 왜 이번 범위 밖인지 사용자에게 보고하고 결정을 받는다.

## 흐름 (Stage 1)
- [ ] 단계마다 주 행동이 정확히 하나다.
- [ ] 3단계 이상이면 진행 표시가 있다. 2단계 이하면 주 행동 버튼 이름이 결과를 말한다("다음" 이 아니라 "주문 확정").
- [ ] 다음으로 못 넘어가는 이유가 그 자리에 보인다(잠긴 버튼에는 이유가 붙어 있다).
- [ ] 이전 단계로 가도 입력값이 남는다.
- [ ] 실패·비어 있음·권한 없음 상태마다 "무엇이·왜·다음에 할 일" 문구가 있다.
- [ ] 사용자 문구에 코드값·내부 용어·스택이 없다.
- [ ] 흔한 과업에 지름길(단축키·최근 항목·기본값)이 있거나, 없어도 되는 이유가 있다.

## 구조 (Stage 2)
- [ ] 화면마다 "먼저 보는 것" 하나가 정해져 있고, 실제로 그것이 먼저 읽힌다.
- [ ] 결정에 필요한 정보가 첫 화면(스크롤 전)에 있다.
- [ ] 같은 대상을 다루는 컨트롤은 한 묶음이고, 파괴적 행동은 주 행동 묶음 밖에 있다.
- [ ] 오류 문구가 해당 입력 바로 옆에 있다.
- [ ] 간격·크기가 전부 레포 토큰 단위다(눈대중 px 없음).
- [ ] 격자를 가진 화면이면 시각 눈금과 데이터 격자가 일치한다.

## 표현 (Stage 3)
- [ ] 공통 컴포넌트가 있는 것은 그것을 썼다.
- [ ] 새 색·새 컴포넌트·새 용어가 0 이거나, 전부 레포 문서에 등록됐다(왜 기존 것으로 안 되는지 포함).
- [ ] 채운 색 버튼이 화면에 하나다(아니면 이유가 있다).
- [ ] 파괴적 행동이 색·위치·확인 절차 중 둘 이상으로 구분된다.
- [ ] 같은 결과를 내는 모든 경로(버튼·닫기·단축키)가 같은 확인 절차를 거친다.
- [ ] 문구 어투가 레포 문서의 어투와 같고, 같은 개념에 한 단어만 쓴다.

## 접근성 (Stage 4)
- [ ] 마우스 없이 과업을 끝까지 할 수 있다.
- [ ] 포커스가 보이고, 탭 순서가 읽는 순서다. 팝업을 닫으면 포커스가 열었던 곳으로 돌아온다.
- [ ] 아이콘만 있는 컨트롤에 접근 가능한 이름이 있다. 이미지에 대체 텍스트가 있다.
- [ ] 상태·선택이 색 말고 다른 것(글·아이콘·테두리)으로도 구분된다.
- [ ] 상태 변화(저장·실패·진행)가 보조기기에도 알려진다(live region).
- [ ] 글자·배경 대비가 충분하다.
- [ ] 쓸 수 없는 행동이 `disabled` 로 사라지지 않고 왜 안 되는지 말한다(`aria-disabled` + 이유). 예외면 이유.
- [ ] 애니메이션이 줄이기 설정을 따른다.
- [ ] 한 글자 단축키가 텍스트 입력 중에 발동하지 않는다.

## 검증 (Stage 5)
- [ ] 실제 화면을 눈으로 봤다(스크린샷 또는 "무엇을 봤다" 기록).
- [ ] 초심자로 한 번, 키보드만으로 한 번 지나갔다(페르소나 에이전트가 있으면 돌렸다).
- [ ] 새 문구를 전부 재독했다(깨진 글자·오타·어투).
- [ ] 레포 UI/UX 문서에 이번 변경(새 패턴·용어·함정)을 반영했다.
- [ ] 레포가 요구하는 자동 검증(lint·단위·e2e)을 돌렸고 결과를 있는 그대로 적었다.
