# 레포 계층 UI/UX 문서 — 템플릿

레포에 UI/UX 문서가 없으면 이 틀로 문서를 만든다.

- 자리는 `docs/rules/` 아래 `ui-ux.md` 이거나, 그 레포의 문서 규약에 맞는 곳이다.
- **공용 원칙은 여기 베끼지 않는다.**
  - 공용 스킬을 링크한다.
  - 여기에는 **이 제품이라서 다른 것**만 적는다.
- 빈칸은 코드(토큰 파일·공통 컴포넌트·라우트)에서 채운다.
- 코드로 알 수 없는 것(주 사용자·기기·어투)만 사용자에게 묻는다.
- 만든 뒤 두 곳에 적는다.
  - 레포 `CLAUDE.md` 의 작업 라우팅 표에 한 줄을 건다.
  - `harness.config.mjs` 의 `project.docs.uiUxRules` 에 경로를 적는다.

---

```markdown
# UI/UX 규범 — <제품명>

> 기준: `<브랜치>` @ `<커밋>` (<날짜>)
> **답하는 질문: "이 제품의 화면을 만들 때, 공용 원칙 위에 무엇이 더 붙나."**
> 공용 원칙·단계 절차·체크리스트는 harness-kit 플러그인의 `ui-ux-guide` 스킬이 SSOT 다. 여기에는 **이 제품이라서 다른 것**만 적는다.
> 충돌하면 이 문서가 공용보다 우선하고, 하위 디렉토리 `CLAUDE.md` 가 이 문서보다 우선한다.

## 1. 사용자·기기·과업 (Stage 0 에서 읽는다)

| 사용자 | 기기·환경 | 주 과업 | 과업이 끝났다고 아는 순간 |
| - | - | - | - |
| | | | |

## 2. 이 제품의 우선순위 — 공용 원칙과 다르게 적용하는 것

<예: "밀도가 여백보다 우선한다", "모든 일정은 항상 보인다(점진적 공개 예외)", "프레임 정확도가 부드러움보다 우선">

## 3. 디자인 토큰 · 공통 컴포넌트 · 용어 (Stage 2·3 에서 읽는다)

값을 적지 않는다 — 위치만.

| 무엇 | 위치 | 규칙 |
| - | - | - |
| 색·간격·글꼴 토큰 | `<경로>` | 의미 이름만 쓴다. 값 직접 사용 금지 |
| 공통 컴포넌트 | `<경로>` | 있는 것을 먼저. 새 것은 여기 등록 후 |
| 용어 사전 | (아래 표) | 한 뜻 한 단어 |
| 문구 어투 | <합니다체 / 해요체> | 실패 문구는 "무엇이·왜·다음에 할 일" |

## 4. 금지 패턴 — 이 레포에서 시도됐다가 되돌려진 것

<예: "핵심 화면 렌더링을 외부 라이브러리에 위임", "CSS 로 배치 땜질", "자동 정렬(사용자가 안 건드린 것을 움직임)">

- 현행: <예: aria 라벨이 일부 화면에만 있음>

| - | - |
```
