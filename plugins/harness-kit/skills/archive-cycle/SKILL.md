# archive-cycle — 낡은 기록을 접고 살아있는 지식만 남긴다

정리는 **삭제가 아니라 이관**이다. 접기 전에 살아있는 지식을 현행 SSOT 로 옮기지 않으면, 현행 지식이 "현행 아님" 영역으로 함께 사라진다.

판정 기준은 하나다 — **"이 문서가 아직 일을 시키는가."** 크기가 아니라 이것으로 가른다.

## 프로필 — 프로젝트 고유값을 읽는 곳

이 스킬은 프로젝트 고유값을 본문에 갖지 않는다. 레포 루트 `harness.config.mjs` 의 `project` 블록에서 읽는다(슬롯 정의는 harness-kit README 「프로젝트 프로필」).

- 읽는 순서: 현재 레포 config → `project.pairOwner` 가 가리키는 주 레포 config. 짝 레포면 양쪽 config 를 다 읽는다.
- 이 스킬이 읽는 슬롯: `memory.slugs` · `docs.archiveDir` · `docs.pathValidator` · `docs.autoloaded` · `git.commitExecution`
- **값이 없으면 지어내지 않는다.** 파일이 없거나 슬롯 키가 없으면 그 자리에서 멈추고 사용자에게 묻는다. `null` 은 "해당 없음으로 판단됨"이므로 그 단계를 건너뛰고 보고에 적는다(예: `docs.pathValidator: null` → ⑤-2 는 grep 만).

## ① 계측 — 무엇이 큰가, 그리고 무엇이 매 세션 실리는가

두 축은 다르다. 큰 파일은 열릴 때만 비용이지만 **자동 로드 파일은 매 턴 실린다** — 진짜 비용은 후자다. 크기 순으로만 훑으면 정작 매 세션 실리는 인덱스를 놓친다.

- **상시 적재 축**: `MEMORY.md` · 자동 로드 `CLAUDE.md` 전부(루트 + 하위 디렉토리, `docs.autoloaded`) · 상시 문서
- **크기 축**: 메모리 디렉토리 파일별 KB · `docs/` 하위

```powershell
# 메모리 규모 + 상위 파일 (<슬러그> = memory.slugs 의 값)
$m="$env:USERPROFILE\.claude\projects\<슬러그>\memory"; $f=Get-ChildItem $m -File
"$($f.Count) files, $([math]::Round(($f|Measure-Object Length -Sum).Sum/1KB))KB"
$f | Sort-Object Length -Descending | Select-Object -First 10 |
  ForEach-Object { "  $([math]::Round($_.Length/1KB,1))KB  $($_.Name)" }
```

메모리 루트 슬러그는 프로젝트마다 다르다(`~/.claude/projects/` 아래). 레포와 메모리는 **1:1 이 아니다** — BE·FE 처럼 짝을 이루는 레포는 메모리도 양쪽을 함께 본다. 같은 레포라도 경로 표기(드라이브 문자 대소문자 등)가 달라 슬러그가 둘로 갈려 있을 수 있다.

**완료기준**: 상시 적재 파일 목록 + 상위 파일 크기표를 사용자에게 제시하고, 이번 사이클의 범위(메모리 / 레포 문서 / 둘 다, 어느 레포)를 합의한다.

## ② 판정 — "아직 일을 시키는가"

**상태 표기를 믿지 않는다.** `✅완료`·`종료`라 적힌 문서가 실제로는 회신 대기·배포 컷오버를 품고 있는 일이 반복해서 있었다. description 이 아니라 **본문을 열어** 남은 후속·대기·미배포 항목을 찾는다.

대상 전건을 셋 중 하나로 배정한다.

| 판정 | 뜻 | 처리 |
| - | - | - |
| **살아있음** | 아직 일을 시킨다 (후속 있음·진행 중 런북·미배포 절차) | 손대지 않는다 |
| **접기** | 일을 다 시켰고 본문에 현행 지식이 없다 | ④ 로 |
| **이관 후 접기** | 일은 끝났지만 본문이 현행 동작을 규정하는 문장을 갖고 있다 | ③ → ④ |

완료 표기가 없거나 애매하면 **살아있음으로 본다.** 되살리는 비용이 접는 이득보다 크다.

**완료기준**: 대상 전건이 셋 중 하나에 배정되고, 각 배정에 근거 한 줄이 붙는다.

## ③ 이관 — 제거 전에, 살아있는 지식을 SSOT 로

"이관 후 접기" 로 판정된 문서에서 **현행 동작을 규정하는 문장**을 추려, 접기 **전에** 현행 SSOT(도메인 문서 · `CLAUDE.md` · 상시 문서)로 옮긴다.

옮길 때 지키는 것:

- **복제하지 말고 링크한다** — 같은 표·정의를 두 문서에 두지 않는다.
- **코드가 SSOT 인 값은 적지 않는다** — 상수값·테스트 수 대신 **위치**(파일 · 심볼명)를 적는다. 라인번호 금지.
- **현행과 이력을 분리한다** — 경위는 하단 `## 이력` 또는 archive 로, 본문엔 현행 + 재발방지 가드레일만.

**완료기준**: 이관한 문장이 목적지 문서에 존재함을 grep 으로 확인한다. 그리고 **이관은 이동보다 앞선 커밋이거나 같은 커밋**이어야 한다 — 순서가 뒤집히면 그 사이 커밋에서 지식이 비어 있다.

## ④ 접기 — 완료 로그는 연표 한 줄로

접는다는 건 지운다는 게 아니라 **연표 한 줄**로 줄인다는 뜻이다: `날짜 · 무엇을 · 결과 · 커밋`. 경위·시행착오·중간 판단은 버린다 — 필요하면 커밋을 읽는다.

**메모리**
- 완료 트랙 파일: description 을 한 줄로 줄이고, 본문은 연표 + 재발방지 ⭐항목만 남긴다.
- `MEMORY.md` 의 해당 포인터도 같이 줄인다. 인덱스 한 줄이 길어지면 그게 매 세션 비용이다.
- 핸드오프 파일은 **최근 3~4 세션만** 유지하고 그 아래는 잘라낸다 — 각 트랙의 상세는 토픽 메모리가 SSOT 다.
- 파일을 지울 땐 **다른 메모리의 `[[위키링크]]` 를 먼저 grep** 한다.

**레포 문서**
- `docs.archiveDir` 로 이동하고, 상단에 **배너**를 단다: 시점 · "현행 아님" · 접은 판정 근거(예: "실행 금지로 판정 — 근거 …").
- 이동 수단: 추적 파일은 `git mv`, **미추적 파일은 `git mv` 가 실패하니 `mv`** 로 옮긴다.

**완료기준**: 접은 각 항목이 연표 한 줄로 남아 있고 원본 경로에는 없다.

## ⑤ 검증

1. **링크** — 이동 **전**에 참조를 grep 해 두고, 이동 **후** 같은 grep 을 재실행한다. 잔여 참조가 0 이거나 전부 새 경로로 갱신돼야 한다.
2. **경로 검사기** — `docs.pathValidator` 가 있는 레포에서만 쓴다. 짝 레포라도 한쪽에만 검사기가 있을 수 있다 — **없는 쪽은 1번 grep 이 유일한 수단이다.**
3. **커밋 범위** — 커밋 경로는 ②~④ 에서 배정한 파일 전부다: 옮긴 문서의 **옛 경로와 새 경로**, 이관받은 SSOT 문서, 연표·참조를 고친 파일. `git add` + 경로 없는 `git commit` 은 쓰지 않는다 — 같은 트리에 다른 세션이 stage 해 둔 변경까지 딸려 들어간다. `git add -A`·`git add .` 도 금지다. `git.commitExecution` 이 `'message-only'` 면 메시지와 아래 명령을 건네고 끝내고, 키가 없으면 묻는다.

```bash
# <ROOT>=레포 루트 · <BRANCH>=현재 브랜치 · <MSG>=메시지 파일 · <NEW…>=새 경로 중 미추적 파일(mv 로 옮긴 것) · <PATHS…>=커밋 경로 전부(추적 중이던 옛 경로 포함 · mv 로 옮긴 미추적 파일의 옛 경로는 넣지 않는다)
R="<ROOT>"; B="<BRANCH>"
[ "$(git -C "$R" rev-parse --show-toplevel)" = "$R" ] \
  && [ "$(git -C "$R" rev-parse --abbrev-ref HEAD)" = "$B" ] \
  && [ ! -e "$(git -C "$R" rev-parse --path-format=absolute --git-path index.lock)" ] \
  && git -C "$R" add -N -- <NEW…> \
  && git -C "$R" commit -F "<MSG>" -- <PATHS…>
```

   경로 하나라도 git 이 모르면 커밋 전체가 실패한다. 커밋 직후 `git -C "$R" show --stat --name-status HEAD` 로 배정한 파일이 전부 들어갔는지(옛 경로는 `D`·`R`, 새 경로는 `A`·`R`) 확인한다. (경로 하나가 빠져 이관분 없이 이동만 커밋된 적이 있다.) 푸시는 하지 않는다 — 하려면 `git push origin <브랜치>` 로 브랜치를 적는다.

**완료기준**: 위 세 확인의 출력이 있고, 커밋에 담긴 파일 목록이 ②~④ 의 배정과 일치한다.

## 함정

| 함정 | 실제로 일어난 일 | 처방 |
| - | - | - |
| 상태 표기 신뢰 | "완료" 로 적힌 트랙에 회신 대기·컷오버가 살아 있었다 | ② 에서 본문을 연다 |
| 이관 없이 이동 | archive 로 옮기면서 현행 판정 규칙이 같이 사라질 뻔했다 | ③ 을 ④ 보다 먼저 |
| 커밋 경로 누락 | pathspec 하나가 없어 스테이징이 실패했는데 그대로 커밋 → 이관분이 빠진 채 이동만 커밋 | 경로 지정 커밋 뒤 `git show --stat --name-status HEAD` 를 배정과 대조 |
| `git mv` 실패 | 미추적 파일엔 동작하지 않는다 | `mv` 로 옮긴다 |
| 링크 파손 | 문서 이동 후 참조가 깨졌고, 검사기가 없는 레포에선 드러나지 않았다 | 이동 전 grep · 이동 후 재실행 |
| 진행 중 런북 접기 | 크기만 보고 대형 런북을 대상에 넣으면 배포 중인 절차가 사라진다 | 완료 전 런북은 손대지 않는다 |
| 크기만 계측 | 정작 매 턴 실리는 인덱스·자동 로드 문서를 놓친다 | ① 의 두 축 모두 |
