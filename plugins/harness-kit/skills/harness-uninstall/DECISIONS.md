# 결정 질문 — 권장과 함께 하나씩 묻는다

질문마다 1단계 표의 근거(상태·근거 열)를 먼저 보이고, 선택지와 각 선택이 바꾸는 것을 함께 제시한다. 답은 받을 때마다 `U answer` 로 체크포인트에 적는다. 사용자가 답하지 않은 칸은 내가 고르지 않는다.

순서: **목적 → 런타임 산출물 → 항목 → 설치 뒤 손댄 것** (2단계) → **kit 플러그인 끄기 · 설치기록 삭제** (5단계) → **제거 커밋** (7단계). 앞 답이 뒤 권장을 바꾼다(목적 → 플러그인 키, 런타임 산출물 → `.gitignore` 줄).

## 권장 — 표에서 계산하고, 고르는 것은 사용자다

- 1단계 표의 「권장」 열이 스크립트가 계산한 권장이다. 아래 규칙표와 같은 규칙이다. 「근거 부족」이면 「판단 근거 부족 — 직접 골라 주세요」로 묻는다.
- 권장 선택지를 첫 번째에 두고 끝에 「(권장)」을 붙이며, 바로 아래 근거 한 줄을 단다.
- **권장 자리에 두지 않는 선택지** — 증거(런타임 산출물)를 사본 없이 지우는 것, 설치 뒤 사람이 고친 치환 줄을 자동으로 되돌리는 것, 후보 밖 파일을 고치는 것. 셋 다 선택지로도 보이지 않는다.
- 영수증이 없으면 후보마다 질문 하나다. AskUserQuestion 한 번에 질문을 4개까지 보낼 수 있다.

## 목적 — 재설치인가 완전 제거인가 (`purpose`)

| 관찰 | 권장 |
| - | - |
| 사용자 요청에 「재설치」·「다시 설치」·「갱신」이 있다 | 재설치 (`reinstall`) |
| 사용자 요청이 「제거」·「걷어내」·「삭제」뿐이다 | 완전 제거 (`remove`) |
| 그 밖 | 판단 근거 부족 |

- **재설치 — 걷어 낸 뒤 새 세션에서 다시 설치** — kit 플러그인 키의 권장이 「켜 둠」이 된다. 새 세션에서 harness-install 이 뜬다.
- **완전 제거 — 하네스를 쓰지 않음** — kit 플러그인 키의 권장이 「끔 (키 삭제)」이 된다.

## 항목 — 무엇을 지우는가

| 후보 | 관찰 | 권장 |
| - | - | - |
| `.harness/` 골격 사본 (`files:skeleton`) | 영수증과 같음 · 또는 영수증 없음 | 지움 |
| `harness.config.mjs` | 늘 | 지움 — 하네스 없이는 읽는 쪽이 없다 |
| 보조 파일 (`file:<경로>`, aux) | 권장대로 걷어 낸 뒤에도 다른 파일이 그 이름을 가리킨다 | 남김 — 지우면 그 안내가 끊긴다(참조는 보고만) |
| 보조 파일 | 가리키는 곳이 없다 | 지움 |
| 표시 블록 · 「개발 하네스」 절 · 절을 가리키는 줄 · 한 줄 표시 (`text:…`) | 늘 | 지움 |
| `.gitignore` 하네스 줄 | 런타임 산출물을 남기기로 했다 | 남김 — 지우면 그 파일이 미추적으로 뜬다 |
| `.gitignore` 하네스 줄 | 그 밖 | 지움 |
| 영수증 치환 (`text:…#replaceN`) | 설치가 바꾼 원문이 영수증의 수만큼 그대로 있다 | 되돌림 |
| `.harness/` 훅 (`hook:…`) | 늘 | 지움 — `.harness/` 가 없어지면 실패하는 훅이다 |
| `enabledPlugins` false 키 (`key:…`) | 영수증에 있다 · 「개발 하네스」 절이 그 키를 적었다 · 설치 커밋에서 생겼다 | 지움 |
| `enabledPlugins` false 키 | HEAD 에 없고 미추적 config 와 함께 생겼을 뿐이다 | 판단 근거 부족 |

- 선택지 — 바뀌는 것
  - **지움 (백업 남음)** — 그 파일·블록·줄·훅·키가 작업본에서 빠진다. 백업 디렉토리에 원본이 남는다.
  - **남김** — 그대로 둔다. 영수증이 있으면 영수증도 남긴다(다음 걷어내기의 기준).
  - **되돌림** — (치환만) 설치 뒤 원문을 영수증의 설치 전 원문으로 바꾼다.
- false 키를 지우면 그 플러그인이 이 레포에서 설치 전처럼 다시 켜진다 — 같은 이름의 스킬이 두 벌 뜰 수 있다는 것을 바뀌는 것에 적는다.

## 설치 뒤 손댄 것 — 따로 묻는다

상태가 `modified`(영수증의 sha256 과 다름) · `extra`(영수증에 없는데 `.harness/` 안에 있음)인 후보는 같은 종류와 묶지 않고 하나씩 묻는다. 무엇이 다른지(줄 수 · 첫 차이) 근거 줄에 보인다 — 백업 전이면 `git diff` 가 아니라 영수증 기준이라는 것을 적는다.

| 후보 | 관찰 | 권장 |
| - | - | - |
| `.harness/` 안 파일 · `harness.config.mjs` · 표시 블록 · 훅 | 손댔다 | 지움 — 하네스 없이는 쓸 데가 없다. 고친 내용은 백업본에 남는다 |
| 보조 파일 | 손댔다 | 남김 — 레포 쪽 용도로 고쳤을 수 있다 |
| 영수증 치환 | 설치 뒤 원문이 영수증의 수와 다르다 | 남김 — 되돌림은 선택지에 없다. 그 줄을 참조 목록으로 보고한다 |

## 런타임 산출물 — 계측 증거 (`runtime`)

`.harness/*.jsonl`(계측 로그 · 승격 레코드)은 하네스가 쌓은 증거 데이터다.

| 관찰 | 권장 |
| - | - |
| 늘 | 레포 밖 보관 후 지움 |

- **레포 밖 보관 후 지움** — `git rev-parse --git-common-dir` 아래 `harness-evidence/<트리>-<시각>/` 에 복사한 뒤 지운다. worktree 를 지워도 남는 자리다. 다른 곳으로 옮기려면 보고 뒤 사용자가 옮긴다.
- **그대로 남김** — `.harness/` 에 그 파일만 남는다. `.gitignore` 하네스 줄도 남기길 권한다.

## kit 플러그인 끄기 — 맨 마지막 결정 (`plugin`, 5단계)

| 관찰 | 권장 |
| - | - |
| 목적이 재설치 | 켜 둠 — 새 세션의 harness-install 이 이 플러그인에 있다 |
| 목적이 완전 제거 | 끔 (키 삭제) |
| 목적 미정 | 판단 근거 부족 |

- **끔 (키 삭제)** — project settings 의 `enabledPlugins."harness-kit@harness-kit"` 와 `extraKnownMarketplaces.harness-kit` 를 지운다(설치 전에 없던 키다). 다음 세션부터 이 레포에서 harness-kit 의 스킬·에이전트가 뜨지 않는다. 사용자 범위에서 켜 둔 PC 는 남는다(1단계 근거에 그 사실이 나온다).
- **켜 둠** — 두 키를 그대로 둔다. 게이트만 걷어 낸 상태가 된다.

## 설치기록 삭제 — 이 PC 의 플러그인 설치 기록 (5단계, 끔을 고른 뒤에만)

| 관찰 | 권장 |
| - | - |
| 늘 | 기록 남김 — 키가 없으면 로드되지 않는다. CLI 는 settings.json 을 통째로 다시 쓴다 |

- **기록 남김** — 아무것도 실행하지 않는다.
- **기록 삭제 (CLI 실행)** — `claude plugin uninstall harness-kit@harness-kit --scope project` 를 사용자 확인 뒤 실행하고, 직후 settings.json 을 백업(5단계 반영판)과 대조해 달라졌으면 그 판으로 되덮는다(PITFALLS §5).

## 제거 커밋 (7단계)

1단계에서 읽어 둔 `project.git.commitExecution` 으로 권장을 정한다. 커밋 경로가 0개면 묻지 않는다.

| 관찰 | 권장 |
| - | - |
| `message-only` | 메시지만 받음 — 묻지 않고 메시지 파일을 건넨다 |
| `auto` | 커밋 실행 — 그래도 직전에 묻는다(가드가 지워져 확인 창이 뜨지 않는다) |
| `null` · 읽지 못함 | 판단 근거 부족 — 레포 `CLAUDE.md` 의 커밋 규칙을 근거 줄에 보인다 |

- **커밋 실행** — 커밋 경로만 경로 지정 커밋한다. push 는 하지 않는다.
- **메시지만 받음** — 메시지 파일 경로와 커밋 명령을 건넨다. 작업본은 바뀐 채로 남는다.

## 질문의 꼴

harness-install TEMPLATES.md §8 과 같은 꼴이다 — header 는 D 번호 없이 대상 + 동작 명사구(공백 포함 12자 이하), 질문 첫 문장은 대상과 할 일을 평이한 말로, 선택지 라벨은 그것만 읽어도 뜻이 통하게. 후보 id 는 header 가 아니라 근거 줄에 둔다.

```text
header: 보조파일 삭제
설치가 만든 보조 파일 backend/gradle/<이름>.gradle 을 지울까?
근거: file:backend/gradle/<이름>.gradle · config 명령이 가리킨다 · 다른 문서 10곳이 이 이름을 가리킨다(남을 참조 목록)

1. 남김 (권장)
   바뀌는 것: 파일이 그대로 남고, 그 이름을 가리키는 문서 줄도 그대로 동작한다. 보고의 「남긴 것」에 적힌다
2. 지움 (백업 남음)
   바뀌는 것: 파일이 빠진다. 그 이름을 가리키는 문서 10곳의 명령이 실패하게 된다(그 줄은 고치지 않는다)

header: 계측로그 보관
하네스 계측 로그 .harness/log.jsonl 을 어떻게 할까?
근거: runtime · 런타임 산출물 1개 — 하네스가 쌓은 증거 데이터

1. 레포 밖 보관 후 지움 (권장)
   바뀌는 것: <git-common-dir>/harness-evidence/ 에 복사한 뒤 지운다. .harness/ 가 통째로 빠진다
2. 그대로 남김
   바뀌는 것: .harness/ 에 로그만 남는다. .gitignore 하네스 줄도 남겨야 미추적으로 뜨지 않는다
```

| 질문 | header | 글자 수 |
| - | - | - |
| 목적 | `제거 목적` | 5 |
| 골격 사본 | `골격사본 삭제` | 7 |
| config | `하네스설정 삭제` | 8 |
| 보조 파일 | `보조파일 삭제` | 7 |
| 「개발 하네스」 절·표시 블록 | `안내절 삭제` | 6 |
| 절을 가리키는 줄·한 줄 표시 | `안내줄 삭제` | 6 |
| `.gitignore` 줄 | `무시목록 줄삭제` | 8 |
| 문서 치환 | `문서줄 되돌림` | 7 |
| 훅 | `하네스훅 삭제` | 7 |
| false 키 | `끈플러그인 복원` | 8 |
| 설치 뒤 손댄 것 | `손댄파일 처리` | 7 |
| 런타임 산출물 | `계측로그 보관` | 7 |
| kit 플러그인 | `kit 플러그인 끄기` | 11 |
| 설치 기록 | `설치기록 삭제` | 7 |

AskUserQuestion 을 쓰면 `header` 에 위 header 를, `question` 에 질문과 근거 한 줄을, 권장 선택지를 `options` 의 첫 번째에 두고 `label` 끝에 「(권장)」을, 각 `description` 에 바뀌는 것을 넣는다.
