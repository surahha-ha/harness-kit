# 결정 질문 — 권장과 함께 하나씩 묻는다

질문마다 1단계 표의 근거(상태·근거 열)를 먼저 보이고, 선택지와 각 선택이 바꾸는 것을 함께 제시한다. 답은 받을 때마다 `U answer` 로 체크포인트에 적는다. 사용자가 답하지 않은 칸은 내가 고르지 않는다.

순서:

1. **다른 세션 확인** (0단계, 혼자)
2. **graft 로컬 연결 → 전역 상태 줄 되돌리기** (0-2단계)
   - 있을 때만 묻는다. scan 전에 묻는다.
   - 범위 낮추기에서는 묻지 않는다.
3. **목적 → 런타임 산출물 → 항목 → 설치 뒤 손댄 것** (2단계)
   - 범위 낮추기면 「범위 낮추기」 절의 항목만 묻는다.
4. **kit 키 처리 → 설치기록 삭제** (5단계, 6단계 검증보다 먼저)
5. **제거 커밋** (7단계)

앞 답이 뒤 권장을 바꾼다(목적 → 플러그인 키, 런타임 산출물 → `.gitignore` 줄).

## 권장 — 표에서 계산하고, 고르는 것은 사용자다

- 1단계 표의 「권장」 열이 스크립트가 계산한 권장이다.
  - 아래 규칙표와 같은 규칙이다.
  - 「권장 없음」이면 아래 「권장이 없는 질문」 절을 따라 묻는다.
- 권장 선택지를 첫 번째에 두고 끝에 「(권장)」을 붙인다. 바로 아래 근거 한 줄을 단다.
- **권장 자리에 두지 않는 선택지** — 아래 셋은 선택지로도 보이지 않는다.
  - 증거(런타임 산출물)를 사본 없이 지우는 것
  - 설치 뒤 사람이 고친 치환 줄을 자동으로 되돌리는 것
  - 후보 밖 파일을 고치는 것
- 영수증이 없으면 후보마다 질문 하나다. AskUserQuestion 한 번에 질문을 4개까지 보낼 수 있다.

## 권장이 없는 질문 — 첫 자리가 권장으로 읽히지 않게

표의 권장이 「권장 없음」인 칸, 목적(관찰 「그 밖」), 다른 세션 확인이 여기에 든다. 걷어내기 시험에서 권장 없는 목적 질문의 첫 선택지(재설치)를, 「권장으로 골라 달라」던 사용자가 그대로 골랐다.

- 본문 첫 줄에 「권장 없음 — <무엇에 따라> 고릅니다」를 쓴다.
  - 예: 「권장 없음 — 하네스를 다시 쓸지에 따라 고릅니다」
  - 「판단 근거 부족」 같은 말을 근거 줄 뒤에 묻어 두지 않는다.
- 어느 라벨에도 「(권장)」을 붙이지 않는다.
- 선택지는 아래 각 절에 적힌 **고정 순서**로 둔다(관찰값에 따라 바꾸지 않는다).
- 사용자가 「권장대로」·「추천대로」라고 답해도 이 질문은 채우지 않는다.
  - 「이 질문은 권장이 없어 직접 골라 주셔야 한다」고 따로 다시 묻는다.
- `U answer --recommended` 도 목적은 채우지 않는다.
  - 그 밖의 권장 없는 칸은 `keep`(남김)으로 채운 뒤 목록을 출력한다.

## 다른 세션 확인 — 같은 트리에 살아 있을 수 있는 세션 (0단계)

| 관찰 | 권장 |
| - | - |
| 늘 | 권장 없음 — 그 세션이 끝났는지는 사용자가 안다 |

- **혼자 먼저 묻는다.** 목적 질문과 한 번에 보내지 않는다.
  - 「중단」을 고르면 함께 받은 목적 답은 쓸 데가 없다(시험에서 둘을 한 묶음으로 보냈다).
- 관찰값은 `U sessions <루트>` 의 「마지막 기록」 시각과 몇 분 전인지다.
  - 파일 수정 시각을 쓰지 않는다.
  - 세션이 끝날 때 timestamp 없는 줄이 붙는다. 그래서 1시간 전에 끝난 세션이 「약 1분 전」으로 보였다.

고정 순서:

1. **계속 진행**
   - 설명에 관찰값을 둔다.
     - 그 세션 id 앞자리
     - 마지막 기록 시각과 몇 분 전인지(「10:24, 1시간 8분 전」)
     - 그 세션이 이 트리의 걷어 낼 파일을 고쳤는지
   - 「그 세션은 종료됨」처럼 사용자가 판단할 사실을 라벨에 적지 않는다.
2. **중단** — 아무것도 고치지 않고 멈춘다. 체크포인트만 남아 다음에 이어 할 수 있다.

## 목적 — 재설치인가 완전 제거인가 (`purpose`)

| 관찰 | 권장 |
| - | - |
| 사용자 요청에 「재설치」·「다시 설치」·「갱신」이 있다 | 재설치 (`reinstall`) |
| 사용자 요청이 「제거」·「걷어내」·「삭제」뿐이다 | 완전 제거 (`remove`) |
| 그 밖 | 권장 없음 — 하네스를 다시 쓸지에 따라 고른다 |

권장이 있으면 권장을 첫 자리에 둔다. 권장이 없을 때의 고정 순서는 이 스킬의 본래 목적인 완전 제거가 먼저다.

1. **완전 제거 (하네스 안 씀)** — kit 플러그인 키의 권장이 「끔 (키 삭제)」이 된다.
2. **재설치 (새 세션에서 다시)** — kit 플러그인 키의 권장이 「켜 둠」이 된다. 새 세션에서 harness-install 이 뜬다.

## 항목 — 무엇을 지우는가

| 후보 | 관찰 | 권장 |
| - | - | - |
| `.harness/` 골격 사본 (`files:skeleton`) | 영수증과 같음 · 또는 영수증 없음 | 지움 |
| `harness.config.mjs` | 늘 | 지움 — 하네스 없이는 읽는 쪽이 없다 |
| 보조 파일 (`file:<경로>`, aux) | 권장대로 걷어 낸 뒤에도 다른 파일이 그 이름을 가리킨다 | 남김 — 지우면 그 안내가 끊긴다(참조는 보고만) |
| 보조 파일 | 가리키는 곳이 없다 | 지움 |
| 보조 파일 — 앞선 걷어내기 백업에서 되찾은 것 | 가리키는 곳이 있다 · 없다 | 위 두 줄과 같다(남김 · 지움). 근거 열에 그때 백업 시각이 나온다 |
| 보조 파일 — config 도 앞선 백업도 없이 이름에 harness 만 있는 것 | 가리키는 곳이 없다 | 권장 없음 — 설치가 만들었는지 근거가 약하다. 고정 순서는 남김 → 지움 |
| 표시 블록 · 「개발 하네스」 절 · 절을 가리키는 줄 · 한 줄 표시 (`text:…`) | 늘 | 지움 |
| `.gitignore` 하네스 줄 | 런타임 산출물을 남기기로 했다 | 남김 — 지우면 그 파일이 미추적으로 뜬다 |
| `.gitignore` 하네스 줄 | 그 밖 | 지움 |
| `.gitignore` 의 `/graft/` 표시 블록 | 0-2단계에서 graft 로컬 연결을 남겼다(`.claude/helpers/graft-hooks.cjs` 가 있다) | 남김 — 지우면 graft build 가 표시 없는 줄을 다시 덧붙인다 |
| `.gitignore` 의 `/graft/` 표시 블록 | graft 로컬 연결을 걷어 냈거나 없다 | 지움 |
| 영수증 치환 (`text:…#replaceN`) | 설치가 바꾼 원문이 영수증의 수만큼 그대로 있다 | 되돌림 |
| `.harness/` 훅 (`hook:…`) | 늘 | 지움 — `.harness/` 가 없어지면 실패하는 훅이다 |
| `enabledPlugins` false 키 (`key:…`) | 영수증에 있다 · 「개발 하네스」 절이 그 키를 적었다 · 설치 커밋에서 생겼다 | 지움 |
| `enabledPlugins` false 키 | HEAD 에 없고 미추적 config 와 함께 생겼을 뿐이다 | 권장 없음 — 고정 순서는 남김 → 지움 |

- 선택지 — 바뀌는 것
  - **지움 (백업 남음)** — 그 파일·블록·줄·훅·키가 작업본에서 빠진다. 백업 디렉토리에 원본이 남는다.
  - **남김** — 그대로 둔다. 영수증이 있으면 영수증도 남긴다(다음 걷어내기의 기준).
  - **되돌림** — (치환만) 설치 뒤 원문을 영수증의 설치 전 원문으로 바꾼다.
- false 키를 지우면 그 플러그인이 이 레포에서 설치 전처럼 다시 켜진다.
- false 키 「지움」의 설명은 아래 문장을 그대로 쓰고 `<…>` 만 채운다.
  - 시험에서 이 문장을 새로 지어 쓰다 오타가 났다.

  > 이 레포에서 `<플러그인>` 이 설치 전처럼 다시 켜집니다. `<겹치는 이름 2~3개>` 처럼 이름이 같은 스킬·에이전트가 두 벌 뜰 수 있습니다. 재설치하면 겹침 질문을 다시 받습니다.

## 설치 뒤 손댄 것 — 따로 묻는다

상태가 `modified`(영수증의 sha256 과 다름) · `extra`(영수증에 없는데 `.harness/` 안에 있음)인 후보는 같은 종류와 묶지 않는다. 하나씩 묻는다.

- 무엇이 다른지(줄 수 · 첫 차이) 근거 줄에 보인다.
- 백업 전이면 `git diff` 가 아니라 영수증 기준이라는 것을 적는다.

| 후보 | 관찰 | 권장 |
| - | - | - |
| `.harness/` 안 파일 · `harness.config.mjs` · 표시 블록 · 훅 | 손댔다 | 지움 — 하네스 없이는 쓸 데가 없다. 고친 내용은 백업본에 남는다 |
| 보조 파일 | 손댔다 | 남김 — 레포 쪽 용도로 고쳤을 수 있다 |
| 영수증 치환 | 설치 뒤 원문이 영수증의 수와 다르다 | 남김 — 되돌림은 선택지에 없다. 그 줄을 참조 목록으로 보고한다 |

## graft 로컬 연결 (0-2단계, harness-install D9 를 켰을 때)

- header: `graft 연결 처리`
- 질문 첫 문장: 「이 PC 에서만 켜 둔 코드 지도(graft)를 이 폴더에서 걷어 낼까요? 커밋된 파일은 바뀌지 않습니다.」
- 근거 줄: `graft-localize.mjs status` 의 세 줄
  - settings.json 의 graft 몫
  - settings.local.json 의 graft 몫·helpers·graft/
  - exclude 블록

| 관찰 | 권장 |
| - | - |
| 사용자 요청이 graft 까지 걷어 내라고 했다 | 걷어 냄 |
| 그 밖(0-2단계는 목적 질문보다 앞이라 목적으로 가를 수 없다) | 권장 없음 — graft 를 이 폴더에서 계속 쓸지에 따라 고른다(고정 순서는 걷어 냄 → 걷어 내되 그래프는 남김 → 남김) |

- **걷어 냄** — `graft-localize.mjs remove` 를 돌린다.
  - 떼는 것: settings.local.json 의 graft 몫(훅 · 상태 줄 · 권한 · `disabledMcpjsonServers` 의 graft)
  - 지우는 것: helpers·skill, init 이 새로 만든 `.mcp.json`·`.ignore`, `graft/`, info/exclude 블록
  - 건드리지 않는 것(`KEEP` 줄): `prepare` 전부터 있던 미추적 helpers·skill·`graft/` 와 추적 파일(`.mcp.json` 등)
  - settings.json 에 graft 몫이 다시 들어와 있으면 아무것도 지우지 않고 FAIL 로 멈춘다.
    - 원인: 업그레이드 뒤 `localize` 를 안 돌렸다.
    - `localize` 를 먼저 다시 돌린다.
  - info/exclude 는 worktree 끼리 공유다.
    - 다른 worktree 에서 graft 를 쓰면 그쪽 helpers 등이 미추적으로 보일 수 있다(출력의 경고 한 줄).
    - `/graft/` 는 `.gitignore` 에 있어 영향이 없다.
    - 그 helpers 에는 개인 절대경로가 들어 있다. 그 worktree 에서 `git add -A` 로 커밋하지 않게 알린다.
  - 다 걷으면 스냅숏·체크포인트를 지운다. 백업 `git-path harness-kit-graft/backup-<시각>/` 은 남긴다.
  - FAIL 이 있으면 다 남긴다.
  - 이어지는 항목 질문에서 `.gitignore` 의 `/graft/` 블록은 「지움」이 권장된다.
- **걷어 내되 그래프는 남김** — 같은데 `--keep-graph` 로 `graft/` 를 남긴다(큰 레포에서 다시 짓는 시간이 아까울 때).
- **남김** — 아무것도 바꾸지 않는다. `.gitignore` 의 `/graft/` 블록도 「남김」이 권장된다.

## 전역 상태 줄 되돌리기 (0-2단계, 전역 영수증이 있을 때)

- header: `전역 상태줄 처리`
- 질문 첫 문장: 「이 PC 의 모든 레포에 적용되는 상태 줄을 harness-kit 이 바꾸기 전으로 되돌릴까요?」
- 근거 줄: `statusline-setup.mjs status` 두 줄과 원래 명령(전역 영수증의 `original`)

| 관찰 | 권장 |
| - | - |
| 이 PC 의 다른 레포에 graft 상태 줄 헬퍼가 있을 수 있다(늘 — 스크립트는 다른 레포를 보지 않는다) | 남김 — 헬퍼가 없는 레포에서는 원래 줄만 나와 해가 없다 |

- **남김 (권장)** — 전역 설정을 바꾸지 않는다. 나중에 `statusline-setup.mjs restore` 로 되돌릴 수 있다고 보고에 적는다.
- **되돌림** — 지금 전역 `statusLine.command` 를 harness-kit 이 쓴 값과 대어 본다.
  - 같으면: 원래 값으로 되돌리고, 영수증을 `~/.claude/harness-kit/backup/` 으로 옮긴다.
  - 다르면: 손대지 않는다(종료코드 3).
  - 합치기 스크립트 사본·`statusline.json` 은 남긴다.
    - graft 를 쓰는 레포의 `settings.local.json` 상태 줄이 그 사본을 계속 쓴다.
    - 지우려면 각 레포에서 graft 연결을 걷어 낸 뒤 손으로 지운다.

## 범위 낮추기 — 계측 → 라이트 (`scan --tier light`, 목적 `lower`)

목적 질문이 없다 — 사용자가 「라이트로 낮춰」류로 요청했을 때만 `scan --tier light` 로 뽑는다. 요청이 「제거」인지 「낮추기」인지 드러나지 않으면 먼저 그것을 묻는다(권장 없음 — 고정 순서는 완전 제거 → 재설치 → 범위 낮추기). 후보마다 묻고, `clean` 인 범위 밖 훅은 한 질문에 묶을 수 있다.

| 후보 | 관찰 | 권장 |
| - | - | - |
| 범위 밖 하네스 훅 (`hook:…`) | 영수증과 같음 | 지움 — 관찰만 하던 훅이다. 골격 사본은 남는다 |
| 범위 밖 config 칸 (`slot:<경로>`) | 설치 때 값 그대로(영수증 `afterSha` 와 같음) | 되돌림 — 남기면 그 칸을 읽는 훅 없이 설정만 남는다 |
| 범위 밖 config 칸 | 설치 뒤 값이 바뀌었다 | 권장 없음 — 되돌리면 그 값을 잃는다(백업에는 남는다). 고정 순서는 되돌림 → 남김 |
| 범위 밖 config 칸 | 칸 안에 docs-setup 표시가 있다 | 남김만 — docs-setup 이 채운 값이다(선택지도 남김 하나) |
| 「개발 하네스」 절 (`text:…#blockN`) | 새 판을 `block` 으로 받기 전 | 권장 없음 — 새 판을 먼저 쓴다. 「바꿈」은 새 판 없이 고를 수 없다 |
| 「개발 하네스」 절 | 새 판을 받았다 | 바꿈 |
| 영수증 (`receipt:tier`) | 늘 | 갱신(선택지 하나) — 다음 걷어내기의 기준 |

- 선택지 — 바뀌는 것
  - **되돌림** — 그 칸이 example 의 값·꼬리 주석으로 돌아간다. example 에 없던 칸은 칸째 빠진다.
  - **바꿈** — 표시 블록이 새 판으로 통째로 바뀐다. 블록 밖 줄은 그대로다.
  - **남김** — 그대로 둔다. 영수증 갱신은 남긴 칸·훅을 그대로 적어 둔다.
  - **갱신** — 영수증의 `tier`·훅·칸·해시를 바꾸고 `tierChanges` 에 한 줄을 더한다.

## kit 키 처리 — 맨 마지막 결정 (`plugin`, 5단계)

header 는 `kit 키 처리` 다. 「끄기」처럼 한쪽 동작을 header 에 쓰면, 권장이 「켜 둠」일 때 header 와 권장이 서로 반대로 읽힌다(시험에서 그랬다).

| 관찰 | 권장 |
| - | - |
| 목적이 재설치 | 켜 둠 — 새 세션의 harness-install 이 이 플러그인에 있다 |
| 목적이 완전 제거 | 끔 (키 삭제) |
| 목적 미정 | 권장 없음 — 목적을 먼저 묻는다(고정 순서는 끔 → 켜 둠) |

- **끔 (키 삭제)**
  - project settings 의 두 키를 지운다: `enabledPlugins."harness-kit@harness-kit"` · `extraKnownMarketplaces.harness-kit`
    - 설치 전에 없던 키다.
  - 설명은 아래 문장을 쓴다.

    > 이 레포 설정에서만 빠집니다 — 다음 세션부터 이 레포에서 harness-kit 스킬·에이전트(harness-install 포함)가 뜨지 않습니다. 사용자 범위로 켜 둔 PC 에서는 계속 뜹니다.

  - 예전 문구 「사용자 범위에서 켜 둔 PC 는 그대로 남습니다」는 무엇이 남는지 읽히지 않았다.
- **켜 둠** — 두 키를 그대로 둔다. 게이트만 걷어 낸 상태가 된다.

## 설치기록 삭제 — 이 트리의 플러그인 설치 기록 (5단계, 끔을 고른 뒤 · 검증보다 먼저)

`U records <루트>` 가 `~/.claude/plugins/installed_plugins.json` 의 harness-kit 기록 중 **`projectPath` 가 이 레포 루트와 같은 것만** 고른다(Windows 는 대소문자 무시 · 슬래시 통일). 다른 트리의 기록은 근거에도 쓰지 않는다.

- 사고: 시험에서 메인 트리(project)와 다른 worktree(local)의 기록을 이 트리의 근거로 썼다.
- 근거 문구는 「project·local 둘 다 disabled」였다. 그런데 이 트리에는 기록이 없었다.

| 관찰 (`records` 출력) | 처리 |
| - | - |
| 「이 트리의 설치 기록 없음」 | 묻지 않는다. 보고에 「이 트리의 설치 기록 없음 — CLI 실행 안 함」 |
| worktree 이고 메인 트리에도 기록이 있다(`WARN`) | 묻지 않고 CLI 를 선택지로 보이지 않는다. 보고에 이유 줄을 옮기고, 사용자가 원할 때만 `INFO 손 절차` 를 건넨다 |
| 설치 기록 파일을 읽지 못했다 | 묻지 않는다. 보고에 이유 줄 |
| `CLI 후보` 줄이 있다(기록이 이 트리에만 있다) | 묻는다 — 권장은 기록 남김(키가 없으면 로드되지 않는다. CLI 는 settings 를 통째로 다시 쓴다) |

- `--scope project|local` 은 **cwd 의 프로젝트**에 작용한다.
  - CLI 가 worktree 를 메인 트리로 푸는지는 확인되지 않았다.
  - worktree 에서 돌린 CLI 가 메인 트리 기록을 지우면 안 된다.
  - 그래서 위 표의 둘째 줄에서는 CLI 를 권하지 않는다.

**선택지**

- **기록 남김** — 아무것도 실행하지 않는다.
- **기록 삭제 (CLI 실행)**
  1. 사용자 확인 뒤 `CLI 후보` 줄의 명령을 **이 트리 루트에서** 실행한다.
  2. 바로 `U after-cli <루트>` 를 돌린다.
     - after-cli 는 settings 를 5-1 의 `after-plugin/` 스냅숏(kit 키를 지운 직후 판)과 바이트 대조한다.
     - 달라졌으면 CLI 판을 `after-cli/` 에 남긴다. 그 뒤 스냅숏 바이트로 되덮는다.
     - 되덮으면 키 순서 · 지워진 키 · 줄끝이 돌아온다.
     - 3단계 백업으로 되덮지 않는다. 키를 지우기 전 판이라 kit 키가 되살아난다(PITFALLS §5).

## 제거 커밋 (7단계)

1단계에서 읽어 둔 `project.git.commitExecution` 으로 권장을 정한다.

verify 의 커밋 경로가 0개면 묻지 않는다. 메시지 파일도 만들지 않는다. verify 가 낸 이유 줄을 보고에 옮긴다.

| 관찰 | 권장 |
| - | - |
| `message-only` | 메시지만 받음 — 묻지 않고 메시지 파일을 건넨다 |
| `auto` | 커밋 실행 — 그래도 직전에 묻는다(가드가 지워져 확인 창이 뜨지 않는다) |

## 질문의 꼴

harness-install TEMPLATES.md §8 과 같은 꼴이다.

- header 는 D 번호 없이 대상 + 동작 명사구로 쓴다(공백 포함 12자 이하).
- 질문 첫 문장은 대상과 할 일을 평이한 말로 쓴다.
- 선택지 라벨은 그것만 읽어도 뜻이 통하게 쓴다.
- 후보 id·경로·내부 용어는 header 와 첫 문장이 아니라 그 뒤 「근거:」 줄에 둔다.

**항목별 규칙**

- **header** — 1단계 표의 「질문 header」 열을 그대로 쓴다.
  - 스크립트가 한 계획 안에서 겹치지 않게 정한다.
    - 훅은 이벤트 이름을 넣는다(`Stop훅 삭제` · `PreTool훅 삭제`).
    - 같은 종류가 여럿이면 끝에 번호를 붙인다(`문서줄 되돌림 3`).
  - 한 번에 보내는 질문들의 header 가 같으면 사용자가 어느 답이 어느 항목인지 가릴 수 없다.
    - 시험에서 `하네스훅 삭제` 가 한 묶음에 세 번 나왔다.
  - 같은 종류를 한 질문에 묶을 때만 번호 없는 꼴을 쓴다.
- **첫 문장** — 무엇을 어떻게 할지를 일상어로 쓴다.
  - 아래 낱말 표의 왼쪽 말을 본문 앞쪽에 쓰지 않는다.
- **라벨** — 선택지가 하는 일만 쓴다. 사용자가 판단할 사실(「그 세션은 종료됨」)이나 근거는 설명(`description`)으로 보낸다.
