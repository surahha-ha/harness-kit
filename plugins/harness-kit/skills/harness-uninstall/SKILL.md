# harness-uninstall — 넣은 것만, 블록과 키 단위로

이 스킬이 걷어 내는 것은 harness-install 이 넣은 것뿐이다.

1. **게이트** — `.harness/`(골격 사본 · 런타임 산출물) · `harness.config.mjs` · config 가 가리키는 레포 고유 보조 파일 · `.claude/settings.json` 의 `.harness/` 훅
2. **설치가 고친 곳**
   - `CLAUDE.md` 의 「개발 하네스」 절과 그 절을 가리키는 줄
   - `.gitignore` 의 하네스 줄
   - 8단계에서 고친 문서 줄
   - 겹침 결정으로 넣은 `enabledPlugins` false 키
3. **harness-kit 플러그인 키** — `enabledPlugins` 의 `harness-kit@harness-kit` · `extraKnownMarketplaces.harness-kit`(맨 마지막 결정)
4. **로컬 전용 선택 항목**(harness-install D9·D10 을 켰을 때)
   - graft 로컬 연결: `settings.local.json` 의 graft 몫 · `.claude/helpers/graft-*.cjs` · `.claude/skills/graft/` · `graft/` · 새로 생긴 `.mcp.json`·`.ignore` · info/exclude 블록
   - 사용자 전역 상태 줄 합치기
   - 이 항목은 커밋되지 않으므로 영수증 해시 대신 각 스크립트의 체크포인트가 기준이다.
   - 0-2단계에서 따로 묻는다.
   - 전역 상태 줄은 이 레포를 걷어 내도 저절로 되돌리지 않는다.

**docs-setup 이 만든 것은 걷어 내지 않는다.**

- 다음은 설치 표시가 없어 후보가 되지 않는다(시험: docs-setup `scripts/boundary.test.mjs`).
  - 옮긴 문서와 배너
  - `docs/README.md` 성격표
  - `CLAUDE.md` 의 작업 라우팅·문서 규약·메모리 규약 절
- config 안의 docs-setup 칸(줄 끝 `// harness-kit:docs-setup`)은 config 와 함께 지워진다.
- 그 칸은 후보가 아니라 **따로 보고**한다.
- 보고 자리: scan 표 위 「docs-setup 칸 N개」 줄 · verify 요약.
- 칸 값은 백업 `files/harness.config.mjs` 와 `index.json` 의 `docsSetup` 에 남는다.
- 새 설치 뒤에는 docs-setup 을 다시 돌리거나, harness-install D8-2 가 최신 백업에서 값을 되살린다.

기준은 둘 중 하나다.

| 레포 루트 | 기준 |
| - | - |
| **영수증**(`harness.install.json`, harness-install 9단계가 쓴다)이 있다 | 영수증 |
| 영수증이 없다 | **알려진 구조**로 후보를 뽑고 항목마다 확인받는다 |

**설치 범위**(라이트 · 계측, harness-install D0)는 영수증의 `tier` 에서 읽는다.

- `tier` 가 없는 schema 1 영수증은 계측으로 읽는다(`WARN` 한 줄). 그때까지의 설치는 모두 전체 설치였다.
- 범위는 「있어야 할 것 · 남은 것」을 가르는 데 쓰인다.
  - 라이트 설치에 관찰 훅이 없는 것은 경고가 아니다.
  - 라이트 영수증인데 관찰 훅이 settings 에 있으면, 그 후보 근거에 「범위 밖 — 남은 것」이 붙는다.
- 목적이 **범위 낮추기**(계측 → 라이트)면 걷어내기 대신 아래 「범위 낮추기」 절의 짧은 길을 간다.

걷어내기를 끝까지 지배하는 말 여섯 개:

- **넣은 것만**
  - 후보로 뽑힌 것만 잘라 낸다.
  - 자르는 단위는 시작·끝 표시로 감싼 블록 · 한 줄 표시 · 영수증의 치환 · JSON 키다.
  - `git restore`·`git checkout -- <파일>`·커밋 되돌리기로 걷어 내지 않는다.
  - 이유: 같은 파일의 하네스와 무관한 변경까지 되돌린 사고가 있었다([PITFALLS.md](PITFALLS.md) §4).
  - 예외는 HEAD 와 내용이 같고 줄끝만 다른 파일 하나뿐이다(6단계 · PITFALLS §6).
  - 사후리뷰 기록(git notes ref · fetch refspec)은 넣은 것이 아니라 사용자 데이터다. 후보가 아니다. 보고에 지우는 명령만 적는다(8단계).
- **묻는다**
  - 결정마다 권장과 근거를 보이고 묻는다([DECISIONS.md](DECISIONS.md)).
  - 고르는 것은 사용자다.
  - 영수증 없이 뽑은 후보는 묶지 않고 하나씩 묻는다.
- **백업 먼저**
  - 손댈 파일을 모두 `git rev-parse --git-path harness-uninstall-backup/` 아래에 복사한 뒤에만 고친다.
  - 런타임 산출물(`.harness/log.jsonl` 등)은 증거 데이터다. `git rev-parse --git-common-dir` 아래 `harness-evidence/` 에 따로 남긴다.
- **참조는 보고만**
  - 후보 밖 파일이 하네스(`.harness`·`harness.config`·보조 파일 이름)를 가리킬 수 있다.
  - 그 줄은 지우거나 고치지 않고 목록으로 보고한다.
- **git 은 마지막**
  - 7단계 전에는 작업본만 바꾼다.
  - 커밋은 경로 지정으로만 하고, 직전에 따로 묻는다.
- **체크포인트**
  - 스크립트가 `git rev-parse --git-path harness-uninstall-state.json` 에 계획·답·백업 위치·적용한 항목을 적는다.
  - 끊겨도 다음 세션의 0단계가 이어받는다.
  - 걷어내기는 같은 항목을 두 번 지우지 않는다(블록은 해시로 찾는다).

보조 스크립트는 이 스킬 디렉토리의 `scripts/uninstall.mjs` 하나다. 아래에서 `U` 는 `node "${CLAUDE_SKILL_DIR}/scripts/uninstall.mjs"` 를 줄인 것이다. 인자에는 레포 경로·후보 id·답만 넘긴다. 명령 문자열을 셸 인자로 넘기면, 아직 살아 있는 실행 전 가드가 그 문자열을 보고 막는다.

스크립트 순서는 하나다: `sessions` → (로컬 선택 항목이 있으면 0-2단계의 `graft-localize.mjs remove` · `statusline-setup.mjs restore`) → `scan` → `answer` → `backup` → `apply` → `plugin` → `records` → (CLI 를 돌렸으면) `after-cli` → `verify` → 보고 → `finish`.

- 명령마다 출력 끝 「다음:」 줄이 다음 명령을 말한다.
- 한 Bash 호출에 두 단계를 묶지 않는다.
- 시험에서 `plugin` 과 `verify` 를 한 번에 돌려, 설치기록 질문이 검증 뒤로 밀렸다.

각 단계를 시작할 때 [PITFALLS.md](PITFALLS.md) 의 같은 번호 절을 먼저 읽는다.

## 0. 사전 확인 — 지금 걷어 내도 되는가

확인할 것:

- `git status --short` · 현재 브랜치 · `git stash list` · `git worktree list`
- **같은 트리의 살아 있는 다른 Claude 세션** — `U sessions <루트>` 로 본다.
  - 스크립트가 `~/.claude/projects/<트리 경로 슬러그>/*.jsonl` 마다 마지막 기록의 시각과 몇 분 전인지를 낸다.
  - 마지막 기록은 **timestamp 가 있는 마지막 user·assistant 기록**이다.
  - 파일 수정 시각은 쓰지 않는다. 세션이 끝날 때 timestamp 없는 줄이 붙기 때문이다.
  - 실제로 1시간 전에 끝난 세션이 「약 1분 전」으로 보였다(PITFALLS §0).
  - 자기 세션은 가장 최근에 쓰인 파일로 추정한다. 틀리면 `--self <id>` 로 준다.
- 영수증 `harness.install.json` 의 유무
- harness-install 체크포인트(`git rev-parse --git-path harness-install-state.json`)의 유무
- uninstall 체크포인트(`git rev-parse --git-path harness-uninstall-state.json`)의 유무. 있으면 `U status <루트>` 로 진행 상황을 보인다.
- 설치가 커밋됐는가(`git log --oneline -- harness.config.mjs`)
  - 커밋되지 않았으면 걷어 낸 뒤 커밋할 것이 없다.
  - 그때는 6단계 verify 가 이유와 함께 「커밋 경로 0개」를 낸다.

판정:

- **harness-install 체크포인트가 있으면** 중단된 설치다.
  - 멈추고 harness-install 0단계의 「재개 / 초기화」로 넘긴다.
- **uninstall 체크포인트가 있으면** 재개다.
  - `done`·`applied` 를 보이고 남은 단계부터 잇는다.
  - `applied` 가 비어 있으면 「다시 뽑기(`scan --refresh`) / 그대로 잇기」를 묻는다.
- **다른 세션 확인이 필요하면** 그 사실을 보이고 계속할지 묻는다. 아래 조건 중 하나라도 맞으면 필요하다.
  - 걷어 낼 파일(`CLAUDE.md`·`.claude/settings.json`·`.gitignore`)에 하네스와 무관한 미커밋 변경이 있다.
  - 다른 세션이 살아 있다.

**다른 세션 확인 질문을 묻는 법**

- 이 질문은 혼자 먼저 묻는다. 목적 질문과 한 번에 묶지 않는다.
  - 이유: 여기서 「중단」을 고르면 목적 답은 쓸 데가 없다.
- 질문은 DECISIONS.md 「다른 세션 확인」을 따른다. 권장 없는 질문이다.
- 선택지 라벨에 「종료됨」 같은 단정을 넣지 않는다.
  - 그 세션이 끝났는지는 사용자가 판단한다.
- `sessions` 가 낸 마지막 기록 시각과 몇 분 전인지는 설명에 둔다.

작업본 편집은 블록·키 단위라 그 변경을 지우지 않는다. 다만 7단계 경로 지정 커밋에는 섞인다.

**완료 기준:**

- 위 항목마다 관찰값이 한 줄씩 적혀 있다.
- 판정이 「중단 — harness-install 초기화로」 · 「진행 — 새로 걷어내기」 · 「재개 — N단계부터」 중 하나다.

## 0-2. 로컬 선택 항목 — graft 로컬 연결 · 전역 상태 줄 (scan 전에)

다음 중 하나라도 맞으면 graft 로컬 연결이 있다.

- 영수증에 `local` 이 있다.
- 영수증이 없어도, `.claude/helpers/graft-hooks.cjs` 가 있다.
- 영수증이 없어도, `git rev-parse --git-path harness-kit-graft/state.json` 이 있다.

`S=${CLAUDE_SKILL_DIR}/../../scripts` 라 할 때, 상태는 `node "$S/graft-localize.mjs" status <루트>` 와 `node "$S/statusline-setup.mjs" status` 로 본다.

**범위 낮추기(1-2단계)면 이 단계를 건너뛴다.**

- graft 로컬 연결·전역 상태 줄(harness-install D9·D10)은 설치 범위와 따로인 선택 항목이다.
- 범위 낮추기는 `.gitignore`(`/graft/` 블록 포함)를 건드리지 않는다.
- graft 훅은 `settings.local.json` 에 있고 `.harness/` 를 가리키지 않는다. 그래서 범위 밖 훅 후보에도 들지 않는다.

이 단계에서 할 일:

- **scan 보다 먼저 한다.**
  - graft 훅을 남긴 채 `.gitignore` 의 `/graft/` 블록을 지우면, 다음 graft build 가 표시 없는 줄을 다시 덧붙인다.
  - 백업·검증의 기준은 graft 몫을 뺀 `settings.local.json` 이어야 한다.
  - 그래야 6단계 대조(하네스가 아닌 훅이 백업과 같은가)가 맞는다.
- **graft 로컬 연결** — [DECISIONS.md](DECISIONS.md) 「graft 로컬 연결」을 묻는다.
  - 「걷어 냄」이면 `node "$S/graft-localize.mjs" remove <루트>` 를 돌린다. 그래프 데이터를 남기려면 `--keep-graph` 를 붙인다.
  - remove 는 `failures=0` 이면 스냅숏·체크포인트를 지우고, 이번 백업 `git-path harness-kit-graft/backup-<시각>/` 은 남긴다(출력의 `백업:` 줄).
  - FAIL 이 있으면 다 남긴다.
  - 그래프 `graft/` 는 다시 만드는 산출물이라 백업하지 않는다.
  - `failures=0` 이어야 다음으로 간다.
  - info/exclude 블록은 worktree 끼리 공유인데도 지운다. 출력의 `WARN` 한 줄을 사용자에게 옮긴다.
    - `WARN` 내용 ①: 다른 worktree 의 graft 산출물이 미추적으로 보일 수 있다.
    - `WARN` 내용 ②: 그 helpers 의 개인 절대경로를 `git add -A` 로 커밋하지 않게 한다.
  - `KEEP` 줄(연결 전부터 있던 파일 · 추적 파일)도 옮긴다.
  - settings.json 에 graft 몫이 다시 들어와 있으면, remove 는 아무것도 지우지 않고 FAIL(종료코드 1)로 멈춘다.
  - 그때는 `graft-localize.mjs localize <루트>` 를 먼저 다시 돌리고, remove 를 다시 한다.
- **전역 상태 줄**
  - 전역 영수증(`~/.claude/harness-kit/receipt.json`)이 있을 때만 DECISIONS.md 「전역 상태 줄 되돌리기」를 따로 묻는다.
  - 「되돌림」이면 `node "$S/statusline-setup.mjs" restore` 를 돌린다.
  - 지금 값이 우리가 쓴 값과 다르면, 스크립트가 손대지 않고 종료코드 3 으로 멈춘다.
  - 그때는 그 사실만 보고한다.
  - 되돌리는 것은 전역 `statusLine` 값뿐이다. 사본 스크립트·`statusline.json` 은 남는다.
  - 출력의 `KEEP` 줄을 사용자에게 옮긴다. graft 를 쓰는 레포의 `settings.local.json` 이 그 사본을 계속 쓴다는 줄이다.
  - 이 PC 의 다른 레포도 같은 전역 줄을 쓴다. 그래서 레포 걷어내기가 저절로 되돌리지 않는다.
- **이 세션의 graft 훅 오류**
  - helpers 가 지워진 뒤, 이 세션에 이미 올라온 graft 훅이 오류(파일 없음)를 낼 수 있다.
  - 오류는 도구 호출·턴 끝에 난다. 막지는 않는 오류다.
  - 새 세션에서는 나지 않는다.

**완료 기준:**

- 로컬 항목이 없으면 「없음」이 적혀 있다.
- 있으면 답마다 스크립트 출력 끝 줄(`failures=0` · `OK` · `STOP` 과 이유)과 백업 경로가 보고 초안에 있다.

## 1. 후보 뽑기 — 영수증 또는 알려진 구조

`U scan <루트>` 를 돌린다. 스크립트가 체크포인트에 계획을 적고 표를 낸다(id · 질문 header · 상태 · 권장 · 답 · 항목 — 근거). 표 위 「후보 N개」 줄과 「설치: HEAD 에 커밋됨 / HEAD 에 없음」이 보고와 7단계의 근거다.

- **영수증이 있으면** 영수증의 파일·블록·줄·치환·훅·키가 후보다.
  - sha256 이 영수증과 다르면 상태가 `modified`(설치 뒤 손댐)다.
  - 영수증에 없는데 `.harness/` 안에 있으면 `extra` 다.
- **영수증이 없으면** 아래 알려진 구조로 뽑는다. 상태는 `unknown`(비교 기준 없음)이다.
  - `.harness/`
  - `harness.config.mjs`
  - `.harness/` 를 가리키는 settings 훅(`settings.local.json` 포함)
  - `CLAUDE.md` 의 「개발 하네스」 절과 그 절을 가리키는 줄
  - `.gitignore` 의 `.harness/` 줄과 바로 위 주석
  - config `commands.*`·`project.commands.*` 가 가리키는 보조 파일(이름에 harness 가 있거나 설치와 함께 생긴 것)
  - 설치 근거가 있는 `enabledPlugins` false 키
  - harness-kit 플러그인 키
  - 표시(`harness-kit:begin`·`harness-kit:line`)가 있으면 어느 파일이든 후보로 잡는다.
- **앞선 걷어내기가 있었으면** 그 백업에서 남긴 보조 파일을 다시 후보로 잡는다.
  - 백업 `git rev-parse --git-path harness-uninstall-backup/*/index.json` 에서 그때 후보와 답을 읽는다.
  - 이유: 두 번째 걷어내기에는 config 가 이미 없다. config 명령으로는 보조 파일을 못 찾는다.
  - 예전 꼴의 index.json(후보 목록 없음)이면, 백업 파일 중 이름에 harness 가 있는 것을 잡는다.
  - config 도 백업도 없으면, 이름에 harness 가 있고 미추적(또는 설치 커밋에서 생긴) 파일을 「권장 없음」으로 잡는다.
  - 표 위 「앞선 걷어내기 백업 N개」 줄이 그 근거다.
- **남을 참조** — 표 아래 목록은 권장대로 걷어 낸 뒤에도 남을 줄이다.
  - 보조 파일을 다른 파일이 가리키면, 그 보조 파일의 권장은 「남김」이 된다.
  - config 권장이 「지움」이면 그 config 의 가드 규칙 id 를 가리키는 줄도 이 목록에 든다(시험에서 `.claude/commands/save.md` 가 `git-commit`·`git-push` 를 인용한 채 남았다).
  - 보고의 참조 수는 이 줄(과 verify 요약)에서 옮긴다.
  - 시험에서 스크립트가 보조 파일을 몰라 「0줄」을 냈고, 보고는 그 수를 손으로 고쳐 썼다.
- **`.gitignore` 의 `/graft/` 표시 블록**(harness-install D9)
  - graft 가 아직 이 트리에 연결돼 있으면(0-2단계에서 남겼으면) 권장이 「남김」이다.
  - 지우면 graft build 가 표시 없는 줄을 다시 덧붙인다.
- 스크립트가 config 의 `project.git.commitExecution`·`push`·`coAuthor` 를 **지우기 전에** 읽어 체크포인트에 적는다. 7단계가 그 값을 쓴다.

**완료 기준:**

- 체크포인트에 계획이 있다.
- 표의 후보마다 header·상태·권장(또는 「권장 없음」)·근거가 있다.
- `WARN` 줄은 하나씩 사용자에게 옮겼다.
- 표에 없는데 하네스로 보이는 것을 찾았으면, 손으로 지우지 않고 보고에 적는다.

## 1-2. 범위 낮추기 — 계측 → 라이트 (목적이 그것일 때만)

`U scan <루트> --tier light` 를 돌린다. 지금 범위보다 낮은 범위를 주면, scan 은 걷어내기 계획 대신 **범위 낮추기 계획**을 뽑는다.

- 지금 범위는 영수증 `tier` 다. schema 1 이면 계측이다.
- 목적은 `lower` 다. 요청이 「라이트로 낮춰」류면 목적 질문은 없다.
  - 요청이 드러나지 않아 목적 질문에서 범위 낮추기를 골랐으면 `U answer purpose=lower` 가 이 명령을 안내한다(종료코드 2). 안내대로 `scan --refresh --tier light` 를 돌린다.
- 칸 되돌림은 잎 칸 단위다. 설치가 블록째 넣은 `project.docs` 라도 그 안의 라이트 칸과 docs-setup 표시 칸은 남는다(DECISIONS.md 「범위 낮추기」).
- 범위 올리기(라이트 → 계측)는 하지 않는다. 스크립트가 종료코드 2 로 거절한다.
- 올리려면 걷어 낸 뒤 새 세션에서 harness-install 을 계측으로 돌린다.

후보는 넷뿐이다. 골격 사본 · config 파일 · `.gitignore` · 보조 파일 · 계측 로그 · 플러그인 키는 후보가 아니고 남는다.

| 후보 | header | 권장 | 하는 일 |
| - | - | - | - |
| 범위 밖 하네스 훅(실행 뒤 · 실패 · 턴 시작 · 턴 종료) | `PostTool훅 처리` 류 | 지움 | settings 에서 그 훅만 지운다. 실행 전 가드는 남는다(계획의 `tier.keep` — verify 가 남았는지 본다) |
| 범위 밖 config 칸(영수증 `config.slots` 중 `tier: instrumented`) | `설정칸 처리 N` | 되돌림 · 설치 뒤 값이 바뀌었으면 권장 없음 · docs-setup 표시 칸은 남김만 | 칸 값을 설치 전 값으로 되돌린다(아래 「칸 되돌리기」) |
| 「개발 하네스」 절(Markdown 표시 블록) | `안내절 처리` | 새 판을 받기 전에는 권장 없음 → 받으면 바꿈 | 블록을 라이트 판으로 통째로 바꾼다(아래 「안내절 교체」) |
| 영수증 | `영수증 처리` | 갱신 | `tier` · 훅 · `config.slots` · config 해시 · 바꾼 블록 해시를 고치고 `tierChanges` 한 줄 · D0 답을 적는다. 다음 걷어내기의 기준이다 |

**칸 되돌리기**

- 칸 값을 설치 전 값(example 원문)으로 바꾸고, 꼬리 주석도 example 판으로 바꾼다.
- example 에 없던 칸은 칸째 지운다.
- 여러 줄 배열 칸도 같다.
- 되돌린 config 를 import 해 본다. 못 읽으면 통째로 원래 판으로 돌려 놓는다.

**안내절 교체**

1. harness-install TEMPLATES.md §4 의 라이트 판을 이 레포 값으로 채운다.
2. 채운 판을 scratchpad 에 Write 한다.
   - 꼴: 첫 줄 begin 표시 · 끝 줄 end 표시 · 안에 표시 없음.
3. `U block <루트> <후보 id> <파일>` 로 넘긴다.

블록은 통째로 바뀐다. 줄끝은 파일 것을 따른다.

이어서 지킬 것:

- **칸과 훅은 함께 간다.**
  - 칸을 되돌리지 않고 훅만 빼면 「설정 ≠ 연결」 상태가 된다.
  - 이 상태에서는 증거 슬롯이 채워져 있는데, 그 칸을 읽는 턴 종료 훅이 없다.
- **영수증에 `config.slots` 가 없으면**(schema 1 · `--example` 없이 쓴 영수증)
  - scan 은 칸 후보를 뽑지 않고, `WARN` 으로 범위 밖 칸 목록을 낸다.
  - 그 칸은 손으로 example 값으로 되돌린다.
- **이어지는 단계는 같다** — 항목 질문(2단계) → `U answer` → `U backup` → `U apply` → `U verify` → 보고 → `U finish`.
  - 2단계에서 목적·런타임·플러그인 질문은 없다.
  - 5단계(kit 키 · 설치 기록)는 해당하지 않는다.
  - 7단계 질문의 「제거」 문구도 해당하지 않는다. 커밋한다면 메시지는 「범위를 라이트로 낮춘다」 꼴이다.
- **verify 가 더 보는 것** — 걷어내기 판정에 더해 아래를 본다.
  - 되돌린 칸이 설치 전 값인가
  - 바꾼 블록이 새 판 그대로 있는가
  - 라이트 범위 훅이 남았는가
  - 영수증 `tier` 가 `light` 이고 범위 밖 훅이 없는가
- 낮춘 뒤 `harness-install` 의 `install.mjs hooks <루트>` 가 영수증 범위(라이트)로 `failures=0` 이어야 한다.

**완료 기준:**

- `U verify` 가 `failures=0` 이다.
- 설정칸 · 안내절 · 영수증 범위 `OK` 줄이 있다.
- 바꾸지 않은 후보(남김)는 그 이유와 함께 보고에 있다.

## 2. 결정 질문 — 권장과 함께 묻는다

[DECISIONS.md](DECISIONS.md) 의 순서(목적 → 런타임 산출물 → 항목 → 설치 뒤 손댄 것)로 묻는다. 다른 세션 확인은 0단계에서 이미 따로 물었다. 플러그인 키와 설치 기록은 5단계, 커밋은 7단계에서 묻는다.

- **권장과 선택지**
  - 질문마다 권장을 첫 선택지에 둔다. 「(권장)」과 근거 한 줄을 단다.
  - 선택지마다 바뀌는 것을 한 줄씩 단다.
- **header** — 표의 「질문 header」 열을 그대로 쓴다.
  - 스크립트가 대상 + 정할 것(12자 이하)으로 정해 둔 것이다. 선택지 하나를 쓰지 않는다.
  - 스크립트는 한 계획 안에서 header 가 겹치지 않게 정한다.
  - 훅은 이벤트 이름을 넣고, 같은 종류가 여럿이면 번호를 붙인다.
- **선택지 라벨**
  - 라벨은 그것만 읽어도 뜻이 통하게 쓴다.
  - 꼴은 DECISIONS.md 끝 절을 따른다(harness-install TEMPLATES.md §8 과 같은 꼴).
- **질문 본문은 평이한 말이 먼저다.**
  - 첫 문장은 무엇을 어떻게 할지를 일상어로 쓴다(「하네스 스크립트 19개를 지울까요?」).
  - 후보 id·경로·내부 용어(골격 사본 · 런타임 산출물 · git-common-dir)는 그 뒤 「근거:」에 둔다.
  - 바꿔 쓸 말은 DECISIONS.md 「질문의 꼴」의 낱말 표를 따른다.
- **목적 질문** — `U scan` 출력의 「목적 질문」 블록을 선택지 설명에 옮긴다.
  - 선택지마다 지우는 것 · 남는 것 · 새 세션에서 harness-install 이 뜨는가를 적는다. 완전 제거는 kit 키 두 개(`enabledPlugins."harness-kit@harness-kit"` · `extraKnownMarketplaces.harness-kit`)도 지운다고 적는다.
  - 범위 낮추기는 블록에 `lower` 줄이 있을 때만(계측 설치 · 영수증 없음) 셋째 선택지로 낸다.
  - 권장은 사용자 요청의 낱말로 정한다(DECISIONS.md 「목적」). 권장이면 「권장 이유: 요청의 「<낱말>」」, 낱말이 없으면 「권장 없음 — 요청에 목적이 드러나 있지 않다」.
- **권장이 있는 질문** — 「(권장)」 선택지 설명 첫 줄에 「권장 이유: <이 레포의 관찰>」을 쓴다.
- **권장이 없는 질문** — 표의 권장이 「권장 없음」인 칸 · 목적(낱말이 없을 때) · 다른 세션 확인.
  - 본문 첫 줄에 「권장 없음 — <무엇에 따라> 고릅니다」를 쓴다.
  - 어느 라벨에도 「(권장)」을 붙이지 않는다.
  - 선택지는 DECISIONS.md 에 적힌 고정 순서로 둔다.
  - 사용자가 「권장대로」라고 답해도 이 질문들은 채우지 않는다. 따로 다시 묻는다.
  - 첫 선택지를 권장으로 읽은 사고가 있었다(PITFALLS §2).
- **묶기**
  - 영수증이 없으면 후보마다 질문 하나다.
  - 영수증이 있으면 상태가 `clean` 인 같은 종류(훅 5개 등)를 한 질문에 묶을 수 있다.
  - 묶은 질문의 header 는 번호 없는 꼴을 쓴다.
  - `modified`·`extra` 는 따로 묻는다.
- **보내기 전 재독** — 질문을 보내기 전에 본문·라벨·설명의 한글을 한 번 다시 읽는다.
  - 시험에서 받침이 틀린 낱말과, 같은 낱말을 두 번 쓴 문장이 그대로 나갔다(PITFALLS §2).
  - 나간 자리는 선택지 설명과 보고였다.
- **답 적기** — 답을 받을 때마다 `U answer <루트> <id>=<값> …` 로 적는다.
  - 값: 목적은 `purpose=reinstall|remove|lower` · 칸은 `revert|keep` · 안내절은 `replace|keep` · 영수증은 `update`.
  - `purpose=lower` 는 답으로 적히지 않는다. 범위 낮추기 계획을 다시 뽑으라는 안내를 내고 종료코드 2 로 끝난다.
  - `scan --tier light` 로 뽑은 계획은 scan 이 목적을 정하므로 목적을 묻지 않는다.
  - 사용자가 「나머지는 모두 권장대로」라고 할 때만 `U answer <루트> --recommended` 를 쓴다.
  - 그때 권장이 없는 칸은 `keep` 으로 채워진다. 스크립트가 그 목록을 출력한다(보고에 옮긴다).
  - `--recommended` 는 목적(`purpose`)을 채우지 않는다.
  - 목적이 미정이면 스크립트가 그렇다고 출력하고, 플러그인 키도 비워 둔다.

**완료 기준:**

- `U status` 의 플러그인 외 모든 후보에 답이 있다.
- 각 답이 사용자 답과 같다. 내가 고른 값은 하나도 없다.
- 권장 없는 질문에 「(권장)」이 붙은 선택지를 보이지 않았다.

## 3. 백업 — 손대기 전에 한 번

`U backup <루트>` 를 돌린다. 스크립트가 하는 일:

- 손댈 파일 전부를 `<git-path>/harness-uninstall-backup/<시각>/files/` 에 복사하고 바이트 대조한다.
- 그 뒤 `index.json` 을 쓴다.
- 런타임 산출물을 지우기로 했으면 `<git-common-dir>/harness-evidence/<트리>-<시각>/` 에도 복사한다.

지킬 것:

- **백업은 한 번만 뜬다.**
  - 재개 때 다시 돌려도 덮어쓰지 않는다.
  - 걷어내던 중간 상태로 백업을 덮으면 원본을 잃는다.
- **`index.json` 의 해시는 둘이다.**
  - `sha256` 은 바이트 그대로다(되돌려 놓은 파일 대조용).
  - `sha256Lf` 는 줄끝을 LF 로 맞춘 뒤의 값이다(영수증과 같은 계산).
  - CRLF 파일은 두 값이 다르다.
- **「되돌리기:」 줄** — 출력의 이 줄은 그대로 복사해 돌리는 한 줄이다.
  - 이 줄은 백업의 `files/` 를 루트에 복사한다. 증거 사본이 있으면 그 `files/` 도 복사한다.
  - 이어서 스크립트 절대경로로 `restore-check` 를 불러 바이트 대조한다.
  - 체크포인트 없이 돌아서 `finish` 뒤에도 쓸 수 있다.
- **「되돌리기(스크립트가 없을 때)」 줄** — 출력에 함께 나온다.
  - kit 키를 지워 플러그인 사본이 없어졌을 때를 위한 줄이다.
  - 이 줄로 복사한 뒤에는 `git status`·`git diff` 로 확인한다.

**완료 기준:**

- 출력에 「백업 N개 = 후보 파일 N개」 줄이 있다. 「≠」 면 멈추고 보고한다.
- 이미 없어서 백업하지 않은 후보 경로가 있으면, 그 목록을 옮겼다.
- 백업·증거 사본 경로와 「되돌리기:」 줄을 사용자에게 알렸다.

## 4. 걷어내기 — 텍스트 → settings → 파일

`U apply <루트>` 를 돌린다. 스크립트가 답이 `remove`·`revert` 인 후보를 아래 순서로 걷어 낸다. 플러그인 키는 건드리지 않는다.

1. **텍스트** — 파일마다 한 번에 처리한다.
   - 영수증 치환을 설치 전 원문으로 되돌린다.
   - 표시 블록·절·줄 묶음·한 줄을 지운다.
   - 블록 앞뒤가 빈 줄이면 빈 줄 하나만 남긴다.
2. **settings** — 훅을 하나씩 지운다.
   - 그룹에 그 훅뿐이면 그룹을 지운다.
   - 이벤트에 그 그룹뿐이면 이벤트 키를 지운다.
   - 다른 훅·다른 키의 바이트는 그대로다.
   - 이어서 false 키를 지운다.
3. **파일** — 아래 순서로 지운다.
   1. 보조 파일 · config · 손댄/생긴 파일 · 골격 사본 · 런타임 산출물
      - 런타임 산출물은 지우기 직전에 증거 사본을 지금 판으로 다시 맞춘다(`OK 증거 사본 … 더해진 N줄` 줄).
      - 이유: 백업 뒤에도 살아 있는 훅이 로그에 줄을 더한다.
      - 맞추지 못하면 지우지 않고 `SKIP` 한다.
   2. 빈 디렉토리
   3. 마지막으로 영수증(남긴 항목이 없을 때만)

`.harness/` 가 지워진 뒤에는, 이 세션에 이미 올라온 하네스 훅이 도구 호출 때 오류(파일 없음)를 낼 수 있다. 오류가 나는지는 훅 설정을 다시 읽는지에 따라 다르다. 시험에서는 걷어 낸 뒤 Bash 4번에 오류가 없었다. 나더라도 막지는 않는 오류다. 재설치하려면 어느 쪽이든 새 세션을 연다(PITFALLS §4·§8).

**줄끝 맞추기**

- 걷어 낸 결과가 HEAD 와 내용이 같아지면, 스크립트가 그 파일의 줄끝을 체크아웃 판에 맞춰 쓴다(`INFO … 줄끝을 체크아웃 판(CRLF)에 맞췄다`).
- 내용이 HEAD 와 다르면 줄끝도 그대로 둔다.
- 이것은 걷어 낸 뒤에도 status 만 M 으로 남는 파일을 막는다.
- 그런 파일은 설치나 플러그인 CLI 가 CRLF 체크아웃 파일을 LF 로 다시 써서 생겼다.

**완료 기준:**

- 출력 끝에 `적용 N건` 줄이 있다. 할 일이 없었으면 `적용 0건 (플러그인 키는 5단계)` 이다.
- 그 위의 모든 줄이 `OK` 다. 아니면 `SKIP`·`KEEP` 줄마다 이유를 사용자에게 옮겼다.
- 이유의 예: 이미 없음 · 설치 뒤 손댄 것이라 되돌리지 않음 · 남긴 항목의 기준.

## 5. 플러그인 키 → 설치 기록 — 맨 마지막 결정, 검증보다 먼저

순서가 정해져 있다. 검증을 설치기록 질문보다 먼저 돌리지 않는다.

1. 5-1 키 지우기
2. 5-2 설치기록 질문
3. 5-3 CLI 와 대조·복원
4. 6단계 검증

**5-1 kit 키.**

- DECISIONS.md 「kit 키 처리」를 묻는다.
- header 는 `kit 키 처리` 다. 권장이 「켜 둠」이어도 header 가 한쪽 동작을 말하지 않게 한다.
- 이 스킬도 harness-kit 안에 있다.
- 키를 지우면 다음 세션부터 이 레포에서 harness-install·harness-uninstall 이 뜨지 않는다.
- 빠지는 것은 이 레포 설정뿐이다. 사용자 범위로 켜 둔 PC 에서는 계속 뜬다.
- 재설치가 목적이면 켜 두는 것이 권장이다.
- 답을 적고 키를 처리한다: `U answer <루트> plugin=off|keep` → `U plugin <루트>`.
- plugin 은 키를 지운 직후의 settings 를 백업 디렉토리 `after-plugin/` 에 스냅숏으로 뜬다.
- 이 스냅숏이 CLI 뒤 되덮기의 기준이다.
- 3단계 백업은 기준이 아니다. 키를 지우기 전 판이라, 그것으로 되덮으면 kit 키가 되살아난다.

**5-2 설치 기록.**

`U records <루트>` 를 돌린다.

- records 는 `~/.claude/plugins/installed_plugins.json` 의 harness-kit 기록 중 **`projectPath` 가 이 레포 루트와 같은 것만** 고른다.
- 경로를 비교할 때 Windows 는 대소문자를 무시하고 슬래시를 통일한다.
- 다른 트리(메인 트리 · 다른 worktree)의 기록은 근거로 쓰지 않는다. 「건드리지 않는다」로만 보인다.
- 시험에서 남의 트리 기록 둘(「project·local 둘 다 disabled」)을 이 트리의 근거로 썼다.

기록에 따라 할 일:

- **이 트리의 기록이 없으면** 묻지 않는다.
  - 보고에 「이 트리의 설치 기록 없음 — CLI 실행 안 함」을 옮긴다.
- **이 트리가 worktree 이고 메인 트리에도 기록이 있으면** 스크립트가 CLI 를 권하지 않는다(`WARN`).
  - 스크립트는 대신 손 절차(`INFO 손 절차`)를 낸다.
  - 그때는 CLI 를 선택지로 보이지 않는다. 손 절차는 사용자가 원할 때만 건넨다.
  - 이유: `claude plugin uninstall --scope project|local` 은 **cwd 의 프로젝트**에 작용한다.
  - CLI 가 worktree 를 메인 트리로 푸는지는 확인되지 않았다.
- **기록이 이 트리에만 있으면** DECISIONS.md 「설치기록 처리」를 묻는다.
  - 출력의 `CLI 후보` 줄이 실행할 명령이다(이 트리 루트에서만).

**5-3 CLI 뒤.**

- 「기록 삭제」를 고르면, CLI 를 이 트리 루트에서 실행한 직후 `U after-cli <루트>` 를 돌린다.
- after-cli 는 settings 를 `after-plugin/` 스냅숏과 바이트 대조한다.
- 달라졌으면 CLI 판을 `after-cli/` 에 남긴 뒤, 스냅숏 바이트로 되덮는다.
- 그러면 키 순서 · 지워진 키 · 줄끝이 스냅숏대로 돌아온다.
- CLI 를 돌리지 않았으면 이 단계는 없다.

**완료 기준:**

- 답이 체크포인트에 있다.
- `off` 면 두 키가 지워졌다는 `OK` 줄과 `after-plugin 스냅숏` 줄이 있다.
- `records` 출력이 있다(「이 트리의 설치 기록 없음」 · CLI 를 권하지 않은 이유 · `CLI 후보` 중 하나).
- CLI 를 돌렸으면 `after-cli: … failures=0` 줄이 있다.

## 6. 검증 — 남은 것과 그대로인 것

`U verify <루트>` 가 판정한다. 5단계(`records`, CLI 를 돌렸으면 `after-cli`)가 끝난 뒤에 돌린다. 그 전에 돌리면 `WARN 설치기록 단계(records)를 아직 안 돌렸다` 가 나온다.

verify 가 보는 것:

- 지우기로 한 파일·디렉토리가 남았는가
- settings 가 `after-plugin/` 스냅숏과 같은가
  - 다르면 `FAIL` 이다. CLI 가 다시 썼는데 `after-cli` 를 안 돌렸거나, 다른 세션이 고친 것이다.
- settings.json·settings.local.json
  - JSON 파싱 · 중복 키 0
  - `.harness` 훅 0(남기기로 한 것 빼고)
  - **하네스가 아닌 훅이 이벤트별로 백업과 같은가**
  - 다른 최상위 키와 다른 `enabledPlugins` 키가 그대로인가
- 후보 밖 파일 — 걷어내기 전부터 있던 미커밋 변경이 그대로이고, 새로 바뀐 파일이 없는가
  - 미추적 폴더(안에 git 저장소가 든 폴더 — 클론해 둔 마켓플레이스 등)는 git 이 `폴더/` 한 줄로만 낸다. 스크립트는 그 폴더를 앞머리로 보고, 폴더 안 파일을 「새로 바뀐 파일」로 세지 않는다.
  - 시험에서 `claude-plugins-official/` 이 걷어내기 전부터 있었는데 verify 가 FAIL 을 냈다.
- 남은 참조 — `.harness`·`harness.config`·`harness.install`·`harness-kit`·보조 파일 이름을 가리키는 줄(보고만)
  - config 를 지우면 그 config 의 `dangerGuard` 규칙 id(`git-commit`·`git-push` 등)를 가리키는 줄도 낸다. 커맨드 문서가 규칙 id 로 가드를 안내하던 줄이 남는다.
- **커밋 경로** — `git status --short` 와 커밋 경로를 낸다.
  - 커밋 경로는 추적 중인 후보 중 HEAD 와 다르고, **실제로 걷어 낸 조각이 HEAD 판에 있던 것**이다.
  - 스크립트가 걷어 낸 연산을 HEAD 판에 똑같이 해 보아 가린다.
  - 설치가 커밋되지 않은 트리에서는 걷어내기가 작업본을 HEAD 쪽으로 되돌릴 뿐이다.
  - 그래서 HEAD 와 남은 차이(손대지 않은 문서 줄 · 남긴 kit 키)는 걷어내기 결과가 아니다.
  - 스크립트는 그 차이를 커밋 경로에서 빼고, 이유와 함께 「커밋 경로 0개」로 낸다.
- **줄끝만 다른 파일** — status 는 M 인데 HEAD 와 내용이 같은 파일이다.
  - 대상: 후보 경로와, 후보가 아니어도 설치가 늘 고치는 `settings.json`·`settings.local.json`·`.gitignore`·`CLAUDE.md`
  - 스크립트가 그 파일을 지금 줄끝 · 체크아웃 판 줄끝과 함께 적는다.
  - 고치는 명령도 함께 낸다: `U eol-fix <루트> <경로>` 또는 `git checkout -- <경로>`.
  - `eol-fix` 는 체크아웃 판 바이트로 쓴다. HEAD 와 내용이 다르면 쓰지 않는다.
  - `git update-index --refresh` 로는 풀리지 않는다(autocrlf=true 시험에서 `needs update` 로 끝났다).
  - 고칠지는 사용자가 정한다.
- **「요약」 블록** — 출력 끝에 있다. 보고의 수와 경로는 이 블록에서 옮긴다.
  - 후보 수 · 답별 수 · 적용 건수
  - 권장이 없어 keep 으로 채운 칸
  - 남은 참조 수 · 설치 기록 판정
  - 백업 수와 절대경로 · after-plugin 스냅숏 · 증거 사본 절대경로
  - 되돌리기 두 줄 · 백업 수명
  - 앞선 백업·증거 사본
  - 「남긴 것을 나중에 지우려면」

**완료 기준:**

- `failures=0` 이다.
- 남은 참조 · 「줄끝만 다름」(과 고치는 명령) · 「HEAD 에 걷어 낸 조각이 없다」 줄이 보고에 옮겨져 있다.

## 7. 커밋 — 1단계에서 읽어 둔 정책대로, 직전에 묻는다

- **커밋 경로가 0개면** 커밋하지 않고, **메시지 파일도 만들지 않는다**.
  - verify 가 낸 이유 줄(예: 「설치가 HEAD 에 커밋된 적이 없다」)을 그대로 보고에 옮긴다.
  - 그 트리에서 남은 차이를 커밋하면, 「제거」가 아니라 「설치 일부 추가」 커밋이 된다.
- **커밋 정책** — 체크포인트에 읽어 둔 `commitExecution` 을 아래 표대로 따른다.

| `commitExecution` | 할 일 |
| - | - |
| `message-only` | 메시지 파일만 건넨다 |
| `auto` | 커밋 직전에 DECISIONS.md 「제거 커밋」을 따로 묻는다. 가드가 지워져 확인 창이 뜨지 않는다 |
| 값 없음(`null`) | 레포 `CLAUDE.md` 의 커밋 규칙을 보이고 묻는다 |

- 메시지는 레포 `git log` 관례를 따른다.
- 메시지 본문에 지운 것 · 남긴 것 · 백업 경로를 적는다.
- trailer 는 읽어 둔 `coAuthor` 와 레포 규칙이 허용할 때만 넣는다.
- 커밋은 경로 지정으로만 한다. 브랜치·toplevel 조건과 같은 명령에서 한다.
- 지운 파일도 경로로 넘긴다.

```bash
R=<레포 루트>; B=<브랜치>
[ "$(git -C "$R" rev-parse --show-toplevel)" = "$R" ] \
  && [ "$(git -C "$R" rev-parse --abbrev-ref HEAD)" = "$B" ] \
  && git -C "$R" commit -F <메시지 파일> -- <verify 가 낸 커밋 경로…>
```

**커밋 뒤 — 커밋이 어디 있나 보이고, push·병합을 묻는다.**

- `node "${CLAUDE_SKILL_DIR}/../harness-install/scripts/install.mjs" commit-where <루트>` 를 돌린다.
  - 연결 worktree 면 기준 브랜치는 메인 트리의 브랜치다. 다르면 `--base <브랜치>` 를 준다.
- 출력(커밋 위치 · 메인 작업 브랜치에서 닿는가 · 원격 · 다음 할 일)을 응답 본문에 옮긴다.
- 그 다음 DECISIONS.md 「제거 반영」을 묻는다(header `제거 반영`). 묻지 않고 미루지 않는다.
  - 1단계에서 읽어 둔 `project.git.push` 로 권장을 정한다. `'never'` 면 push 선택지를 내지 않는다.
  - 고른 명령만 실행한다. 꼴은 `commit-where` 의 「다음 할 일」(같은 명령 안 브랜치 조건)이다.
  - 「지금은 하지 않음」이면 보고에 그 명령을 옮긴다.

**완료 기준:**

- 커밋했으면 `commit-where` 출력이 응답 본문에 있고, 「제거 반영」 답을 받았다.
- 커밋했으면 `git show --stat HEAD` 의 파일 목록이 커밋 경로와 같다.
- 커밋했으면 `git status --short` 에 걷어내기 전부터 있던 변경(과 남긴 항목)만 남아 있다.
- 커밋하지 않았으면 그 이유가 보고에 있다.

## 8. 보고 → 그다음에 체크포인트 정리

**순서가 정해져 있다.**

1. 보고를 응답 본문으로 먼저 내보낸다.
2. 그 뒤에 `U finish <루트>` 를 부른다.
3. finish 출력 한 줄(체크포인트를 지웠다)만 덧붙인다.

- **finish 를 보고보다 먼저 부르지 않는다.**
  - 보고가 끊기거나 틀리면, 체크포인트로 `U status`·`U verify` 를 다시 돌려 보고를 다시 만들 수 있어야 한다.
- finish 는 체크포인트 파일 하나만 지운다.
- 백업과 증거 사본은 그대로다. 그래서 보고에 적은 경로는 finish 뒤에도 유효하다.

보고에 담을 것은 아래와 같다. 수와 경로는 verify 「요약」 블록에서 옮기고, 손으로 세지 않는다. 시험에서 후보 14개를 13개로 적었다.

- **기준과 처리**
  - 기준(영수증 / 알려진 구조) · 후보 수(플러그인 키 포함)
  - 지운 것 · 되돌린 것 · 남긴 것(이유)
  - 「설치 뒤 손댄 것」의 처리
  - 권장이 없어 keep 으로 채운 칸
- **결과**
  - 남은 참조 목록 · 검증 결과
  - 커밋: SHA, 메시지 파일, 또는 verify 가 낸 「커밋하지 않음」 이유
  - 커밋 위치(`commit-where` 출력): 브랜치 · worktree 경로 · 메인 작업 브랜치에서 닿는가 · 「제거 반영」 답과 하지 않은 명령
  - worktree 에서 걷어 냈으면 작업을 메인 트리로 가져오는 명령(병합)과 worktree 를 지우는 명령. worktree 를 지우면 그 안의 백업도 지워진다고 함께 적는다.
  - 플러그인 키 상태
  - 설치 기록: 요약의 「설치 기록:」 줄. 다른 트리 기록은 건드리지 않았다는 것을 적는다.
- **0-2단계 로컬 항목**
  - graft 로컬 연결: 걷어 냄 / 남김 · 백업 경로 · 남긴 exclude 블록과 이유
  - 전역 상태 줄: 되돌림 / 남김 / 값이 달라 손대지 않음
  - 남겼으면 나중에 걷어 내는 명령(`graft-localize.mjs remove` · `statusline-setup.mjs restore`)을 적는다.
- **백업과 증거 사본 — 두 절대경로와 수명.**
  - 백업은 `git-path` 아래에 있다. worktree 면 `.git/worktrees/<이름>/` 안이라 `git worktree remove` 가 함께 지운다.
  - 다음 harness-install·docs-setup 은 이 트리 · 메인 트리 · 다른 worktree 의 백업을 모두 찾는다. worktree 를 지우기 전이면 거기서 찾는다.
  - 증거 사본은 `git-common-dir/harness-evidence/` 아래라 worktree 를 지워도 남는다. 필요 없어지면 손으로 지운다.
  - 재설치할 수 있으면, 백업을 레포 밖으로 옮겨 두라고 적는다.
  - **앞선 걷어내기의 백업·증거 사본**도 함께 적는다(요약의 「앞선 백업」·「앞선 증거 사본」 줄).
  - 앞선 증거 사본은 손으로 지워야 남지 않는다고 적는다.
- **사후리뷰 기록** — 요약의 「리뷰 기록(사용자 데이터 — 남겼다)」 줄과 「지우려면」 줄을 그대로 옮긴다.
  - 대상: `refs/notes/<notesRef>` · 받아 둔 기록 `refs/notes/<notesRef>-<remote>` · `remote.<remote>.fetch` 의 notes refspec
  - 이것은 설치물이 아니라 `/harness-kit:review-pending`·save 가 남긴 리뷰 결과다. 후보로 뽑지 않고 지우지 않는다.
  - 기본은 남긴다. 사용자가 지우겠다고 하면 그 줄의 명령을 건넨다. 이 스킬이 대신 돌리지 않는다.
  - 원격의 같은 ref 는 팀 공용이라 다루지 않는다.
  - 줄이 없으면(기록·refspec 이 없거나 config 에 `notesRef` 가 없었다) 적지 않는다.
- **docs-setup 칸** — 요약의 「docs-setup 칸 N개」 줄을 지운 항목과 따로 옮긴다.
  - 옮길 것: 칸과 값 · 백업 config 경로 · 되살리는 길
  - 되살리는 길: docs-setup 다시 돌리기 · 재설치면 harness-install D8-2
  - 설치 단계를 바꾸는 재설치(낮은 단계로 내리기 등)에서도 같다.
  - 이유: 문서 칸이 없는 단계에서도 docs-setup 은 자기 블록을 다시 넣는다.
- **되돌리는 법**
  - 요약의 「되돌리기:」 줄(그대로 복사해 돌린다)과 「되돌리기(스크립트가 없을 때)」 줄을 옮긴다.
  - 되돌리면 하네스 훅도 돌아오니, 새 세션을 연다는 말을 붙인다.
- **남긴 것을 나중에 지우려면**
  - 요약의 같은 이름 절을 항목마다 옮긴다(다시 걷어내기 · 정확한 손 편집 · 줄끝 명령).
  - `git restore`·`git checkout -- <파일>` 로 한꺼번에 되돌리지 않는다고 적는다.
  - 이유: 파일 단위라 다른 변경까지 되돌린다. 자동 모드의 권한 분류기가 막을 수도 있다.
  - 막히면 우회하지 않는다. 줄 단위 Edit 나 걷어내기 재실행으로 한다(PITFALLS §8).

**재설치 절차는 uninstall → 새 세션 → install 이다.**

- 걷어 낸 세션에는 옛 훅과 옛 `CLAUDE.md` 가 올라와 있다.
- 같은 세션에서 harness-install 을 돌리면, 0단계가 옛 상태를 보고 판정이 틀어진다.
- 사용자에게 「새 세션을 열고 `하네스 설치해줘`」라고 안내한다.
- 옛 훅이 이 세션에서 오류를 낼지는 훅 설정을 다시 읽는지에 따라 다르다.
- 그러니 「반드시 오류가 난다」고 쓰지 않는다.
- 플러그인 키를 지웠으면 새 세션에서 harness-install 이 뜨지 않는다.
- 그때는 사용자 범위로 켜거나 키를 다시 넣는 방법을 함께 적는다.
