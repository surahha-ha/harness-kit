# docs-setup — 문서가 접힐 자리와 규약을 세운다

이 스킬이 레포에 남기는 것은 세 가지다.

1. **문서 구조와 아카이브 규약**
   - 아카이브 폴더, 아카이브로 옮긴 문서와 그 배너
   - `docs/README.md` 성격표
   - `CLAUDE.md` 의 작업 라우팅·문서 규약 표
2. **config 칸**
   - 채우는 칸: harness-kit `project.docs.archiveDir`·`pathValidator`·`autoloaded`·`project.memory.slugs`.
   - harness-agent `docs.always`·`docs.archive` 를 그 값과 맞춘다.
   - 목표는 archive-cycle 이 읽는 칸이 모두 채워지는 것이다.
   - 설치 단계(tier)와 무관하게 돈다. 문서 칸이 없는 config 에는 자기 블록을 넣는다.
   - 채운 칸마다 줄 끝에 `// harness-kit:docs-setup` 표시를 단다.
   - 영수증(`harness.install.json`)이 있으면 `owners["docs-setup"]` 에 적는다.
   - config 는 harness-install 이 만든 파일이라 걷어내기와 함께 지워진다.
   - 표시가 있으면 걷어내기가 따로 보고하고 백업에 남긴다. 그러면 재설치가 그 칸을 되살린다(harness-install D8-2).
3. **메모리 규약**
   - 레포 `CLAUDE.md` 의 한 절이다.
   - 메모리 폴더는 레포 밖이라 구조를 만들지 않는다. Claude 가 런타임에 따를 규칙만 둔다.

프로젝트 고유 지식은 레포 안(`CLAUDE.md`·`docs/`)에 둔다. 메모리에는 레포 문서로 가는 포인터와 세션 사이의 진행 상태만 둔다.

끝까지 지배하는 말 다섯 개:

- **묻는다**
  - 결정은 근거와 함께 하나씩 묻는다([DECISIONS.md](DECISIONS.md)).
  - 권장은 1단계 관찰에서 계산해 보일 뿐이다. 고르는 것은 사용자다.
  - 분류 이름·폴더 이름은 정해 두지 않는다. 레포에 있는 문서를 보고 제안한다.
- **아직 일을 시키는가**
  - 문서를 옮길지는 이 질문으로 가른다. 크기·날짜·상태 표기로 가르지 않는다.
  - archive-cycle ② 와 같은 기준이다.
  - 표기는 힌트일 뿐이다. 본문을 열어 판정한다.
- **옮기면 깨진다**
  - 문서 이동은 참조를 깨뜨린다.
  - 아카이브가 아닌 이동의 권장은 언제나 「옮기지 않음」이다.
  - 옮길 때는 참조 고침 목록을 보이고, 확인받은 뒤 고친다.
- **스테이징하지 않는다**
  - `git mv`·`git add <경로>` 를 쓰지 않는다. 새 파일의 `git add -N` 만 쓴다.
  - 일반 파일 이동을 한다.
  - 커밋은 경로 지정(`git commit -- <옛 경로> <새 경로>…`)으로만 한다.
  - 남의 스테이징을 삼키지 않는다.
- **체크포인트**
  - 2단계부터 단계가 완료 기준을 통과할 때마다 체크포인트를 적는다. 2단계는 답 하나마다 적는다.
  - 자리: `git rev-parse --git-path docs-setup-state.json` 파일.
  - 적는 것: 완료 단계·결정 답·이동 계획·백업 위치(꼴은 [TEMPLATES.md](TEMPLATES.md) §7).
  - 이동 계획과 링크 기준선도 같은 git 디렉토리에 둔다. scratchpad 는 세션과 함께 사라진다.
  - 세션이 끊기면 다음 세션이 이 스킬을 다시 불러 0단계에서 이어받는다.

보조 스크립트는 이 스킬 디렉토리의 `scripts/` 에 있다(node, 의존성 없음).

- 출력은 요약만 낸다. 전체는 `--json <파일>` 로 scratchpad 에 받는다.
- 대상 레포의 작업 트리에는 결과 파일을 만들지 않는다.
- 이어받기에 쓰는 계획·기준선·체크포인트·백업은 git 디렉토리에 둔다.

| 스크립트 | 하는 일 | 쓰는 단계 |
| - | - | - |
| `observe.mjs <레포>` | `docs/` 문서별 표지·참조 수, `CLAUDE.md` 의 표 유무, config 칸과 그 어긋남, 메모리 크기 | 1 · 4 |
| `refs.mjs <레포> <문서>…` · `--prefix` · `--plan` · `--after` | 옮길 문서의 참조와 패턴 참조, 이동 계획의 참조 고침 목록(세부는 아래) | 2 · 3 · 4 |
| `links.mjs <레포>` | 깨진 상대 링크·경로 참조(세부는 아래) | 3 · 4 |
| `config-slots.mjs list·record·backups·restore <레포>` | 표시 붙은 config 칸 읽기 · 영수증 `owners["docs-setup"]` 기록 · 백업에 남은 칸 조회 · 백업에서 칸 되살리기(세부는 아래) | 0 · 3 · 4 |
| `boundary.mjs <레포> --base <rev>` | 이번에 쓴 줄이 harness-uninstall 의 후보 꼴에 걸리는지(세부는 아래) | 4 |

**스크립트별 세부**

- `refs.mjs`
  - 옮길 문서의 참조(링크·경로·이름만)와 패턴 참조를 낸다.
  - 이동 계획의 참조 고침 목록을 낸다.
  - 링크 글자에 적힌 옛 경로도 고친다.
  - 지시 문서(`CLAUDE.md`·`.claude/`·config)의 참조는 고치지 않는다. 「지시 문서」로 따로 낸다.
  - 파일을 바꾸는 것은 `--apply --backup` 일 때뿐이다.
  - `--after` 는 적용 뒤 남은 옛 경로만 낸다. 배너의 출처 표기·새 경로 표기는 정상으로 센다.
- `links.mjs`
  - `--baseline` 으로 이번에 새로 깨진 것만 센다.
  - 코드 스팬·펜스 안의 링크 꼴은 예시로 보고 세지 않는다.
  - 펜스는 연 글자와 같은 글자로만 닫힌다.
- `config-slots.mjs`
  - `list` — 표시 붙은 config 칸을 읽는다.
  - `record` — 영수증 `owners["docs-setup"]` 에 기록한다.
  - `backups` — 걷어내기 백업에 남은 칸과 그 칸이 가리키는 경로를 낸다.
  - `restore` — 백업에서 칸을 되살린다. harness-install D8-2 도 이 명령을 쓴다.
- `boundary.mjs`
  - 후보 꼴: 설치 표시 · 표시 블록 안 · 「개발 하네스」 절.
  - uninstall 과 같은 판정 함수로 본다.

## 0. 사전 확인 — 이 트리에서 지금 돌려도 되는가

확인할 것:

- `git status --short` · 현재 브랜치 · `git worktree list`
  - 특히 `docs/`·`CLAUDE.md`·`README.md`·`harness.config.mjs`·`.claude/` 의 미커밋 변경을 본다.
- **같은 트리의 살아 있는 다른 Claude 세션**
  - `~/.claude/projects/<트리 경로 슬러그>/*.jsonl` 의 최근 수정 시각을 본다.
  - 자기 세션 파일은 뺀다.
- 체크포인트 파일
  - 있으면 남은 상태(완료 단계·답·이동 계획·백업 위치)를 보이고 「재개 / 처음부터」를 묻는다.
  - 체크포인트의 `plan`·`linksBaseline` 파일이 없으면 그 사실을 보인다. 옛 꼴은 scratchpad 를 가리켰다.
  - 그때 계획은 `decisions` 의 A2 값으로 다시 쓴다.
  - 그때 기준선은 「없음 — 새 깨짐을 가를 수 없다」로 보고한다.
- `harness.config.mjs` 의 유무
  - 없으면 config 칸 결정은 「harness-install 먼저」로 보고한다. 나머지 결정만 진행한다.
  - 있는데 문서 칸 블록이 없으면(문서 칸이 없는 설치 단계) 그대로 진행한다.
- 앞선 걷어내기 백업에 남은 docs-setup 칸
  - `config-slots.mjs backups <레포>` 로 본다.
  - 있으면 A6 의 근거로 쓴다.
- 한글이 든 문서의 인코딩
  - `observe.mjs` 가 UTF-8 이 아닌 문서를 낸다.
  - 변환 전에는 그 문서를 판정 근거로 쓰지 않는다. 이동·고침 대상에서도 뺀다.

**판정** — 아래 중 하나면 **worktree 에서 돌리자고 제안한다.**

- 문서·`CLAUDE.md`·`.claude/`(에이전트·커맨드·스킬) 에 미커밋 변경이 있다.
- 다른 세션이 살아 있다.

이유: 이동과 참조 고침이 남의 작업과 한 파일에 섞인다.

**완료 기준:**

- 위 항목마다 관찰값이 한 줄씩 있다.
- 판정이 셋 중 하나로 나 있다: 「중단」 · 「진행 — 현 트리 / worktree 후보」 · 「재개 — N단계부터」.
- 그 판정과 관찰값을 사용자에게 보이는 응답 본문에 냈다.
- `observe.mjs` 의 첫 줄을 봤다.
  - 사실: 그 줄이 문서와 지시 문서(`.claude/`·하위 `CLAUDE.md`)의 미커밋 변경을 함께 센다.
  - 할 일: 이 스킬이 고칠 파일과 겹치는지 본다.

## 1. 관찰 — 읽기만

```bash
node <스킬>/scripts/observe.mjs <레포> --json <scratchpad>/observe.json [--untracked-skip <남의 미추적 폴더>/]
```

조사할 것:

- **`docs/` 트리**
  - 할 일:
    - 파일 목록과 문서마다 성격을 본다: 현행 규칙·명세 / 진행 계획 / 시점 기록·완료 보고 / 참조.
    - **후보마다 본문을 연다.**
    - 진행 상태를 모으는 문서(백로그 표 등)가 있으면 그것과 대조한다.
  - 근거 — 표지만으로 판정하지 않는 이유:
    - `observe.mjs` 의 표지 힌트(`기록?`·`살아있음?`·`혼재`)는 출발점일 뿐이다.
    - 체크하지 않은 상자는 끝난 문서에도 흔하다.
    - 상태 줄과 상위 백로그 표가 서로 다른 일도 흔하다.
- **들어오는 참조**
  - 문서마다 링크·경로·이름만 참조 수를 센다.
  - 참조하는 쪽이 **지시 문서**인지 서술 문서인지도 본다.
  - 지시 문서는 `CLAUDE.md`·`.claude/` 의 에이전트·커맨드·스킬·config 다.
- **`CLAUDE.md`**
  - 루트와 하위 `CLAUDE.md` 목록을 본다.
  - 작업 라우팅 표·문서 규약 표·문서 목록 절·메모리 절의 유무와 크기를 본다.
  - 크기를 보는 이유: 자동 로드라 매 턴 실린다.
- **다른 곳의 문서 색인**
  - 루트 `README.md` 의 문서 표 등을 본다.
  - 성격표가 그것을 복제하지 않게 한다.
- **config**
  - 볼 칸: kit `project.docs.*`·`project.memory.slugs`·`project.git.commitExecution`, harness-agent `docs.always`·`docs.archive`.
  - 서로 어긋나는지 본다.
    - `docs.archive` 접두가 살아 있는 문서를 덮는가
    - `archiveDir` 가 `docs.archive` 에 없는가
    - `autoloaded` 가 실제 `CLAUDE.md` 목록과 다른가
- **메모리**
  - `~/.claude/projects/<슬러그>/memory` 의 파일 수·크기·핸드오프류 수를 본다.
  - `MEMORY.md` 의 줄 수·바이트·가장 긴 줄·절 구성을 본다.
  - 자동 로드 한도 대비 비율을 본다.
  - 한도는 앞 200줄 또는 25KB 중 먼저 닿는 쪽이다.
  - 한도의 근거는 Claude Code 문서의 auto memory 절이다. 바뀔 수 있다.
- **경로 검사기**
  - 레포에 문서 경로·링크 검사 스크립트가 있는가를 본다(`pathValidator` 후보).

**완료 기준:**

- [DECISIONS.md](DECISIONS.md) 의 질문마다 「근거(파일:행·관찰값) 있음 / 근거 없음」이 표시돼 있다.
- 질문마다 권장 규칙표에서 맞은 줄이 표시돼 있다.
- 아카이브 후보 문서마다 판정 근거 한 줄이 있다.

## 2. 결정 질문 — 하나씩 묻는다

[DECISIONS.md](DECISIONS.md) 의 순서대로 묻는다(아카이브 폴더 → 옮길 문서 → 나머지 문서 → 성격표 → `CLAUDE.md` 표 → config 칸 → 메모리 규약). 앞 답이 뒤 질문의 선택지를 바꾼다. 일괄 기본값을 보이고 "이대로 갈까요" 로 묶지 않는다.

- **근거 표는 질문보다 먼저 응답 본문에 낸다.**
  - 사용자가 보는 것은 응답 본문과 질문 창뿐이다.
  - 생각 안에 만든 표와 서브에이전트의 보고는 보이지 않는다.
  - 본문으로 낼 표: 옮길 문서의 후보 표(A2) · config 칸 표(A6) · 메모리 판단값 표(A7) · 3단계의 참조 고침 목록.
  - 이 표는 AskUserQuestion 을 부르기 전에 낸다. 그 뒤에만 질문에 「위 표」라고 쓴다.
  - 표를 내지 않았으면 값을 `question` 안에 직접 적는다(칸=값).
- **질문 꼴**
  - 질문 header 는 번호 없이 **대상 + 동작** 명사구로 쓴다(12자 이하, `아카이브 폴더 정함`).
  - 질문 첫 문장은 대상과 할 일을 평이한 말로 쓴다.
  - 선택지 라벨은 그것만 읽어도 뜻이 통하게 쓴다.
  - 이 스킬의 용어는 첫 문장에 풀어 쓴다: 접기·이관 후 접기·성격표·게이트·칸·SSOT·이름만·판단값.
  - 꼴과 풀이표는 [TEMPLATES.md](TEMPLATES.md) §8 에 있다.
- **권장 표시**
  - 권장 선택지를 첫 번째에 둔다. 라벨 끝에 「(권장)」을 붙인다.
  - 설명 첫 줄에 「권장 이유: …」를 둔다.
  - 선택지마다 바뀌는 것을 한 줄씩 단다.
  - 권장 규칙표에 맞는 줄이 없으면 「권장 없음 — <무엇을 찾지 못했나>. 직접 골라 주세요」로 묻는다.
  - 그때는 어느 선택지에도 「(권장)」을 붙이지 않는다.
- **옮길 문서 질문**
  - 후보 표(문서 · 판정 · 근거 · 들어오는 참조 수)를 먼저 보이고 묻는다.
  - 「이관 후 접기」로 판정된 문서는 이 스킬에서 옮기지 않는다.
  - 그 문서는 archive-cycle ③ 의 이관 대상 목록으로 넘긴다.
  - 판정을 서브에이전트에 맡겼으면 그 표를 본문으로 옮겨 보인다.
- **문구 재독** — 질문과 선택지 문구도 내기 전에 한 번 읽는다. 오타·깨진 음절은 훅이 잡지 못한다.
- **체크포인트** — 답을 받을 때마다 체크포인트에 그 답, 정해진 값, 권장·근거·따름 여부를 적는다.

**완료 기준:** 모든 질문에 사용자 답이 있거나 「미정 → 하지 않음 / `null`」로 기록돼 있고, 체크포인트의 답과 같다. 내가 고른 값은 하나도 없다.

## 3. 적용 — 백업 → 이동 → 참조 고침 → 배너 → 표·절 → config

순서를 지킨다. 각 하위 단계가 끝날 때마다 체크포인트 `done` 에 적는다.

1. **기준선** — 고치기 전 링크 상태를 떠 둔다.
   - 명령: `node <스킬>/scripts/links.mjs <레포> --json "$(git -C <레포> rev-parse --git-path docs-setup-links-before.json)"`
   - 이미 깨진 참조는 이번 작업의 결과가 아니다.
   - 기준선은 git 디렉토리에 둔다. 그래야 세션이 끊겨도 4단계가 같은 기준선과 대조한다.
2. **이동 계획**
   - 2단계 답으로 `plan.json` 을 쓴다.
   - 꼴은 `{ "moves": [{ "from", "to" }] }` 이고, 경로는 레포 기준 상대경로다.
   - 자리는 `git -C <레포> rev-parse --git-path docs-setup-plan.json` 경로다. 체크포인트에 그 경로를 적는다.
   - 아카이브 안에서는 원래 하위 경로를 유지한다: `docs/<하위>/<문서>` → `<archiveDir>/<하위>/<문서>`.
   - 그래야 같은 이름 충돌을 막고 출처가 남는다.
3. **참조 고침 목록**
   - 실행:
     - `node <스킬>/scripts/refs.mjs <레포> --plan <plan.json> --list 200 --json <scratchpad>/refs.json` 을 돌린다.
     - 옮기는 폴더·접두 경로를 쓰는 패턴 참조는 `--prefix <접두>` 로 함께 돌린다.
     - 목록을 아래 셋으로 묶어 응답 본문에 보인다.
   - 분류:
     - **자동 고침**
       - 대상: `link`(그 문서로 풀리는 마크다운 링크) · `path`(레포 기준 경로 문자열) · `out`(옮긴 문서 안의 상대 링크).
       - `path` 에는 링크 글자 `[docs/a.md](…)` 안의 경로도 든다.
       - 스크립트가 새 위치 기준으로 다시 쓴다.
       - 합계 줄의 「자동 고침 N건」에는 지시 문서 줄이 들지 않는다.
     - **지시 문서의 참조는 경로만 바꾸지 않는다.**
       - 대상: `CLAUDE.md`·`.claude/` 의 에이전트·커맨드·config 가 「먼저 읽을 문서」로 가리키던 것.
       - 이것을 아카이브 경로로 바꾸면, 에이전트가 시점 기록을 현행으로 읽는다.
       - `refs.mjs` 는 이 줄을 `instr` 로 따로 낸다. `--apply` 에서도 고치지 않는다.
       - 줄마다 「지움 / 현행 문서로 바꿈 / 아카이브 경로로만 바꿈」 안을 보이고 고른다.
     - **눈으로 볼 것**
       - `name`: 파일 이름만 맞는 줄(코드 주석·디렉토리 그림·표의 글자).
       - 패턴 참조: `plan-*.md` 처럼 이름 틀로 문서를 찾는 커맨드 등.
       - 줄마다 「고침 / 그대로(사유)」를 받는다.
   - 다음: **확인을 받은 뒤에만** 4번으로 간다.
4. **백업 · 이동 · 자동 고침**
   - 명령: `node <스킬>/scripts/refs.mjs <레포> --plan <plan.json> --apply --backup "$(git -C <레포> rev-parse --git-path docs-setup-backup)"`
   - 스크립트가 옮길 파일과 고칠 파일을 먼저 백업한다.
   - 아래 중 하나라도 걸리면 스크립트는 아무것도 하지 않고 멈춘다.
     - 원본이 없다.
     - 대상이 이미 있다.
     - UTF-8 이 아닌 파일이 낀다.
   - git 디렉토리 안의 백업은 커밋에 섞이지 않고, 세션이 끊겨도 남는다.
   - 아래 줄은 3번에서 받은 답대로 곧바로 Edit 로 고친다.
     - 지시 문서 줄(스크립트가 고치지 않고 남긴 것)
     - 이름만 줄
     - 패턴 참조
   - 고치기 전까지 지시 문서는 옛 경로를 가리킨다.
5. **배너**
   - 옮긴 문서마다 [TEMPLATES.md](TEMPLATES.md) §1 의 배너를 Edit 로 단다.
   - 자리는 첫 제목 줄 바로 아래다. 제목이 없으면 맨 위다.
   - archive-cycle ④ 와 같은 꼴이다: 시점 · 「현행 아님」 · 접은 판정 근거 · 현행이 있는 곳.
6. **성격표 · `CLAUDE.md` 표 · 메모리 규약 절**
   - 2단계 답대로 [TEMPLATES.md](TEMPLATES.md) §2~§4 꼴로 Edit/Write 한다.
   - 행은 이 레포의 관찰에서만 만든다. 없는 문서·스킬을 행으로 지어내지 않는다.
   - **설치가 넣은 것 밖에 둔다.**
     - `<!-- harness-kit:begin -->`~`end` 블록 안에 쓰지 않는다.
     - 「개발 하네스」 절 안에 쓰지 않는다.
     - `harness-kit:line` 표시 줄과 「개발 하네스」 절을 가리키는 줄은 옮기거나 고치지 않는다.
     - 그 안에 쓴 줄은 걷어내기가 설치와 함께 지운다.
   - 기존 절을 바꾸거나 이름을 바꿨으면(문서 목록 절 → 라우팅 표 등) 옛 절 이름을 레포 전체에서 찾는다.
     - 찾을 곳: `config` 주석의 「<절 이름>」 절 · 다른 문서의 절 안내.
     - 찾은 곳을 새 이름으로 고친다.
7. **config**
   - 2단계 답대로 `harness.config.mjs` 를 Edit 로 고친다(§5).
   - 값만 바꾼다. 칸마다 한 줄에 줄 끝 주석 `// harness-kit:docs-setup — <근거>` 를 단다.
   - 여러 줄 배열을 한 줄로 합칠 때는 항목별 주석의 뜻을 표시 주석 안에 옮긴다.
   - 이유: 주석이 사라지면 그 항목을 왜 두는지가 함께 사라진다.
   - 문서 칸 블록이 없으면 그 블록을 연다. 여는 줄에도 표시를 단다.
   - 열거형·경로 규칙은 harness-kit README 「프로젝트 프로필」을 따른다(상대경로, 개인 경로 금지).
   - 고친 뒤 `config-slots.mjs list <레포>` 가 `failures=0` 이어야 한다.
   - 영수증이 있으면 `config-slots.mjs record <레포>` 를 돌린다.

한글은 Write/Edit 로만 쓴다. 쓴 직후 그 부분을 다시 읽어 오타와 깨진 음절을 확인한다.

**완료 기준:**

- 계획의 이동이 전부 끝났다(원래 경로에 없음 · 새 경로에 있음).
- 3번 목록의 줄마다 「고침 / 그대로(사유)」가 있다.
- 옮긴 문서마다 배너가 있다.
- 백업 위치가 체크포인트에 있다.

## 4. 검증 — 깨진 것이 없고, archive-cycle 이 읽는 칸이 찼는가

1. **링크**
   - `node <스킬>/scripts/links.mjs <레포> --baseline <git 디렉토리>/docs-setup-links-before.json --plan <git 디렉토리>/docs-setup-plan.json` 을 돌린다.
   - 새 깨짐 0 이어야 한다(종료코드 0).
   - 기준선에서 고쳐진 것도 함께 보고한다.
2. **남은 옛 경로**
   - `node <스킬>/scripts/refs.mjs <레포> --plan <plan.json> --after` 를 돌린다.
   - 배너의 출처 표기와 새 경로를 적은 줄의 파일 이름은 「정상」으로 따로 센다.
   - 목록에 남은 줄은 3번에서 「그대로」로 받은 것뿐이어야 한다.
   - 체크포인트 `refDecisions` 와 대조한다.
3. **경로 검사기** — `pathValidator` 가 있으면 그것도 돌린다. 없으면 1번이 유일한 수단이라고 보고에 적는다.
4. **config**
   - `node --check harness.config.mjs` 가 통과한다.
   - `observe.mjs` 를 다시 돌린다. archive-cycle 이 읽는 네 칸에 「키 없음」이 0 이어야 한다.
     - 네 칸: `docs.archiveDir`·`docs.pathValidator`·`docs.autoloaded`·`memory.slugs`.
   - 「어긋남?」 줄은 2단계에서 받은 답으로 설명돼야 한다.
     - 아카이브 폴더 하나로 모았고 안의 문서가 모두 배너를 달았으면, 그 칸은 「맞음」 줄로 나온다.
   - `config-slots.mjs list` 가 채운 칸마다 `SLOT` 줄을 낸다.
     - 영수증이 있으면 「owners 가 표시 칸과 같다」도 낸다.
   - 설치가 끝난 레포면 harness-install 의 `install.mjs slots <레포>` 도 `failures=0` 이다.
5. **걷어내기 경계**
   - `node <스킬>/scripts/boundary.mjs <레포> --base <시작 HEAD>` 가 `failures=0` 이다.
   - 옮긴 문서·배너·성격표·`CLAUDE.md` 표가 harness-uninstall 의 후보 꼴에 걸리지 않는다.
6. **한글** — 이번에 쓴 배너·표·절을 다시 읽어 깨진 음절·오타가 없다.

**완료 기준:** 여섯 확인의 출력이 있고, 실패가 있으면 고쳤거나 「남은 문제」로 보고에 있다.

## 5. 커밋 — 경로 지정, 같은 명령에서 브랜치 조건

- config `project.git.commitExecution` 을 따른다.
  - `'message-only'` 면 메시지 파일과 명령만 건넨다.
  - config 가 없으면 묻는다.
- 신규 파일(옮긴 문서의 새 경로, 새 `docs/README.md`)은 `git add -N -- <경로>` 를 먼저 한다.
- 커밋은 `git commit -F <메시지 파일> -- <옛 경로…> <새 경로…> <고친 파일…>` 로만 한다.
  - 이동은 **옛 경로와 새 경로를 둘 다** 넣는다. 그래야 지움과 생김이 한 커밋에 들어간다.
  - 브랜치·toplevel 조건과 커밋을 한 명령에 둔다(꼴은 [TEMPLATES.md](TEMPLATES.md) §6).
- 메시지는 레포 `git log` 관례와 config `project.git.commitFormat`·`coAuthor` 를 따른다.
- push 는 config `project.git.push` 를 따르고, `'ask'` 면 실행 직전에 따로 확인받는다.

**완료 기준:**

- 커밋 직후 `git status --short` 에 시작 전부터 있던 변경만 남아 있다.
- `git show --stat HEAD` 의 파일 목록이 의도한 목록(이동 쌍 · 고친 파일 · 새 파일)과 같다.

## 보고

마지막 응답에 아래를 담는다.

- 결정별 답 표(「권장」 열 — 권장대로 / 권장과 다름 / 권장 없음)
- 옮긴 문서와 판정 근거
- archive-cycle 로 넘긴 「이관 후 접기」 목록
- 참조 고침 수(자동 / 지시 문서 / 눈으로 본 것)
- 채운 config 값
- 검증 결과
- 커밋 SHA 또는 건넨 메시지
- 남은 문제

코드 색인 도구(심볼·호출 그래프 색인 등)는 이 스킬이 넣지 않는다. 문서 구조와 별개인 **선택 사항**이라는 한 줄만 보고에 둔다.

보고를 건넨 뒤 체크포인트 파일을 지운다. 아래 셋은 사용자가 커밋을 확인한 뒤 지우도록 위치를 한 줄씩 알린다. 셋 다 같은 git 디렉토리에 있다.

- 백업 폴더(`docs-setup-backup`)
- 이동 계획(`docs-setup-plan.json`)
- 링크 기준선(`docs-setup-links-before.json`)

세션이 끊겨 다른 세션이 이어 갈 때도 이 스킬을 다시 불러 0단계부터 탄다. 메모리·핸드오프 메모만 보고 4·5단계를 돌리면 결정별 답 표 같은 보고 항목이 빠진다. 스킬이 목록에 없으면 체크포인트의 `skillDir` 에서 이 파일을 읽는다.

## 함정

| 함정 | 일어나는 일 | 처방 |
| - | - | - |
| 상태 표기 신뢰 | 「ACTIVE」로 적힌 문서가 상위 백로그에서는 끝났고, 「COMPLETE」 문서에 추적되지 않는 이월 항목이 남아 있다 | 1단계에서 본문과 백로그를 대조한다 |
| 체크 상자 신뢰 | 끝난 계획서의 상자가 하나도 체크돼 있지 않다 | 상자 수가 아니라 기능이 나갔는지(코드·커밋)를 본다 |
| 지시 문서 경로만 바꿈 | 에이전트·커맨드가 아카이브 문서를 현행 참조로 계속 읽는다 | 3단계 3번 — 지우거나 현행 SSOT 로 바꾼다 |
| 접두 경로 아카이브 | `docs.archive` 의 접두가 같은 이름 꼴의 살아 있는 문서까지 검사에서 뺀다 | 아카이브 폴더 하나로 모은다 |
| 패턴 참조 놓침 | 이름 틀(`plan-*.md`)로 문서를 찾는 커맨드가 옮긴 문서를 더는 찾지 못한다 | `refs.mjs --prefix` 로 찾아 줄마다 묻는다 |
| `git mv`·`git add` | 남의 스테이징까지 커밋에 섞인다 | 일반 이동 + `add -N` + 경로 지정 커밋 |
| 이관 없이 이동 | 끝난 문서에만 있던 현행 규칙이 「현행 아님」 폴더로 사라진다 | 「이관 후 접기」는 옮기지 않고 archive-cycle 로 넘긴다 |
| 성격표가 색인 복제 | 루트 README 의 문서 표와 `docs/README.md` 가 따로 낡는다 | 성격표는 규칙과 분류만, 파일 목록은 기존 색인을 링크한다 |
| 표시 없이 config 칸 채움 | 재설치가 config 를 새로 만들며 값이 사라지고, 설치 값과 구별되지 않아 되살릴 근거도 없다 | 칸마다 줄 끝 `// harness-kit:docs-setup` · `config-slots.mjs list` |
| 설치 블록 안에 표 추가 | 걷어내기가 「개발 하네스」 블록·절과 함께 docs-setup 표를 지운다 | 블록·절 밖에 둔다 · `boundary.mjs` |
| 근거 표를 생각 안에만 둠 | 질문이 「위 표대로」라고 하는데 사용자에게는 표가 없다. 후보 판정·칸 값을 못 본 채 고른다 | 2단계 — 표를 응답 본문에 먼저 낸다 |
| 계획·기준선을 scratchpad 에 둠 | 세션이 바뀌면 체크포인트가 가리키는 파일이 없어 이어받은 세션이 새 깨짐을 가르지 못한다 | git 디렉토리(`--git-path`)에 둔다 |
| 링크 글자의 옛 경로 | `[docs/a.md](a.md)` 의 대상만 고치고 글자는 옛 경로로 남는다 | `refs.mjs` 가 글자 안 경로도 path 로 고친다 |
| 바꾼 절 이름이 남음 | config 주석·다른 문서가 없어진 절(「Key Documentation」 등)을 계속 가리킨다 | 3단계 6번 — 옛 절 이름을 찾아 고친다 |
