# 결정 질문 — 2단계에서 하나씩 묻는다

질문마다 **1단계 근거(파일:행·관찰값)** 를 먼저 보이고, 선택지와 각 선택이 바꾸는 것을 함께 제시한다. 사용자가 답하지 않은 칸은 내가 고르지 않는다 — 「미정 → 하지 않음」(config 는 `null` + 「미확정」 주석)으로 두고 보고에 적는다. 답을 바꾸면 체크포인트의 그 항목도 덮어쓴다(TEMPLATES.md §7).

아래 순서대로 묻는다. 앞 답이 뒤 질문의 선택지를 바꾼다.

## 권장 — 관찰에서 계산하고, 고르는 것은 사용자다

- 각 결정의 **권장 규칙** 표를 위에서부터 읽어 1단계 관찰과 **처음 맞는 줄**의 권장을 쓴다. 앞 결정의 답도 관찰로 친다.
- 맞는 줄이 없으면 「권장 없음 — <무엇을 찾지 못했나>. 직접 골라 주세요」라고 적고 어느 선택지에도 「(권장)」을 붙이지 않는다. 표에 없는 근거로 권장을 지어내지 않는다.
- 권장 선택지를 **첫 번째**에 두고 끝에 「(권장)」을 붙이며, 설명 첫 줄에 **「권장 이유: <이 레포의 관찰>」** 을 단다. 선택지마다 **바뀌는 것**을 한 줄씩 단다(꼴 TEMPLATES.md §8).
- 질문이 기대는 표(후보 표·칸 표·판단값 표)는 질문보다 먼저 **응답 본문**에 낸다. 생각 안의 표·서브에이전트 보고는 사용자에게 보이지 않는다.
- **권장 자리에 두지 않는 선택지** — 아카이브가 아닌 문서 이동, 「살아있음」·「이관 후 접기」 문서의 이동, 지시 문서의 참조를 아카이브 경로로만 바꾸기. 선택지로는 보인다.
- 수치 기준(줄 길이·한도 비율·보관 개수)은 **판단값**이다. 질문과 절에 「판단값」이라고 밝히고, 사용자가 바꾸면 그 값을 쓴다.
- 사용자가 권장과 다르게 고르면 그대로 따른다. 체크포인트의 그 답에 `followed: false` 를 적는다.

## A1. 아카이브 폴더 — 어디에 두고, 지금 만드는가

- 근거: `docs/` 아래 기존 보관 폴더(이름이 보관·이력·archive 류이거나 안의 문서가 배너를 달고 있다), config `project.docs.archiveDir`, harness-agent `docs.archive`.

| 관찰 | 권장 |
| - | - |
| config `archiveDir` 가 이미 있고 그 폴더가 있다 | 그대로 둔다(묻지 않고 보고에 「유지」) |
| 배너를 단 문서가 모인 기존 폴더가 있다 | 그 폴더를 아카이브로 쓴다 |
| `docs/` 가 있고 보관 폴더는 없다 | `docs/archive` 를 새로 정한다 |
| `docs/` 가 없다 | 권장 없음 — `docs/` 가 없다 |

- 선택지 — 바뀌는 것
  - **`docs/archive` 새로 정함** — `project.docs.archiveDir: 'docs/archive'`. 폴더는 첫 문서를 옮길 때 생긴다(빈 폴더는 git 에 남지 않는다). 옮길 문서가 0건이어도 칸은 채워 archive-cycle 이 다음에 쓴다.
  - **기존 폴더를 아카이브로 씀** — 그 경로가 `archiveDir` 가 된다. 안의 배너 없는 문서는 A2 후보로 함께 본다.
  - **아카이브 두지 않음** — `archiveDir: null`. archive-cycle ④ 의 레포 문서 이동이 건너뛰어진다.

## A2. 아카이브로 옮길 문서 — 「아직 일을 시키는가」

- 근거: 1단계에서 후보마다 연 본문, 진행 상태를 모으는 문서(백로그 표 등)와의 대조, 기능이 나갔는지(코드·커밋), 들어오는 참조 수.
- 문서마다 판정한다(archive-cycle ② 와 같다). 후보 표를 보인 뒤 한 번 묻는다.

| 문서 관찰 | 판정 | 이번에 옮기나 |
| - | - | - |
| 남은 후속·대기·미배포 항목이 본문에 있거나, 백로그가 진행 중으로 가리킨다 | 살아있음 | 옮기지 않는다 |
| 현행 동작·규칙·명세·참조를 적은 문서다(설계서·API 명세·운영 가이드·영구 체크리스트·착수 전 계획) | 살아있음 | 옮기지 않는다 — 낡았으면 내용 갱신 대상으로 보고 |
| 일이 끝났고(백로그·커밋으로 확인) 본문의 현행 지식이 다른 현행 문서·코드에 이미 있다 | 접기 | 옮긴다(권장) |
| 일이 끝났지만 본문에만 있는 현행 규칙·추적되지 않는 이월 항목이 있다 | 이관 후 접기 | 옮기지 않는다 — archive-cycle ③ 이관 대상으로 넘긴다 |
| 완료 표기가 없거나, 표기와 본문·백로그가 어긋나 판정이 서지 않는다 | 살아있음 | 옮기지 않는다 |
| 본문에 설치 표시(`harness-kit:begin`·`harness-kit:line`)가 있다 | 판정과 무관 | 옮기지 않는다 — 영수증의 경로와 어긋나 걷어내기가 그 줄을 「설치 뒤 생긴 것」으로 잡는다. 보고에 적는다 |

- 선택지 — 바뀌는 것
  - **「접기」 후보 전부 옮김** — 「접기」 후보가 1건 이상이면 권장이다. 표의 「접기」 문서가 `archiveDir` 아래로 옮겨지고 배너가 달린다. 참조 고침 목록이 3단계에 뜬다.
  - **골라서 옮김 — 목록을 받음** — 사용자가 고른 문서만 옮긴다. 「살아있음」·「이관 후 접기」 문서를 고르면 그 근거를 한 번 더 보이고 확인받는다.
  - **지금은 옮기지 않음** — 폴더와 규약만 세운다. 후보 표는 보고에 남겨 archive-cycle 이 쓴다.
- 「접기」 후보가 0건이면 묻지 않고 보고에 「후보 없음」을 적는다.

## A3. 나머지 문서 — 분류 폴더로 옮기는가

- 근거: 살아 있는 문서 수, 그 문서들에 들어오는 참조 수(특히 지시 문서의 참조).

| 관찰 | 권장 |
| - | - |
| (언제나) | 옮기지 않음 — 이동은 참조를 깨뜨리고, 분류는 성격표(A4)가 이동 없이 보여 준다 |

- 선택지 — 바뀌는 것
  - **옮기지 않음 (권장)** — 문서 경로가 그대로다. 분류는 A4 의 성격표에만 적힌다.
  - **분류 폴더로 옮김 — 대상 목록을 받음** — 분류 이름과 대상 문서를 사용자에게 받는다(이 레포의 문서를 보고 분류 이름을 제안할 수는 있다). 대상마다 참조 수를 보인 뒤 A2 와 같은 3단계 절차(목록 확인 → 백업 → 이동 → 고침)를 탄다. 배너는 달지 않는다.

## A4. 문서 성격표 — `docs/README.md`

- 근거: `docs/README.md` 의 유무와 내용, 다른 곳의 문서 색인(루트 `README.md` 의 문서 표 등)과 그 링크 수, `docs/` 파일 수.

| 관찰 | 권장 |
| - | - |
| `docs/README.md` 에 폴더·문서 성격(현행 / 시점 기록) 표가 이미 있다 | 아카이브 행만 보강(없으면) — 나머지는 묻지 않는다 |
| `docs/README.md` 는 있는데 성격 구분이 없다 | 기존 README 에 성격표 보강 |
| `docs/README.md` 가 없고 다른 곳에 문서 색인이 있다 | 새로 만듦 — 성격 규칙·분류·아카이브 규약만 두고 파일 목록은 그 색인을 링크한다 |
| `docs/README.md` 도 다른 색인도 없다 | 새로 만듦 — 분류별 문서 목록까지 |

- 선택지 — 바뀌는 것
  - **새로 만듦** — `docs/README.md` 가 생긴다(꼴 TEMPLATES.md §2). harness-agent `docs.always` 에 더할지를 A6 에서 함께 묻는다.
  - **기존 README 보강** — 성격 열·아카이브 행이 더해진다.
  - **만들지 않음** — 성격은 `CLAUDE.md` 문서 규약 표(A5)에만 남는다.

## A5. `CLAUDE.md` 표 — 작업 라우팅 · 문서 규약

항목마다 따로 묻는다. `CLAUDE.md` 는 자동 로드라 늘어난 바이트가 매 턴 실린다 — 질문 근거에 더해질 대략의 크기를 적는다.

| 항목 | 관찰 | 권장 |
| - | - | - |
| 작업 라우팅 | 작업 → 먼저 읽을 것 표가 있다 | 아카이브로 옮긴 문서를 가리키는 행만 고침(3단계 지시 문서 처리) — 묻지 않는다 |
| 작업 라우팅 | 문서 목록 절(작업 열 없이 문서만 나열)이 있다 | 그 절을 라우팅 표로 바꿈 — 목록의 문서는 그대로, 「이 작업을 한다면」 열을 더한다 |
| 작업 라우팅 | 둘 다 없다 | 새 절 추가 — 행은 이 레포의 현행 문서·스킬·커맨드에서만 |
| 문서 규약 | 성격 구분·아카이브 규칙을 적은 절이 있다 | 아카이브 행·배너 규칙만 보강(없으면) |
| 문서 규약 | 없다 | 새 절 추가 |

- 선택지 — 바뀌는 것
  - **새 절 추가 / 라우팅 표로 바꿈 / 보강** — `CLAUDE.md` 에 TEMPLATES.md §3 꼴의 절이 들어가거나 바뀐다. 레포 작업 라우팅 표가 있으면 docs-setup 이 세운 규약 절을 가리키는 한 줄을 건다.
  - **넣지 않음** — 규약은 `docs/README.md`(A4)에만 있다. 자동 로드되지 않으므로 Claude 가 아카이브 규칙을 모른 채 문서를 열 수 있다.

## A6. config 칸 — archive-cycle 이 읽는 넷과 게이트 문서 칸

`harness.config.mjs` 가 없으면 묻지 않고 「harness-install 먼저」로 보고한다. 칸마다 권장을 따로 계산해 칸 표(칸 · 지금 값 · 넣을 값 · 근거)를 응답 본문에 낸 뒤 한 질문으로 묻는다.

- **설치 단계와 무관하다.** config 에 `project.docs`·`project.memory`·게이트 `docs` 블록이 없어도(문서 칸이 없는 단계) 묻는다 — 채우면 그 블록을 새로 열고 여는 줄에도 표시를 단다(TEMPLATES.md §5). 설치가 채운 다른 칸은 건드리지 않는다.
- **채운 칸은 docs-setup 소유로 표시한다.** 칸마다 한 줄, 줄 끝 주석이 `// harness-kit:docs-setup` 으로 시작한다. 표시가 있어야 걷어내기가 그 칸을 따로 보고하고 백업에 적으며, 재설치가 되살린다. 표시 없이 채운 칸은 설치 값과 구별되지 않아 재설치 때 잃는다.
- 앞선 걷어내기 백업에 docs-setup 칸이 있으면(`config-slots.mjs backups`) 그 값을 칸마다 근거 줄에 보인다 — 가리키는 폴더·파일이 남아 있으면 그 값이 권장이다.

| 칸 | 관찰 | 권장 |
| - | - | - |
| `project.docs.archiveDir` | A1 답이 있다 | 그 경로 |
| `project.docs.pathValidator` | 레포에 문서 경로·링크 검사 스크립트가 있다 | 그 실행 명령 |
| `project.docs.pathValidator` | 없다 | `null` — 검증은 이 스킬의 `links.mjs` 와 grep 이 맡는다고 주석 |
| `project.docs.autoloaded` | 실제 `CLAUDE.md` 목록과 다르다 | 실제 목록(레포 기준 상대경로) |
| `project.memory.slugs` | 메모리 디렉토리가 있고 슬러그에 사용자 이름·홈 경로가 없다 | 그 슬러그(대소문자만 다른 둘은 같은 폴더로 보고 하나만) |
| `project.memory.slugs` | 슬러그에 사용자 이름이 들어가거나 메모리 디렉토리가 없다 | `null` |
| `docs.archive`(게이트) | 접두가 살아 있는 문서를 덮거나 `archiveDir` 가 빠져 있다 | `[<archiveDir>/]` 로 모음 — 접두가 덮던 살아 있는 문서는 검사 대상으로 돌아온다 |
| `docs.archive`(게이트) | 이미 `archiveDir` 만 담고 있다 | 그대로 |
| `docs.always`(게이트) | A4 에서 `docs/README.md` 를 만들었다 | 더한다 — 틀리면 문서를 잘못 찾아간다 |
| `docs.always`(게이트) | 목록의 파일이 없다 | 그 항목을 뺀다 |

- 선택지 — 바뀌는 것
  - **표대로 채움** — 칸마다 값과 근거 주석이 들어간다. archive-cycle 이 「키 없음」에서 멈추지 않는다.
  - **칸을 골라 채움** — 고르지 않은 칸은 그대로 두고 보고에 적는다.
  - **채우지 않음** — config 를 건드리지 않는다. archive-cycle 이 빈 칸에서 멈추고 묻는다.

## A7. 메모리 규약 — `CLAUDE.md` 에 넣는가, 기준값은

- 근거: 1단계 메모리 관찰(파일 수·크기·핸드오프류 수, `MEMORY.md` 줄 수·바이트·가장 긴 줄·150자 넘는 줄 수(`--line-max`)·절 구성), 레포 문서와 같은 내용을 담은 메모리 파일(진행 계획 사본 등).

| 관찰 | 권장 |
| - | - |
| 메모리 디렉토리가 있다 | `CLAUDE.md` 에 넣음 — 기준값은 아래 판단값 |
| 메모리 디렉토리가 없다 | 권장 없음 — 메모리 디렉토리가 없다. 넣으면 다음 세션부터 따른다 |

기준값(판단값 — 질문에 그대로 보이고, 바꾸면 그 값을 쓴다):

| 기준 | 판단값 | 근거 |
| - | - | - |
| 인덱스 한 줄 | `- [제목](파일.md) — 한 줄 요약`, 150자 이하 | 인덱스는 매 세션 실리고, 자세한 것은 토픽 파일이 SSOT 다 |
| 인덱스 절 | 진행 중 · 규칙 · 참조 · 완료(접힘) | 매 세션 먼저 볼 것이 위에 온다 |
| 끝난 일 | 연표 파일 하나(`날짜 · 무엇을 · 결과 · 커밋` 한 줄씩)로 접고 인덱스에는 그 파일 한 줄만 | archive-cycle ④ |
| 핸드오프 | 최근 4 세션만 | archive-cycle ④ 「최근 3~4 세션」 |
| 레포 지식 | 메모리에 복제하지 않고 레포 문서 경로를 가리킨다 | 레포 밖이라 팀과 다른 PC 가 못 본다 |
| archive-cycle 부를 때 | `MEMORY.md` 가 자동 로드 한도(앞 200줄 또는 25KB)의 60% 를 넘거나, 150자 넘는 인덱스 줄이 5개 이상 | 한도를 넘으면 뒤가 세션에 실리지 않는다 |

- 선택지 — 바뀌는 것
  - **`CLAUDE.md` 에 넣음** — TEMPLATES.md §4 꼴의 절이 들어간다. 지금 기준을 넘었으면 보고에 「archive-cycle 권함」을 적는다. 메모리 폴더 자체는 이 스킬이 고치지 않는다.
  - **기준값을 바꿔 넣음** — 사용자가 준 값으로 같은 절을 넣는다.
  - **넣지 않음** — 메모리 규약이 레포에 없다. archive-cycle 은 여전히 돌지만 언제 부를지 기준이 없다.
