# 실전 함정 — 단계별

각 단계를 시작할 때 같은 번호 절을 읽는다. 전부 실제 설치에서 터진 것이다.

## §0 사전 확인

- **워킹트리를 커밋본으로 단정하지 않는다.** IDE·사용자가 브랜치를 바꿔 둔 채인 경우가 잦다. 결론 전에 `git status`·현재 브랜치를 본다.
- **같은 트리의 다른 세션이 settings.json 을 고치는 중일 수 있다.** 다른 도구가 훅을 설치하면서 settings.json·`.gitignore` 를 미커밋으로 바꿔 둔 상태였다. 그 위에 하네스를 얹으면 설치 커밋이 남의 변경을 삼키거나, 나중 병합이 틀린다 → worktree.
- **끝난 세션을 살아 있는 세션으로 셌다.** 트랜스크립트 파일의 수정 시각이 「2시간 안」이라 worktree 를 권했는데, 그 세션은 설치 세션을 열기 30초 전에 사용자가 중단하고 끝낸 것이었다. 파일 끝에는 종료 때 붙는 줄(timestamp 없는 비용·마지막 입력 기록)이 붙어 수정 시각이 늦어진다. 마지막 user·assistant 기록의 시각을 이 세션 시작과 견주고(`install.mjs precheck`), 시작 전에 끝난 기록은 「동시」로 세지 않는다. 끝났는지 기록만으로 가를 수 없으면 권장 없이 묻는다.
- **설치 트리가 이미 시험용 연결 worktree 였다.** 「새 worktree 에 설치」를 권하면 worktree 를 하나 더 만들자는 말이 되는데, 질문이 그것을 밝히지 않았다. 트리 종류를 먼저 보고 선택지 이름을 「지금 worktree 에 설치」·「새 worktree 를 하나 더 만들어 설치」로 바꾼다(DECISIONS.md D1).
- **설정 파일을 저장하면 그 트리에서 돌던 세션이 바로 훅을 집어 든다.** 설치 도중에도 다른 세션 이벤트가 `.harness/log.jsonl` 에 쌓일 수 있다. 반대로 `CLAUDE.md` 규칙은 새 세션부터 적용된다.
- **끊긴 설치는 「이미 설치됨」처럼 보인다.** `.harness/` 와 example 과 바이트가 같은 config 만 남은 트리가 있었다. 파일 유무로 가르지 말고 CHECKS.md §5 의 표(체크포인트 · example 동일 여부 · `--status`)로 가른다.
- **HEAD 에 하네스가 있는데 작업본에서만 지운 트리가 있었다** — 재현 시험을 하려고 일부러 걷어낸 것이었다. 복원부터 하면 시험을 망치고, 묻지 않고 설치하면 실수로 지운 경우를 덮는다 → 멈추고 의도를 묻는다.
- `core.autocrlf=true` 이고 `.gitattributes` 가 없으면 워킹트리는 CRLF 다. Git Bash 로 도는 `.sh` 훅이 `\r` 때문에 조용히 아무것도 안 할 수 있다 — 기존 훅의 실제 동작은 확인 못 했으면 「미확인」으로 적는다.

## §1 레포 분석

- **기본 프로파일이 공유 개발 DB 를 향하는 레포가 있다.** 프로파일 이름(`local`·`dev`)과 실제 연결 대상은 다르다. 기본값이 공유 호스트면 앱 기동만으로 스키마 마이그레이션이 그쪽에 적용된다 — 이것은 명령 문자열에 호스트가 안 드러나 가드가 못 본다(`risk.destructive` 와 CLAUDE.md 로 알린다).
- **공유 DB 에 직접 쓰는 테스트가 비활성화 없이 커밋돼 있었다.** 디버깅용 일회성 코드가 하드코딩 접속·쓰기 구문을 단 채 남아, 전체 테스트를 돌리는 순간 공유 데이터를 바꿨다. CI 는 테스트를 건너뛰어 안전했고, 위험은 **로컬·에이전트의 전체 테스트**였다. 전체 테스트 명령을 안내하는 문서(CLAUDE.md·커맨드·에이전트 문서)가 그대로 그 사고 경로다.
- 테스트 실행 기록(리포트 디렉토리·결과 파일)이 없다고 안전한 것이 아니다 — 아직 안 돌렸을 뿐이다.
- 레포 안 커맨드(`/save` 류)가 `테스트 2>&1 | tail` 꼴로 결과를 판정하고 있었다. 파이프 끝 명령의 종료코드가 되어 실패를 통과로 읽는다.
- FE 단위 테스트 러너가 없는 레포도 있다. 없는 러너의 명령을 지어내지 않는다(`null`).

## §2 결정 질문

- 레포 `CLAUDE.md` 는 「커밋은 하지 않고 메시지만」인데 다른 메모리·자동화 규칙은 「선택 커밋까지 자동」이었다. 서로 다른 규칙이 있으면 둘 다 보여 주고 고르게 한다.
- kit 의 `git.commitExecution` 은 `'auto'`·`'message-only'` 만 받는다. `'ask'` 를 넣었다가 무효라 멈춘 적이 있다 — 열거형 값은 README 「프로젝트 프로필」에서 확인한다.
- 하네스 deny 와 공유 자원 ask 의 경계: 공유 쓰기를 deny 로 두면 승인된 쓰기를 사람이 직접 쳐야 하고, 그때 접속 정보가 대화에 남는다.
- **플러그인을 끄자 그 플러그인이 막던 가드가 함께 사라졌다.** 겹침 질문(D6)을 위험 명령 질문(D4) 뒤에 물어, 볼륨 삭제를 「막지 않음」으로 정한 뒤에야 끈 플러그인이 그것을 막고 있었다는 것을 알았다. 결국 D4 를 다시 묻고, 사라지는 규칙 열 가지를 따로 조사해 세 묶음을 다시 적었다. D6 을 D4 앞에 묻고, 끄기로 하면 그 플러그인의 훅을 `install.mjs plugin-hooks` 로 뽑아 사라지는 것마다 묻는다(D6-2).
- **질문이 내부 용어로 시작해 다섯 번 되물었다.** 「D4-4 의 주제가 무엇인지 이해가 안 된다」(`gradlew --stop`) · 「deny 는 원천 차단인가, 차단하고 나서 어떻게 되나」 · 「trailer 가 뭐야」 · 「어떤 설정이랑 겹쳐서 없어진 거야」(플러그인을 끄면 사라지는 가드) · 「옮길 위치가 deny → 플러그인으로 옮기는 거야」(방향을 거꾸로 읽음). 질문 첫 문장은 무엇이 일어나는지를 쉬운 말로 쓰고, 용어는 괄호로 보낸다(TEMPLATES.md §8 풀이표).
- **권장 없는 질문의 첫 선택지가 권장으로 읽혔다.** 근거가 없으면 「권장 없음」을 질문에 밝히고 「(권장)」을 어디에도 붙이지 않는다.

## §3 게이트 설치

- **골라 복사 금지.** 바뀐 파일만 옮기면 새로 생긴 `lib/` 모듈이 빠지고, 실행 전 훅은 로드 실패(종료코드 1)를 「막지 않음」으로 읽는다 — 가드가 조용히 꺼진다.
- 레포 고유 보조 파일을 `.harness/` 안에 두면 ① 사본↔원본 드리프트 축에 늘 차이로 뜨고 ② 다음 통째 교체 때 지워진다.
- **테스트 제외 init script 가 하위 패키지까지 뺐다.** 루트 패키지 직속 테스트 3개를 빼려고 `exclude '<패키지 경로>/*'` 를 썼는데, Gradle 은 제외 패턴을 디렉토리에도 맞춘다 — `*` 가 하위 패키지 디렉토리에 맞아 그 아래 테스트 전부가 빠졌다. 결과 파일이 72개 대신 7개였고, 정적 확인은 「빼려던 것이 빠졌나」만 봐서 통과했다. 사용자 실행에서야 드러났다. 직속 클래스만 빼려면 `<패키지 경로>/*.class` 나 클래스 이름으로 쓴다. 테스트 필터(`excludeTestsMatching`·`--tests`)의 `*` 는 점을 넘어 하위 패키지까지 맞는다 — 같은 함정이다. 제외 규칙을 만들면 `install.mjs test-select` 로 빠지는 목록을 펼치고, 실행 뒤에는 **돌아야 할 것이 돌았는지**를 결과 파일 수·클래스 목록으로 본다(CHECKS.md §8).
- 포매터가 저장소 전체를 재포맷하면 `.harness/` 사본이 원본과 바이트가 어긋난다 → 제외 목록에 넣는 것까지가 복사다.
- 원본 SHA 를 안 남기면 나중에 「이 설치처는 어느 판인가」를 drift 비교로만 거꾸로 추정하게 된다. 보고·커밋 메시지에만 적었더니, 커밋하지 않고 끊긴 설치에서는 SHA 가 어느 파일에도 없었다 → config 머리 줄(TEMPLATES.md §6).
- **긴 쓰기 단계를 백그라운드 서브에이전트 하나에 묶었다가 결과가 사라졌다.** 3~6·8단계를 맡긴 서브에이전트가 부모 세션이 끝나며 끊겨, example 복사본만 남고 보고는 오지 않았다. 서브에이전트에는 한 번에 한 단계만 맡기고, 메인이 그 단계의 완료 기준을 확인한 뒤 체크포인트를 쓴다.
- **autocrlf 트리에서 `.harness/` 비교가 전부 거짓 차이로 떴다.** `git archive` 로 푼 판(index 그대로 LF)과 작업본(CRLF)을 그냥 `diff -r` 했다. 줄끝을 무시하거나 index blob 으로 비교한다(CHECKS.md §5).

## §4 config 작성

- **명령 문자열 가드는 가드를 만드는 작업을 막는다.** 규칙 정규식이나 차단될 명령을 셸 인자로 다루면(`--cmd "<명령>"`, `echo`, `grep`) 실행 전 훅이 그 문자열을 보고 막는다. config·판정 스크립트는 Write/Edit 로 쓰고, 판정은 `evaluate` import 로 한다.
- **파이프 판정 정규식이 `2>&1 |` 를 놓쳤다.** `[^|;&]*\|` 꼴은 `2>&1` 의 `&` 에서 매칭이 끊긴다. 리다이렉션(`>&`·`&>`)은 건너뛰도록 쓰고, 케이스 표에 `<명령> 2>&1 | tail` 을 반드시 넣는다.
- **증거 패턴이 「테스트를 뺀 빌드」(`build -x test` 꼴)를 증거로 인정했다.** 같은 조각 안의 테스트 제외 플래그는 불인정으로 둔다. watch 모드로 도는 테스트 명령(`npm run test` 가 watch 인 경우)도 증거가 아니다. 0건이면 통과하는 러너 설정은 빈 그린을 만든다.
- 명령 패턴은 명령이 시작되는 자리에 고정한다(`(^|[;&|(]\s*)` 머리) — 안 하면 커밋 메시지·출력 문구 속 같은 글자가 걸린다.
- **머리를 고정한 패턴이 셸 래퍼와 와일드카드를 통과시켰다.** 시험 설치의 전체 테스트 규칙은 `bash -c "./gradlew test"` 를 놓쳤다 — 머리가 `bash -c "` 뒤를 명령 시작으로 보지 않았고, 끝 조건이 `test"` 의 따옴표를 경계로 보지 않았다. `--tests 'com.<패키지>.*'` 도 「`--tests` 로 좁힌 실행」 예외를 타고 통과했는데, 그 `*` 가 공유 DB 테스트까지 덮었다. 같은 케이스 표를 그 레포의 정답본 규칙에 대 보니 그쪽도 래퍼 변형 49건이 통과했다 — 맨 명령만 케이스로 두면 어느 판이든 이 구멍이 보이지 않는다. 머리에 래퍼(`bash|sh|cmd|powershell|pwsh` + 옵션 + 따옴표)를, 끝 조건에 따옴표를 넣고, 좁힌 실행 예외에는 `*` 없음 조건을 단다. 케이스 표가 래퍼·와일드카드를 덮게 한다(CHECKS.md §4).
- **kit 이 읽는 칸을 주석 없이 `null` 로 두면 그 자산이 말없이 꺼진다.** `docs.archiveDir: null` 은 「해당 없음」으로 읽혀 archive-cycle 이 레포 문서 이동을 건너뛰었고, 설치 보고에도 꺼진다는 말이 없었다. null 칸마다 주석에 꺼지는 자산을 적고 `install.mjs slots` 로 대조한다(DECISIONS.md D8).
- **게이트 `docs.archive` 에 이름 앞머리를 넣으면 살아 있는 문서가 검사에서 빠진다.** `docs/task/goal-`·`docs/phase` 를 넣은 설치처에서 아직 진행 중인 문서 9개가 검사 밖으로 나갔다. 아카이브 폴더 하나나 파일 경로만 넣는다.
- 문서의 자리표시자 줄(`--tests <클래스>` 처럼 `<…>` 가 든 줄)은 「좁힌 실행」 예외에 안 맞아 차단될 수 있다. 의도한 결과인지 케이스 표에 적어 둔다.
- 옛 설치처 config 를 복사하면 `metrics.definitionChanges` 같은 새 슬롯이 없다 → 최신 example 에서 시작한다.
- 모노레포에서 kit `project.commands.*` 에 `cd <하위> &&` 를 붙이면 kit 이 한 번 더 cd 해 경로가 틀린다.

## §5 settings.json 반영

- **example 그대로인 config 위에 훅을 걸면 가드가 조용히 통과한다.** `--status` 는 「규칙 없음」이고 실행 전 훅은 아무것도 막지 않는데, 훅이 걸려 있어 설치된 것처럼 보인다 → 4단계 완료 기준을 통과한 뒤에만 이 단계를 연다.
- **git 이 충돌 없이 자동 병합한 settings.json 이 틀렸다.** 양쪽이 이벤트 키를 따로 추가해, 병합본 한 객체에 같은 이벤트 키가 두 번 생겼다. `JSON.parse` 는 뒤쪽만 남기므로 하네스 훅이 조용히 사라졌고, 다른 도구의 Stop 항목은 엉뚱한 이벤트 아래로 옮겨졌다. 훅이 든 settings.json 을 병합한 뒤에는 **이벤트별 항목을 양쪽 부모와 기계 대조**한다(CHECKS.md §1 의 합집합 대조). 병합 커밋 중에는 `git commit -- <경로>` 를 쓸 수 없다 — 스테이징 집합을 diff 로 확인한 뒤 커밋한다.
- **`claude plugin install --scope project` 가 settings.json 을 통째로 다시 썼다** — 최상위 키·훅 필드 순서를 바꾸고, 다른 도구의 배열 값을 빈 배열로 지웠다. 정작 마켓플레이스 선언과 다른 플러그인의 false 키는 넣지 않았다. 편집 뒤 스냅숏(`settings-snap after-edit`) → 실행 → `after-cli` 대조·복원이 한 묶음이다. 「편집 전 백업」으로 되덮으면 방금 넣은 훅·키가 사라지므로 기준은 편집 뒤 판이다. 팀원 첫 설치에도 같은 일이 생기므로 CLAUDE.md 에 「실행 직후 `git restore .claude/settings.json`」을 적는다.
- **CRLF 체크아웃의 settings.json 이 설치 뒤 LF 가 됐다.** `core.autocrlf=true` 트리였고, 5단계에서 훅·키를 넣을 때 Edit 대신 Write 로 파일 전체를 다시 썼다 — Write 는 넘긴 문자열(LF)을 그대로 쓴다. 이 설치에서는 CLI 를 돌리지 않았으므로(설치 기록이 이미 있어 건너뜀) 원인은 그 Write 하나였다. git diff 는 autocrlf 로 줄끝을 숨겨 깨끗해 보였고, 나중 걷어내기의 백업에도 LF 판이 남았다. Edit 만 쓰고, 편집 뒤 `install.mjs settings-eol` 로 편집 전 스냅숏과 줄끝·BOM 을 맞춘다. CLI 도 LF 로 다시 쓰므로 `after-cli` 가 같은 일을 한다.
- **다른 도구의 SessionStart 훅이 새 트리에서 settings.json 을 재배치**해, worktree 를 만들 때마다 settings.json 이 M 으로 떴다. 커밋 전에 그 diff 가 내 것인지 가린다.
- 같은 이벤트에 걸린 훅은 병렬로 돈다 — 배열 순서는 실행 순서가 아니다. 턴은 가장 느린 훅을 기다린다.
- 훅 `timeout` 단위는 **초**다. 다른 도구가 밀리초로 보이는 값(8000 등)을 넣어 둔 것을 봤다 — 고치지 말고 보고한다.
- Stop 훅(`turn-end`)의 timeout 은 작업 트리 스캔 제한(`scanTimeoutMs`, 기본 5초)보다 길어야 한다.
- 실행 후 훅만 걸고 `PostToolUseFailure` 를 빠뜨리면 실패한 증거 실행이 「실행 없음」으로 떨어진다. matcher 는 Bash·PowerShell **둘 다** — 하나만 걸면 다른 셸 경로가 무방비인데 검증은 걸린 쪽에서만 하게 돼 사각이 그린으로 보인다.
- setup 스크립트가 배달용 settings 사본을 강제로 덮어쓰는 구조면, 실설정에만 훅을 걸면 다음 setup 때 훅이 사라진다 → 사본도 같이 고치고 diff 로 같음을 본다.
- **local scope 플러그인은 worktree 마다 다시 설정해야 했다.** project scope 로 바꾸니 같은 PC 의 새 worktree 는 재설치 없이 로드됐다. local 에서 project 로 옮길 때는 local 을 먼저 `uninstall --scope local --keep-data` 한다(project 가 켠 것을 uninstall 하면 local 에 false 가 기록된다).
- `claude plugin list` 는 PC 전체의 설치 기록을 나열하고 enabled 를 현재 cwd 설정으로 계산한다. 실제 로드는 새 세션의 `/plugin` 이나 디버그 로그(「Loaded N skills … from plugin」)로 본다.

## §6 정적 확인

- 프로토콜 계층(훅 입력 JSON 을 stdin 으로 넣어 보기)은 대상 트리의 `.harness/log.jsonl` 에 이벤트를 남긴다. 하려면 scratchpad 사본 루트에서 `HARNESS_ROOT=<사본>` 으로 돌린다. `test-first.mjs --audit` 도 로그에 audit 이벤트를 쓴다.
- `.harness/*.test.mjs` 는 실행 대신 원본과의 `diff -r` 로 같음을 확인한다.
- 합성 페이로드로 `turn-end` 를 돌리면 「턴의 시작을 알 수 없어 판정 안 함」이 나온다 — 합성이라 그런 것이지 결함이 아니다.

## §7 발동 확인

- `--status` 「활성」은 **설정**만 본다. 훅이 실제로 불리는지는 대화형 세션의 도구 호출로만 확인된다. 헤드리스(`-p`)는 훅이 안 불리고, `!` 직접 실행은 도구 호출이 아니다 — 둘 다 거짓 음성.
- 폴더 신뢰를 승인하기 전에는 프로젝트 settings 의 훅이 로드조차 안 된다.
- 프로브는 실규칙이 아니라 전용 토큰으로 한다 — 기존 가드가 같은 패턴을 덮으면 누가 막았는지 특정할 수 없다. 판정 메시지의 서명(「차단됨 — 검증 전용 프로브…」)으로 주체를 확인한다.
- 비밀번호를 `!` 로 입력하면 대화 기록에 평문으로 남는다.

## §8 레포 지식 초안

- 새 deny 는 레포 문서에 적힌 옛 명령(맨 전체 테스트, `| tail` 판정)을 막는다. 고치지 않으면 서술 문서가 차단될 명령을 권하는 모순이 남고, 레포 플러그인 사본이 있으면 정본·사본 둘 다 고쳐야 한다(바이트 동일 확인).
- 과거 실행 기록 문서(작업 로그·QA 기록)의 옛 명령은 시점 박제라 고치지 않는다.
- **레포 플러그인의 파일을 고치고 판을 올리지 않았다.** 걸리는 줄을 레포 안 프로젝트 전용 플러그인(명시 version 이 있는 것)에서도 고쳤는데, 시험 설치본은 version 을 그대로 두었다. 같은 레포의 정답본은 같은 고침에서 patch 를 올렸다 — 그 플러그인은 이후 고칠 때마다 0.1.1 → 0.1.2 → 0.2.0 으로 올랐다. 명시 version 플러그인은 판이 바뀌어야 설치본이 갱신되므로, 고친 커밋에서 올린다(SKILL.md 8단계). version 이 없는 플러그인(harness-kit 처럼 커밋 SHA 로 판을 가르는 것)에는 version 을 새로 넣지 않는다.
- **표시 없이 넣은 절과 고친 줄은 나중에 가려낼 수 없었다.** 걷어내기 시험에서 「개발 하네스」 절은 제목으로 찾았지만, 커맨드·에이전트 문서 곳곳의 고친 명령 줄은 설치가 바꾼 것이라는 근거가 HEAD 와의 diff 뿐이었다 — 그것으로 되돌리면 파일 단위 되돌리기가 된다. 절은 시작·끝 표시로 감싸고, 고친 줄은 바꾸기 전·뒤 원문을 체크포인트 `edits` 에 적는다.

## §9 영수증 · 커밋

- **영수증의 sha256 은 줄끝을 LF 로 맞춘 내용으로 계산한다.** autocrlf 트리는 같은 커밋도 PC 마다 CRLF·LF 가 달라, 바이트 해시면 다른 PC 에서 걷어 낼 때 모든 파일이 「설치 뒤 손댐」으로 뜬다. 스크립트가 맞춰 계산하므로 해시를 손으로 적지 않는다.
- **영수증을 쓴 뒤 설치 파일을 고치면 영수증이 낡는다.** 9단계 안에서 config·블록을 더 고쳤으면 영수증을 다시 쓴다.
- **`git add` + `git commit` 이 다른 세션의 스테이징을 삼켰다.** 경로 지정 커밋(`git commit -- <경로>`)만 쓰고, 미추적 신규 파일은 `git add -N` 을 먼저 한다.
- 브랜치·toplevel 조건은 커밋과 **같은 명령**에 건다. 앞 명령에서 확인하고 뒤 명령에서 커밋하면 그 사이 브랜치가 바뀔 수 있다.
- 레포 규칙이 trailer 를 금지하는데 도구 기본값이 trailer 를 붙이는 경우가 있다 — 메시지 파일을 직접 써서 넘긴다.
- autocrlf 레포에서 「LF will be replaced by CRLF」 경고는 정규화 안내일 뿐이다. diff 줄 수로 확인한다.
