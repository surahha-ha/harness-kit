# 화면 명세

이 명세는 화면의 구성·문구·인터랙션을 정한다. 값(색·간격·글꼴)은 적지 않는다. 그 프로젝트의 토큰 파일을 쓴다.
화면을 만들기 전에 레포 UI/UX 문서(`docs.uiUxRules`)를 연다. `ui-ux-guide` 스킬이 있으면 함께 쓴다. 레포 문서가 이 명세보다 우선한다.
문구의 `{우리}`·`{상대}`·`{테넌트}`·`{전송}` 은 D12 의 표시 이름과 D1 의 전송 이름으로 바꾼다. 문구 원문은 상수 파일 한 곳에 둔다.

## 1. 골격

```
┌ 머리 띠 ─────────────────────────────────────────────────────────────────┐
│ [제목][화면 링크*][연결 상태] [지우기][요청][응답][응답 대기][평균 소요][실패율][건수][새 메시지] │
├ 툴바 ────────────────────────────────────────────────────────────────────┤
│ 1줄 [스트림 토글][검색][방향]                       [보기][글자 크기][테마] │
│ 2줄 [결과 칩 ×7]                                                          │
│ 3줄 [참여자 ▾][action 칩][필터 초기화]                           [요약 접기] │
├──────────────────────────────────────────┬───────────────────────────────┤
│ 목록(행·카드·패널)                          │ 상세(고르면 열림)                │
└──────────────────────────────────────────┴───────────────────────────────┘
```

`*` = 현황판(§14)을 만들 때만 있다. 없으면 그 자리를 비우지 않고 다음 요소가 붙는다.

- 앱 셸(공통 머리·푸터) 없이 전체 화면으로 그린다. 오래 띄워 두는 작업 화면이다.
- 줄 순서는 고정이다. 폭이 모자라면 줄이 다음 줄로 넘어가되 순서는 그대로다.
- 구역은 구분선이 아니라 컨트롤 모양으로 가른다. 조건 = 칩·분절 버튼, 표시 설정 = 아이콘 분절 버튼.

## 2. 머리 띠

| 요소 | 내용 |
| - | - |
| 제목 | `{전송} 메시지 모니터` 또는 `메시지 모니터`(전송이 둘 이상일 때) |
| 화면 링크 | 현황판(§14)을 둘 때만. 제목 바로 오른쪽에 `현황판`. 현황판에는 같은 자리에 `메시지 모니터`. 아이콘 + 라벨 |
| 연결 상태 | 알약 하나. 라벨 + 아이콘 + 보조 정보. 상태별은 §7 |
| 지우기 | 아이콘 버튼 `메시지 전체 지우기`. 지표 바로 왼쪽. 되돌릴 수 없다 |
| 지표 5 | `요청` · `응답` · `응답 대기` · `평균 소요` · `실패율`. 정의는 RULES.md §8. 낼 수 없으면 `—` |
| 건수 | 조건 없음 `총 N건` · 조건 있음 `표시 N건 / 총 N건`. 옆에 `최대 N ▾`(보관 상한 선택). 상한에 닿으면 `최근 N건만 보관` |
| 새 메시지 | 멈춘 동안 `새 메시지 N건 ▲`. 누르면 맨 위로 가고 실시간을 잇는다 |

- 응답 대기가 0 보다 크면 주의색 + `◷`. 실패율이 0 보다 크면 실패색 + `✕`. 평균 소요는 소요 단계 색이다.
  - 행의 `대기` 결과 배지는 중립 톤이다(RULES.md §4). 지표 카드 `응답 대기` 만 주의색이다. 배지는 요청 하나가 기다리는 정상 상태이고, 카드는 쌓인 대기 수를 알리는 경고다. 둘을 같은 톤으로 맞추지 않는다.
  - 실패율은 처리 실패·송신 문제·시간 초과를 합친 값 하나다(RULES.md §8). 원인별 두 칸은 패널 머리와 현황판에서 나눈다.
- 의미색 아이콘은 응답 대기·실패율만 쓴다. 요청·응답·평균 소요는 중립 아이콘이다.

## 3. 툴바

| 요소 | 내용 |
| - | - |
| 스트림 토글 | 평소 `실시간`(누르면 `일시정지`) · 멈춤 `일시정지됨`(누르면 `재개`). hover·focus 때 누르면 일어날 일을 보인다. 네 라벨을 한 칸에 겹쳐 폭이 그대로다 |
| 검색 | placeholder `채널·action·상관 키·참여자 ID 검색`. placeholder 전체가 보이는 폭 밑으로 줄지 않는다 |
| 방향 | `방향`: `전체` · `{상대}→{우리}` · `{우리}→{상대}` |
| 보기 | `행` · `카드` · `패널`. 기본은 카드. 마지막 선택을 기억한다 |
| 글자 크기 | 선택지 3개(예: 12·14·16). 목록·상세 본문만 바뀐다. 머리 블록은 고정 |
| 테마 | `밝은 테마` · `어두운 테마`. §9 |
| 결과 | `결과`: `전체` + 결과 6종 칩. 칩마다 패싯 건수 |
| 참여자 | 닫힌 버튼: 고른 것 없음 `전체 (N개)` · 하나 그 칩 라벨(칩 색) · 둘 이상 `N개 선택`. 펼치면 §6 |
| action | 건수 많은 순 상위 N개(D11 「action 칩 표시 개수」), 나머지 `+N개` / `접기`. action 없음은 `action 미상` |
| 필터 초기화 | 조건이 기본값이 아닐 때만 보인다. 다섯 조건을 모두 푼다 |
| 요약 접기 | `요약 접기` · `요약 펼치기`. 접으면 2·3줄을 숨기고 1줄 끝에 `적용 중인 조건 N개` |

- 그룹 라벨 옆 ⓘ 는 설명 popover 를 연다(`방향 설명` · `결과 설명` · `참여자 설명` · `action 설명`).
- 칩 옆 숫자는 "검색어와, 그 그룹을 뺀 다른 조건을 모두 건 건수"다(RULES.md §9). 설명 popover 에 이 뜻을 적는다.
- 전송이 거절 코드를 주지 않으면(D1, `REJECTED` 가 생기지 않음) 결과 칩에서 `송신 거절` 을 숨기고 §8 의 그 행도 뺀다. 늘 0 인 칩은 「거절은 없었다」로 읽힌다. 표시 규칙이다. 판정 모델은 결과 6종 그대로다(RULES.md §4). 「모두 고르면 전체로 접기」의 기준은 보이는 칩이다(RULES.md §9).

## 4. 보기 3종

| 보기 | 구성 |
| - | - |
| 행 | 표. 열 = 시각 · 방향 · 보낸 쪽 → 받는 쪽 · 종류 · action · 상관 키(앞 8자) · 결과 · 채널 · payload. 상세가 열리면 채널·payload 열을 접는다 |
| 카드 | 메시지 1건 = 카드 1장. payload 미리보기를 둔다 |
| 패널 | 상대 ID 마다 칸 하나(RULES.md §11). 칸 순서 = 최근 메시지 순. 칸 한 줄 = 요청·응답 한 쌍. 최신이 위. D4 가 패널을 뺐으면 없다 |

- 종류 라벨: `요청` · `응답` · `이벤트`(`EVENT`, D2(b)일 때만).
- 맨 위가 가장 최근 메시지다. 새 행은 잠깐 강조한다(`NEW_ROW_MS`).
- 행·카드는 보이는 항목만 그린다(가상 스크롤). 내려 본 동안 목록이 바뀌어도 보던 항목은 제자리에 둔다.
- 패널 머리: 참여자 칩 · `최근 메시지` 시각 · `요청`·`응답` 건수 · `✕ 처리 실패`·`↯ 송신 문제` 건수(RULES.md §8-1). 실패 두 칸은 0 이 아니면 그 결과의 톤이다. 0 이어도 자리를 숨긴 채 차지한다.
- 칸은 grid 로 채우고 화면 폭이 칸 수를 정한다. 칸이 많으면 패널 영역이 세로로 스크롤된다. 칸을 숨기거나 「더보기」로 접지 않는다.
- 패널 내용 방식 `패널 내용`: `전체`(기본) · `활동 중`. 선택은 패널 영역 위 얇은 바에 둔다. 툴바 폭이 보기 전환에 흔들리지 않게 한다.
  - 전체: 칸마다 고정 높이, 칸 안 스크롤. 칸 안을 맨 위에서 내리면 목록 멈춤이다. `쉼` 표시는 없다.
  - 활동 중: 칸마다 최근 1쌍만. 쉬는 칸도 빼지 않는다. 위 막대를 중립색, 글자를 흐린 색으로 바꾸고 머리에 `쉼` 을 적는다. 색만으로 알리지 않는다.
  - 활동 중 설명: `패널마다 최근 1쌍만 보입니다. {N}초 동안 메시지가 없는 패널은 흐리게 보입니다. 응답을 기다리는 동안은 흐려지지 않습니다.`

## 5. 상세

- 머리 2줄: [시각 라벨][시각] / [방향][종류][action][결과] 칩. 모든 탭이 함께 쓴다.
- 탭: `Payload` · `메타` · `요청·응답`.
  - Payload: 들여쓴 JSON. 복사 버튼.
  - 메타: 필드 표. 송신 실패 사유(`error`)는 여기 보인다.
  - 요청·응답: 위에 [소요][`응답으로 이동` / `요청으로 이동`], 아래 2칸 비교표. 요청 칸이 늘 왼쪽이다. 고른 쪽 칸에 `(선택됨)`.
- 짝이 없을 때 상대 칸 안내(RULES.md §2·§3)

| 상황 | 문구 |
| - | - |
| 응답의 요청이 처음부터 없음 | `이 응답의 요청이 목록에 없습니다. 이 화면을 연 뒤에 오간 메시지만 보입니다.` |
| 요청이 상한 때문에 밀려남 | `요청 메시지는 최대 보관 건수를 넘어 목록에서 밀려났습니다.` |
| 먼저 온 응답이 상한 때문에 밀려남(요청은 남음) | `응답 메시지는 최대 보관 건수를 넘어 목록에서 밀려났습니다.` |
| 응답 대기 | `아직 응답이 오지 않았습니다. 응답이 오면 여기에 나란히 보입니다.` |
| 키 없음 | `상관 키가 없는 메시지라 요청·응답을 찾을 수 없습니다.` |
| 요청·응답이 아닌 메시지(`EVENT`) | `요청·응답 메시지가 아니라 짝을 찾지 않습니다.` |

- 필터로 빠진 메시지를 연 채면 위쪽에 `현재 검색 조건에 없는 메시지입니다.`(role="status").
- footer: `※ {우리}→{상대} 메시지의 시각은 송신 결과가 확정된 시각입니다. 소요 시간은 요청과 응답 시각의 차이입니다.` / `※ {우리}가 요청한 경우 소요에는 네트워크 왕복과 {상대} 처리 시간이, {상대}가 요청한 경우 {우리} 처리 시간이 들어 있습니다.`
- 복사: 성공 `복사했습니다.` · 실패 `복사하지 못했습니다. 브라우저가 클립보드 접근을 막았을 수 있으니 내용을 직접 선택해 복사해 주세요.`

## 6. popover

- **한 번에 하나만 열린다.** 하나를 열면 앞의 것을 포커스 이동 없이 닫는다.
- hover 로 열지 않는다. 눌러서 연다. Esc 와 바깥 누르기로 닫는다. 닫으면 포커스를 연 버튼으로 돌린다.
- 버튼 아래에 붙이고 화면 가장자리 여백 안으로 밀어 넣는다.
- 참여자 popover(RULES.md §9-1): 위에서부터 검색칸 · 일괄 버튼 줄 · `전체 (N개)` 줄 · 후보 체크박스 목록.
  - 검색칸: placeholder `참여자 ID·칩 라벨 검색`. ID 원문과 칩 라벨에서 부분 일치로 찾는다.
  - 일괄 버튼 줄: `전체 선택` · `선택 해제` + 적용 범위 `목록 N개에 적용`(검색 중이면 `검색 결과 N개에 적용`).
  - 전체 줄: 보조 문구 `새로 나타나는 참여자 포함`. 빈 선택이면 체크, 일부 선택이면 indeterminate 다. 누르면 조건을 푼다.
  - 후보 목록은 상한이 없다. 고정 높이 안에서 보이는 줄만 그린다(가상 스크롤). 정렬은 열 때 한 번 정한다. 연 동안 체크를 바꿔도 줄이 뛰지 않는다.
  - 후보 줄 = 체크박스 + 칩(라벨·역할색) + 건수. ↑/↓ 로 줄을 옮긴다.
  - 찾는 것이 없으면 `찾는 참여자가 없습니다. 검색어를 바꿔 주세요.`
  - 목록의 칩을 누르면 `이 참여자만 보기`.
- 보관 상한 popover: 선택지 목록. 줄이면 오래된 것부터 바로 잘린다.

## 7. 연결 상태 · 빈 상태

| 상태 | 라벨 | 아이콘 | 보조 문구 |
| - | - | - | - |
| connecting | `연결 시도 중` | ↻ | — |
| open | `연결됨` | ✓ | `{HH:mm:ss}부터` · `{테넌트} {id}` |
| reconnecting | `재연결 중` | ↻ | `서버와 연결이 끊겨 다시 연결하고 있습니다. 끊긴 동안 오간 메시지는 목록에 나타나지 않습니다.` |
| 404 | `사용할 수 없음` | ✕ | `이 환경에서는 메시지 모니터를 쓸 수 없습니다. 기능이 켜진 개발·검증 환경에서 열어 주세요.` |
| 401(갱신 실패) | `사용할 수 없음` | ✕ | `로그인이 만료되어 메시지를 받을 수 없습니다. 다시 로그인한 뒤 이 화면을 새로 열어 주세요.` |
| 403 | `사용할 수 없음` | ✕ | 서버 문구 우선(CONTRACT.md §7). 없으면 `로그인한 계정의 {테넌트}를 확인할 수 없어 메시지를 받을 수 없습니다.` |
| 503 | `재연결 중` | ↻ | 서버 문구 우선. 없으면 `{테넌트} 정보를 조회하지 못해 아직 연결하지 못했습니다. 잠시 뒤 자동으로 다시 연결합니다.` |

빈 상태는 목록 정중앙에 [아이콘]→[문구]다. 우선순위는 RULES.md §12.

| 경우 | 문구 | 버튼 |
| - | - | - |
| 연결 문제 | 위 표의 보조 문구 | — |
| 받은 것 없음 | `아직 받은 메시지가 없습니다. {상대}와 {우리}가 메시지를 주고받으면 여기에 바로 나타납니다.` | — |
| 걸러져 비었음 | 조건에 맞는 메시지가 없다는 안내 | `필터 초기화` |

- 문구는 줄 배열로 둔다. 한 원소가 한 줄이다. 줄바꿈을 문자열·CSS 로 넣지 않는다.
- D5 가 「단일 범위」면 `{테넌트}` 가 든 문구와 보조 정보를 뺀다.

## 8. 결과·방향 설명 문구

| 키 | 설명 |
| - | - |
| 처리 성공 | `응답이 왔고, 요청을 받은 쪽이 처리에 성공했습니다.` |
| 처리 실패 | `응답이 왔고, 요청을 받은 쪽이 처리하다 실패했습니다.` |
| 송신 거절 | `{우리}→{상대} 메시지를 전송 계층이 받고 거절했습니다(권한·대상 문제 등).` |
| 송신 실패 | `{우리}→{상대} 메시지를 보내지 못했거나(연결 끊김 등) 보낸 뒤 송신 확인을 받지 못했습니다. 확인만 못 받은 경우는 실제로 도착했을 수 있습니다.` |
| 대기 | `요청에 아직 응답이 오지 않았습니다({N}초 이내).` |
| 시간 초과 | `이 화면이 요청을 받고 {N}초 동안 응답이 오지 않았습니다. 처리 결과는 알 수 없습니다.` |
| 결과 덧붙임 | `송신 거절·송신 실패는 {우리}가 보낸 메시지에만 생깁니다.` · `시간 초과 뒤에 응답이 오면 그 응답의 결과로 바뀝니다.` |
| 원인 구분 | `처리 실패는 상대가 요청을 처리하다 실패한 것이고, 송신 거절·송신 실패(합쳐서 송신 문제)는 전송 단계의 문제입니다. 그래서 색과 아이콘이 다릅니다.` |
| `{상대}→{우리}` | `{우리}가 받은 메시지입니다. {상대}가 보낸 요청과 {우리} 요청에 대한 {상대} 응답이 해당합니다. 시각은 {우리} 수신 시각입니다.` |
| `{우리}→{상대}` | `{우리}가 보낸 메시지입니다. {우리}가 보낸 요청과 {상대} 요청에 대한 {우리} 응답이 해당합니다. 시각은 {우리} 송신 시각(송신 결과가 확정된 시각)입니다.` |
| 방향 공통 | `{상대}가 실제로 보낸 시각은 메시지에 없어 표시할 수 없습니다.` — 보낸 시각이 실리면(T12, CONTRACT.md §3 `sentAt`) `{상대}가 보낸 시각은 메타 탭에 있습니다. 시계가 달라 소요 계산에는 쓰지 않습니다.` 로 바꾼다 |

- 결과의 뜻은 이 표 한 곳에서 칩·설명 popover 가 함께 가져간다.
- 소요 단계 라벨: `◇ 주의 ({경계}초 이상)` · `◆ 지연 ({경계}초 이상)`. 이름과 괄호 사이는 한 칸 띄운다. 단계명은 모두 함수 하나로 만든다. 정상은 표시하지 않는다.
- 「송신 문제」 라벨은 상수 한 곳에 두고, 패널 머리·현황판·결과 설명이 함께 쓴다.

## 9. 테마와 토큰

- 모니터 전용 토큰 집합을 둔다. 앱 테마와 분리한다. 모니터 테마를 바꿔도 앱의 다른 화면은 그대로다.
- 표면은 세 단이다.
  - **틀**(`bg`): 머리 블록, 상세 패널 바탕·탭 줄·footer.
  - **내용**(`surface`): 목록, 상세 제목, Payload JSON, 메타 표, 비교표 칸.
  - **떠 있는 표면**(`overlay`): 모든 popover. 내용보다 한 단 밝다. 어두운 테마도 같은 세 단이고 값만 바뀐다.
- 결과 톤은 5개다: success · danger · **transport** · warning · neutral(RULES.md §4). 소요 단계 2개는 warning·danger 를 쓴다.
  - 톤 → 색(글자·옅은 바탕)은 **표 하나**에 둔다. 칩·패널 머리·현황판 카드·비율 막대가 모두 이 표를 쓴다. 화면마다 색을 다시 적지 않는다.
  - transport 는 danger 와 다른 색상 계열로 고른다. 「처리하다 실패」와 「보내지 못함」을 눈으로 가른다.
  - 아이콘 글리프의 크기가 서로 다르면 톤별 배율을 같은 표 곁에 둔다(기준 구현: `↯` 가 작아 transport 만 키운다).
- 참여자 칩 팔레트는 **역할색 2개**(A 쪽·B 쪽)다(D12). 의미색과 겹치지 않게 고르고, 표면 위 3:1 이상이다. 역할 → 색 번호는 색 상수 한 곳이 정한다. 컴포넌트가 색을 고르지 않는다.
- OS 설정(prefers-color-scheme)을 따를지는 레포 문서가 정한다. 기준 구현은 따르지 않고 밝은 테마로 시작했다.
- 글자 크기는 루트 변수 하나가 정한다. 목록·상세의 치수는 그 값에서 em 으로 나온다.

## 10. 레이아웃 안정성

실시간 화면이라 숫자가 계속 바뀐다. 머리·툴바가 흔들리지 않게 한다.

- 숫자 칸은 상한 길이(글자 수, `ch`)로 폭을 미리 잡는다. 숫자는 tabular-nums 로 그린다. 칸 글자 수는 상수에서 파생한다. 보관 상한 칸은 가장 큰 선택지 길이로 잡는다.
- `최근 N건만 보관` · `새 메시지 N건` · 실패 아이콘(지표 카드·패널 머리)은 자리를 늘 차지한다. 보이지 않을 때는 visibility 로 숨긴다. 새 메시지 수가 표시 상한을 넘으면 `상한+` 로 적는다.
- 머리 첫 줄 높이는 지표 카드 높이에서 파생한 토큰 하나다. 현황판이 있으면 그 머리도 같은 토큰을 최소 높이로 쓴다. 화면을 오갈 때 머리가 튀지 않는다.

## 11. 인터랙션

- **일시정지**는 보이는 목록만 멈춘다. 수신은 계속된다. 목록을 맨 위에서 내려 봐도 멈춘다. 멈춤 사유가 하나라도 풀리면 새 메시지 수를 0 으로 비운다(RULES.md §10).
- 키보드: ↑/↓ 로 이전·다음 메시지를 고른다. 패널 보기는 칸 순서, 칸 안 순서로 잇는다. Esc 로 상세나 popover 를 닫는다. 텍스트 입력 중에는 단축키가 발동하지 않는다.
- 필터로 빠진 메시지를 연 채 ↑/↓ 를 누르면 새 결과 맨 위부터 간다.
- 마지막 선택(보기·테마·글자 크기·보관 상한·요약 접힘·패널 내용)은 브라우저 저장소에 기억한다. 저장값이 선택지 밖이면 기본값으로 시작한다. 저장소를 못 쓰면 기본값으로 동작한다.

## 12. 접근성

- 아이콘만 있는 버튼에 접근 가능한 이름을 단다(예: `메시지 전체 지우기`, `결과 설명`).
- 분절 버튼·테마 버튼은 `aria-pressed` 로 선택을 알린다.
- 결과·소요 단계는 색만으로 구분하지 않는다. 아이콘과 라벨을 함께 둔다.
- 연결 상태 변화와 필터 안내는 role="status" 로 알린다.

## 13. 테스트 ID

캡처(GUIDE.md §4)와 e2e 가 찾는 요소다. 3단계에서 화면을 만들 때 함께 단다. 표시 문구·클래스 이름이 바뀌어도 캡처가 깨지지 않는다.

| ID | 요소 |
| - | - |
| `monitor-header` | 머리 블록 전체(머리 띠 + 툴바). 캡처 `toolbar` 의 범위 |
| `monitor-count` | 건수 칸(`총 N건`). 캡처가 모의 피드가 찼는지 이것으로 기다린다 |
| `monitor-row` | 목록 항목 하나(행·카드 보기) |
| `party-filter-toggle` | 참여자 popover 를 여는 버튼 |
| `buffer-limit-toggle` | 보관 상한 popover 를 여는 버튼 |

- `결과 설명` 버튼과 결과 칩은 접근 가능한 이름(§12)으로 찾는다. 테스트 ID 를 달지 않는다.

## 14. 현황판(선택)

**선택 화면이다.** 모니터는 "지금 목록에 있는 메시지"를 보고, 현황판은 "화면을 연 뒤 받은 메시지 전부"를 누적해 본다. 오래 띄워 두고 이상이 생겼는지 보는 화면이다. 이력 저장은 없다. 새로고침하면 0 부터 다시 센다.

- 진입 가드·레이아웃(앱 셸 없음)은 모니터와 같다. 수신부(스트림 연결·재연결·401 판정)는 모니터와 **같은 모듈**을 쓴다. 테마는 같은 저장 키를 쓴다.
- 판정은 모니터 규칙을 그대로 부른다(RULES.md §16). 결과 라벨·아이콘·톤, 참여자 칩 라벨·색, action 라벨, 지표 이름·의미색이 모니터와 같다.

```
┌ 머리 ───────────────────────────────────────────────────────────┐
│ [제목][메시지 모니터 링크][연결 상태]                       [테마] │
│ {HH:mm:ss}부터 집계 · 범위 안내                                  │
│ (놓친 요청 안내 — 있을 때만)                                     │
├ 본문(세로 스크롤) ──────────────────────────────────────────────┤
│ 누적 지표 1줄 규모 [참여자][요청][응답]                          │
│           2줄 상태 [응답 대기][평균 소요][실패율]                 │
│ [분당 요청·응답 차트]            │ [분당 소요 차트]               │
│ [결과 분포 카드 6]               │ [방향별 현황 카드 2]           │
│ [참여자별 카드 격자]             │ [action 별 카드 격자]          │
└─────────────────────────────────────────────────────────────────┘
```

| 구역 | 내용 |
| - | - |
| 머리 | 제목 `{전송} 현황판` · 화면 링크 `메시지 모니터`(모니터 머리와 같은 자리) · 연결 상태(§7 과 같은 알약) · 테마. 아래 줄에 `{HH:mm:ss}부터 집계` + 범위 안내 |
| 범위 안내 | `이 화면을 연 뒤 받은 메시지를 모두 셉니다. 새로고침하면 0부터 다시 셉니다. 메시지 모니터의 지표는 지금 목록에 보이는 메시지만 세므로 숫자가 다를 수 있습니다.` |
| 요청·응답이 아닌 메시지 | D2(b)일 때만. 세지 않은 `EVENT` 건수 한 줄(RULES.md §16) |
| 놓친 요청 | 기억 상한(D11)을 넘어 결과를 잃은 요청이 있을 때만. role="status". `응답을 기다리던 요청 N건은 기억할 수 있는 요청 수(N건)를 넘어 결과에서 뺐습니다.` |
| 규모 줄 | 카드 셋: 참여자 · 요청 · 응답. 카드 안에 A 쪽·B 쪽 숫자를 같은 크기로 나란히 두고 역할색 견본을 붙인다. 합계는 라벨 옆에 작게(`합계 N`). 보낸 측 기준이다 |
| 상태 줄 | 카드 셋: 응답 대기 · 평균 소요 · 실패율. 이름·값·의미색·아이콘은 모니터 머리 지표 카드와 같은 함수다 |
| 추이 차트 | `분당 요청·응답`(막대, 칸 안 왼쪽 요청·오른쪽 응답) · `분당 소요`(선, 실선 평균·점선 최대). 최근 N분(D11) |
| 결과 분포 | 결과 6종 카드. 카드 = 아이콘+라벨 · 건수 · 비율 · 얇은 비율 막대. 왼쪽 띠는 결과 톤. 넓으면 3×2, 좁으면 2×3 |
| 방향별 현황 | 방향 카드 둘. 카드 = 그 방향으로 보낸 요청 + 그 요청에 온 응답. 숫자 = 요청 · 응답 · 처리 실패 · 송신 문제 · 실패율 · 평균 소요 + 결과 비율 누적 막대. 카드 아래에 뺀 짝 없는 응답 한 줄 |
| 참여자별 · action 별 | 항목마다 카드 하나: 이름 · 건수 · 처리 실패 · 송신 문제 · 평균 소요(단계 표시). 위에 검색칸(`참여자 검색` · `action 검색`)과 정렬 버튼(건수 · 실패 · 평균 소요) |

- 지표 두 줄은 칸 폭이 같아 세로로 나란하다. 숫자 앞 아이콘 칸은 하나다. 단계 문구 줄은 늘 자리를 차지해 카드 높이가 같다.
- 처리 실패·송신 문제는 0 이 아니면 그 결과 톤과 아이콘(`✕`·`↯`), 0 이면 보통 글자색이다. 실패율은 합계다.
- 짝 없는 응답 줄은 0 이면 글자만 숨기고 자리는 차지한다. `지금까지 짝 없는 응답 N건을 뺐습니다.`
- 결과·방향 제목 옆 ⓘ 는 모니터와 같은 설명 popover 컴포넌트다. 결과: 비율의 뜻(`결과가 둘인 메시지는 양쪽에 셉니다`)과 늦은 응답. 방향: 세는 기준과 링크의 한계(RULES.md §17).
- 항목 카드 격자는 고정 높이 안에서 스크롤한다. 열 수는 칸 폭에 맞춰 자동이다. 항목을 숨기거나 상위 N개로 자르지 않는다.
- 정렬 버튼은 `aria-pressed` 와 방향이 든 aria-label 을 단다. 지금 정렬을 다시 누르면 방향이 뒤집힌다. 고르지 않은 기준에도 "누를 수 있음" 아이콘을 둔다.
- 찾는 항목이 없으면 `찾는 항목이 없습니다. 검색어를 바꿔 주세요.` 아직 없으면 `집계할 메시지가 아직 없습니다.`

**모니터로 가는 링크.** 숫자·카드를 누르면 그 조건 하나를 건 모니터가 열린다(RULES.md §17).

| 누르는 곳 | 여는 조건 |
| - | - |
| 규모 줄 요청·응답의 A·B 숫자 | 그 측이 보낸 방향 |
| 규모 줄 참여자 카드 | 링크가 아니다. 아래 참여자별 칸으로 스크롤하고 그 칸에 포커스를 둔다 |
| 결과 카드 | 그 결과 |
| 방향 카드 이름 | 그 방향 |
| 참여자 · action 카드 | 그 참여자 · 그 action |

- 링크마다 title(방향 링크는 aria-label 도) `{라벨} — 메시지 모니터에서 조건을 걸어 보기` 를 단다. 항목 카드의 aria-label 에는 이름·건수·실패 두 칸·평균 소요를 넣는다.
- 모의 피드로 띄운 경우 두 화면을 오갈 때 모의 쿼리(`seed`·`parties`)를 이어 붙인다. 운영 링크는 이 처리를 거치지 않는다.

**차트.** 차트 라이브러리를 들이지 않는다. SVG 를 직접 그린다(RULES.md §17).

- 차트의 실제 폭을 재어(ResizeObserver) 그 폭을 viewBox 폭으로 쓴다. 축 글자·선 두께가 창 폭과 관계없이 같은 px 이다.
- 대체 텍스트(aria-label)는 요약 한 문장이다(예: `최근 N분 분당 요청·응답 건수입니다. 분당 요청은 최대 N건, 응답은 최대 N건입니다.`). 칸별 값은 화면 낭독기용 표(`{제목} 표`, 첫 열 `시각`)로 둔다. 집계 전 칸은 `집계 전` 이다.
- 그릴 것이 없으면 차트 자리에 `아직 집계한 메시지가 없습니다.` · `소요를 낼 수 있는 요청·응답 쌍이 아직 없습니다.`

**좁은 폭.** 화면 폭이 아니라 **카드 폭**으로 판정한다(container query). 같은 카드가 넓은 칸·좁은 칸 어디에 놓여도 맞게 줄어든다.

- 지표 카드: 폭 경계 밑이면 숫자 크기를 한 단계 낮춘다. 결과 분포: 3열 → 2열.
- 방향 카드: 먼저 여섯 값을 함께 한 단계 낮춘다. 그래도 한 줄에 안 들어가면 두 줄로 놓는다. 평균 소요를 첫 줄 끝에 두어, 둘째 줄에 실패 값끼리 나란하게 한다.
- 항목 카드: 두 줄로 놓을 때 평균 소요를 건수 옆(첫 줄)에 둔다. 처리 실패·송신 문제가 같은 줄에 나란하다.
- 값이 칸 밖으로 나가지 않는다. 경계 폭은 토큰으로 둔다. 컴포넌트에 숫자를 적지 않는다.
