# 마스킹

payload 의 개인정보는 **서버에서 한 번**, 팬아웃·스트림 전에 가린다. 원문은 버스·스트림·브라우저 어디에도 가지 않는다.
브라우저에서 가리지 않는다. 브라우저에 온 순간 이미 나간 것이다.

## 1. 규칙

- **키 이름으로 가린다.** 깊이·위치와 관계없이 트리 전체를 훑는다. 봉투 `data` 안이든 밖이든 같다.
- 전송 메타데이터(`transportMeta`, T10)를 올리면 그 트리도 같은 규칙으로 가린다. 메시지 키·헤더 값에 고객 ID·전화번호가 실리기도 한다.
- **숫자는 원문 글자를 보존한다.** 일반 맵으로 풀면 큰 정수(2^53 초과)가 바뀌고 키 순서도 바뀐다(예: Go 는 숫자 보존 디코딩을 쓴다). 브라우저 `JSON.parse` 에서 잃는 큰 정수는 가이드 「한계」에 적는다.
- 키 이름은 **대소문자를 무시하고** 비교한다(기본). `Phone`·`PHONE` 도 `phone` 이다. 구분하려면 이유를 결정 기록에 적는다.
  - `mobile_no`·`mobileNo` 같은 표기 차이는 비교 규칙으로 풀지 않는다. 대조 표(§4)에서 키로 따로 올린다.
- **마스킹 키의 값은 형태와 관계없이 통째로 가린다.**
  - 숫자·불리언은 글자로 바꿔 그 키의 방식으로 가린다.
  - 객체·배열은 JSON 글자로 바꾼 뒤 그 키의 방식으로 통째로 가린다. 안쪽 키를 따로 훑지 않는다. 형태가 달라도 원문이 새지 않는다.
  - `null` 은 그대로 둔다.
  - 큰 덩어리 키(아래)만 예외다. 요약 객체로 바꾼다.
  - 안쪽 칸마다 다른 방식이 필요하면(예: 주소 객체의 우편번호·상세 주소) 바깥 키를 목록에 넣지 않는다. 안쪽 칸 키를 목록에 올린다(§2).
- **문자열 안의 JSON** — 문자열 값이 `{`·`[` 로 시작하면 JSON 으로 풀어 같은 규칙으로 가린 트리로 바꾼다.
  - 중첩 한도(예: 3)를 둔다. 한도를 넘으면 키 이름과 관계없이 사유 문구로 바꾼다. 더 안쪽은 키가 이스케이프돼 이름으로 찾을 수 없다.
  - 풀지 못했는데 마스킹 키 이름이 문자열 안에 보이면 사유 문구로 바꾼다. 보이지 않으면 원문을 둔다.
  - 사유 문구 예: `개인정보가 들어 있을 수 있는 JSON 문자열을 읽지 못해 내용을 가렸습니다.`
- **payload 전체가 JSON 객체·배열이 아니면** 원문 대신 사유 문구를 보낸다. 가릴 수 없는 것은 내보내지 않는다.
  - 예: `JSON 객체로 읽을 수 없는 메시지입니다({N}자).` · 직렬화 실패 `메시지 내용을 직렬화하지 못했습니다.`
  - `{N}` 은 받은 원시 payload 를 UTF-8 로 읽은 글자 수다. 바이트 수가 아니다.
  - payload 가 JSON 이 아닌 형식(T11: 스키마 기반 바이너리 등)이면 먼저 본 처리와 같은 방법으로 풀어 트리로 만든다. 풀기는 큐 뒤에서 한다. 풀 수 없거나 디코딩 의존(스키마 저장소 등)이 실패하면 사유 문구다(예: `스키마를 찾지 못해 메시지 내용을 풀지 못했습니다.`).
- **큰 덩어리는 요약으로 통째로 바꾼다.** 서명·이미지·첨부 문서 원문 같은 것이다.
  - 예: `{ "readable": true, "fieldCount": 12, "filledCount": 12, "hasImage": true }` — 칸 이름은 그 덩어리의 구조로 정한다
  - 읽지 못하면 `readable: false`, 나머지 null.
  - 요약 규칙은 본 처리가 그 덩어리를 읽는 규칙과 같게 한다(래퍼·이중 인코딩 풀기). 다르게 풀면 요약이 거짓이 된다.

## 2. 키별 가림 방식(예)

| 종류 | 키 예 | 방식 | 예 |
| - | - | - | - |
| 이름 | `name` | 첫·끝 글자만 남기고 가운데는 글자마다 `*`. 2자는 첫 글자 + `*`, 1자는 `*` | 김민수 → 김*수 |
| 전화 | `phone` | 숫자만 남겨 숫자 길이로 형식을 고른다. 아래 표 | 01012345678 → 010-****-5678 |
| 생년월일 | `birthDate` | 글자 수만큼 `*` | 19900101 → ******** |
| 주소 | `address` | 공백으로 나눈 앞 두 어절만 남기고 나머지를 `****` 하나로 바꾼다. 어절이 셋 미만이면 전체를 `****` | 한빛시 새솔구 누리로 12 3층 → 한빛시 새솔구 **** |
| 큰 덩어리 | `document` | 요약 객체로 교체 | §1 |

**전화 — 원래 숫자가 7자 이상이면 길이와 관계없이 최소 4자리를 가린다.** 「앞 3 + 뒤 4」를 모든 길이에 쓰면 7자는 하나도 가리지 못하고, 8~10자는 1~3자리만 가린다.

| 숫자 길이 | 형식(예) | 입력 예 | 결과 | 가린 숫자 |
| - | - | - | - | - |
| 11 이상 | 앞 3 + 뒤 4 | 01012345678 | `010-****-5678` | 4 이상 |
| 10 | 앞 2 + 뒤 4 | 0311234567 | `03*-****-4567` | 4 |
| 9 | 뒤 4 | 021234567 | `***-****-4567` | 5 |
| 8 | 뒤 4 | 15881234 | `****-1234` | 4 |
| 7 | 뒤 3 | 1234567 | `****-*567` | 4 |
| 7 미만 | 전부 | 123456 | `****` | 전부 |

- 표의 형식과 입력은 예다(11자 휴대전화 형식을 쓰는 나라를 예로 들었다). 원칙(7자 이상은 최소 4자리를 가린다)만 지키면 형식은 바꿔도 된다.
- 형식을 바꾸면 앱의 다른 응답도 함께 바뀔 수 있다. PITFALLS.md §2 「마스킹 형식을 바꿨다」를 먼저 읽는다.
- 주소처럼 객체로 오는 값에 칸마다 다른 방식이 필요하면, 바깥 키 대신 칸 키를 목록에 올리고 칸마다 방식을 정한다(§1). 상세 주소 칸은 전체를 가린다.
- 앱에 이미 마스킹 유틸이 있으면 그것을 쓴다. 화면 목록과 모니터가 같은 사람을 다르게 가리면 안 된다.

## 3. 마스킹하지 않는 것 — 명시한다

결정 기록에 "가리지 않는 키"와 이유를 적는다. 적지 않으면 빠뜨린 것인지 정한 것인지 알 수 없다.

- 예: 직원·담당자 이름(고객 정보가 아님), 내부 ID, 참여자 ID, 상관 키, action.
- (a) 가릴 키 목록 방식(D6)이면 **목록 밖의 모든 키는 원문이다.** 이 사실을 가이드 「개인정보 마스킹」 절에 적는다.

## 4. 키 대조 절차 — 상대가 모르는 키로 PII 를 실을 때

가릴 키 목록 방식은 목록에 없는 키를 원문으로 보낸다. 상대가 새 키나 다른 이름으로 PII 를 실으면 그대로 나간다.

1. 상대의 payload 키 목록을 받는다(D6 출처). action 마다 요청·응답 둘 다다. `EVENT` 도 종류마다 받는다. 전송 메타데이터를 올리면 그 키(헤더 이름 등)도 받는다.
2. A 가 보내는 payload 의 키 목록을 코드에서 뽑는다.
3. 두 목록의 모든 키를 표 하나로 만든다. 키마다 「PII 여부」와 「처리(가림 방식 · 가리지 않음 + 이유)」를 채운다.
4. PII 인데 마스킹 키 목록에 없는 키를 0 으로 만든다. 같은 뜻 다른 이름(예: `name`·`fullName`·`userName`)을 놓치지 않는다.
5. 대조 표를 결정 기록에 붙이고, 받은 날짜와 상대 명세 판을 적는다.
6. 실제 샘플이 있으면 마스킹을 돌린 결과를 사람이 한 번 읽는다. 키 목록만으로 못 잡는 것(자유 텍스트 안의 전화번호 등)을 본다.

- 대조를 끝내지 못했으면 「미확보」로 적는다. 그동안은 실고객 데이터가 흐르지 않는 환경에서만 켠다(D7).
- 상대 명세가 바뀌면 대조를 다시 한다. 결정 기록의 날짜로 판정한다.

## 5. 테스트 사례

| 입력 | 기대 |
| - | - |
| `{"data":{"name":"김민수"}}` | `김*수` |
| `{"a":{"b":[{"phone":"010-1234-5678"}]}}` | 깊이와 관계없이 `010-****-5678` |
| `{"phone":"12345"}` | `****` |
| `{"phone":"1234567"}` · `{"phone":"15881234"}` · `{"phone":"021234567"}` · `{"phone":"031-123-4567"}` | `****-*567` · `****-1234` · `***-****-4567` · `03*-****-4567` (가린 숫자 4 이상) |
| `{"Phone":"010-1234-5678"}` | `010-****-5678` (대소문자 무시) |
| `{"address":"한빛시 새솔구 누리로 12"}` | `한빛시 새솔구 ****` |
| `{"address":"새솔구 누리로12"}` | `****` (어절 둘) |
| `{"name":null}` | `null` 그대로 |
| `{"name":12345}` | `{"name":"1***5"}` (글자 `12345` 를 이름 방식으로) |
| `{"phone":{"main":"010-1234-5678"}}` | `{"phone":"010-****-5678"}` (JSON 글자의 숫자 11자를 전화 방식으로. 객체가 문자열로 바뀐다) |
| `{"raw":"{\"name\":\"김민수\"}"}` | 풀어서 가린 트리 |
| 중첩 한도를 넘는 문자열 JSON | 사유 문구 |
| `{"raw":"{name:김민수"}` (깨진 JSON, 키 이름 보임) | 사유 문구 |
| `{"raw":"{not json"}` (깨진 JSON, 키 이름 없음) | 원문 |
| 원시 payload `just text` (따옴표 없는 9글자) | `JSON 객체로 읽을 수 없는 메시지입니다(9자).` |
| 원시 payload `"just text"` (따옴표까지 11글자, JSON 문자열) | `JSON 객체로 읽을 수 없는 메시지입니다(11자).` — JSON 이지만 객체·배열이 아니다 |
| 큰 덩어리 정상 · 읽기 실패 · null | 요약 · `readable:false` · null 그대로 |
| 가리지 않는 키(예: 담당자 이름) | 원문 |
| 대조 표의 PII 키 전부 | 각 방식대로 가려진다 |
