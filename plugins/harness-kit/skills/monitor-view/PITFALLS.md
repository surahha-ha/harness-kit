# 함정 — 단계별

각 단계를 시작할 때 같은 번호 절을 읽는다. 기준 구현을 만들고 리뷰하며 겪었거나 미리 막은 것이다.
전송 고유의 함정은 전송 부록의 T9 에 있다. 함께 읽는다.

## §0 결정

- **시간 초과 값을 화면만 보고 정했다.**
  - 모니터의 응답 제한시간이 A·B 의 실제 응답 제한시간과 다르면 화면이 거짓을 말한다.
  - 기준 구현은 이 값을 「미확인 — BE 확인 대상」으로 남긴 채 출시했다.
  - D11 에 근거(설정 키·명세 절)를 적는다. 없으면 「미확인」으로 두고 가이드 한계에 적는다.
- **상대의 payload 키 목록 없이 마스킹 키를 정했다.**
  - 가릴 키 목록 방식은 목록 밖의 키를 원문으로 보낸다. 상대가 새 키로 PII 를 실으면 그대로 나간다.
  - D6 에서 출처를 정하고, 4단계에서 대조한다(MASKING.md §4).
- **요청·응답이 아닌 메시지를 생각하지 않았다.**
  - BE 는 `kind: null` 로 보냈고 FE 파서는 그것을 조용히 버렸다. 아무도 몰랐다.
  - D2 에서 (a) BE 가 버린다 (b) `EVENT` 로 보인다 중 하나를 정하고 계약에 적는다.
- **스트림 인증 갱신을 정하지 않았다.**
  - EventSource·fetch 스트림은 앱 HTTP 클라이언트의 토큰 갱신 경로 밖에 있다.
  - 401 에 재연결을 멈추면 토큰 만료만으로 모니터가 선다. 오래 띄워 두는 화면이라 반드시 겪는다. D10 에서 정한다.
- **오프라인 버퍼가 있는데 끊긴 송신을 `NOT_SENT` 로 기록했다.**
  - 쌓인 메시지는 재연결 뒤 나간다. 화면은 "안 보냄"이라 말하는데 실제로는 도착한다. D1 세 번째 질문으로 정한다.
- **"검증 환경이니 괜찮다"고 봤다.**
  - 운영 복제 데이터나 실단말이 붙는 환경이면 운영과 같은 개인정보가 흐른다. D7 은 환경 이름이 아니라 「실고객 데이터가 흐르나」로 정한다.
- **보낸 끝점의 ID 가 메시지에 있다고 가정했다.**
  - 전송이 보낸 쪽 ID 를 싣지 않는 경우가 많다. 봉투에도 없으면 자기 송신 판별·패널 묶음이 막힌다. D4 를 먼저 푼다.
- **전송 부록의 답을 확인 없이 옮겼다.**
  - 부록은 그 전송의 일반 답이다. 클라이언트 라이브러리·판·설정에 따라 답이 다르다. 이 프로젝트 코드로 확인하고 근거를 단다.
- **개발 서버가 어디에 붙는지 확인하지 않았다.**
  - 프록시 기본 타깃이 공유 원격 환경이면, 로컬에서 띄운 화면이 원격 스트림을 본다.
  - `risk.devServer` 와 프록시 설정을 확인하고 결정 기록에 적는다.

## §2 BE

- **리스너에서 직렬화·마스킹·발행을 했다.** 콜백은 본 처리와 같은 실행 단위(스레드·경량 스레드·이벤트 루프)에서 온다. 본 처리가 늦어진다. 유한 큐에 넣고 즉시 반환한다. 큐를 비우는 쪽은 런타임 유형이 정한다(SKILL.md 2단계 2).
- **이벤트 루프형에서 큐를 마이크로태스크로 비웠다.** 같은 턴에 다 돌아 큐가 없는 것과 같다. 다음 턴의 매크로태스크로 비운다.
- **큐가 무한이었다.** 큰 payload 가 쌓이면 메모리가 묶인다. 넘침을 건마다 로그로 남기면 로그가 장애가 된다. 모아서 WARN 을 남긴다.
- **이벤트 발행 호출의 실패가 본 처리로 번졌다.**
  - 본 처리 안의 "이벤트 하나 내기" 호출은 어떤 실패(예외·panic·오류 반환)도 밖으로 내지 않는다. 리스너의 실패가 송신 경로로 번지면 안 된다.
  - 경량 스레드형(예: Go)은 실패 모양이 다르다. 찬 채널에 보내면 막힌다 → 막히지 않는 넣기(`select … default`). 닫힌 채널에 보내면 panic → 종료 중에는 넣지 않는다. 큐를 비우는 goroutine 의 panic 은 프로세스를 내린다 → 그 안에서 `recover` 한다.
  - 테스트: 리스너가 실패(예외·panic)하게 하고, 큐를 닫은 뒤 넣어 보고, 본 처리 결과와 프로세스가 그대로인지 본다.
- **자기 송신이 되돌아와 두 번 기록됐다.** 되돌림은 보낸 인스턴스가 아닌 다른 A 인스턴스로 갈 수 있다. "A 의 어느 인스턴스"인지로 가린다(D4). 판정 함수는 하나만 둔다.
- **모든 인스턴스가 받는 채널의 INBOUND 를 모두 팬아웃했다.** 브라우저에 인스턴스 수만큼 겹쳐 보인다. D9 에서 정한다.
- **버스가 테넌트 이벤트의 순서를 지키지 않았다.** 나눔 키(파티션·샤드)가 테넌트가 아니면 같은 테넌트 이벤트가 바뀐 순서로 닿는다. 짝 규칙의 전제가 깨진다(RULES.md §2). D9 「버스 확인 항목」에서 정한다.
- **중복 수신을 결함으로 봤다.** 수신 기록은 중복 제거 전이다(T7). 짝 규칙(RULES.md §2)이 처리한다. 가이드 「한계」에 적는다.
- **모니터 때문에 봉투를 바꾸고 싶어진다.**
  - 예: 상대 응답 봉투에 ID 가 없어 패널이 「ID 없음」으로 모인다.
  - 봉투·채널·직렬화는 상대와의 계약이다. 모니터 때문에 바꾸지 않는다. 화면이 짝 상대 쪽 ID 로 묶는다(D4).
  - 직렬화 고정 테스트로 지킨다. 기대값은 명세(필드 이름·순서·빈 값 생략)에서 다시 쓴다.
- **A→B 요청의 받는 쪽을 송신 때 특정하려 했다.**
  - 받는 끝점이 송신 때 정해지지 않는 채널(모두 받음 · 나눠 받음, T4)이면 `receiverId` 는 null 이다. 화면은 D12 의 사유로 적는다(RULES.md §14).
- **테넌트를 요청 파라미터로 받았다.** 다른 테넌트의 메시지를 열 수 있다. 인증 주체에서만 푼다.
- **미인증이 401 이 아니라 403 으로 나왔다(또는 그 반대).**
  - 예외 처리 범위 밖의 스트림 엔드포인트는 인증 미들웨어·가드가 상태를 정한다. 미인증을 기본 403 으로 내는 프레임워크가 있다. 코드만 보고 단정하지 않는다.
  - 거부 응답 5종(CONTRACT.md §7 표)을 테스트로 고정한다.
- **세션이 만료됐는데 스트림이 계속 흘렀다.**
  - 이미 열린 연결은 세션 만료를 모를 수 있다. D10 서버 세션 항목대로 하트비트 때 다시 확인하거나 최대 연결 시간을 둔다.
- **플래그 하나만 봤다.**
  - 전송 전체가 꺼졌는데 모니터 플래그만 켜면 의존 객체(전송 클라이언트·모듈)가 없어 기동이 깨질 수 있다. 두 플래그를 함께 조건으로 건다.
- **연결 보관소를 다른 스트림과 같이 썼다.**
  - 키가 다르다(사용자 ID vs 테넌트). 섞으면 엉뚱한 연결에 보낸다. 인스턴스를 분리한다.
- **전화 마스킹이 짧은 번호를 거의 가리지 않았다.**
  - 「앞 3 + 뒤 4」를 모든 길이에 쓰면 7자 번호는 하나도 가리지 못한다. 8~10자도 1~3자리만 가린다.
  - 원래 숫자가 7자 이상이면 길이와 관계없이 최소 4자리를 가린다(MASKING.md §2 표).
- **마스킹 형식을 바꿨더니 저장값이 덮어써졌다.**
  - 모니터가 앱의 마스킹 유틸을 함께 쓰면(MASKING.md §2), 그 유틸을 고칠 때 앱의 API 응답 마스킹도 바뀐다.
  - 화면은 마스킹 값을 받아 숫자만 남긴 채 저장 요청에 되돌려 보낼 수 있다. `*` 가 사라져 「마스킹 값이면 변경 없음」 판정을 비켜 간다.
  - 그래서 「응답 마스킹 값의 숫자만과 같으면 변경 없음」 판정을 둔다. 형식을 바꾸면 이 판정은 새 형식만 알아본다.
  - 이미 옛 응답을 받아 둔 화면이 옛 형식의 숫자를 보내면 저장값을 그 숫자로 덮어쓴다.
  - 전환기에는 옛 형식의 숫자만도 「변경 없음」으로 인정하는 호환을 둔다. 모든 화면이 새 마스킹 응답을 다시 받은 뒤 지운다. 호환을 지울 조건을 그 코드 곁에 적는다.
  - 테스트: 옛 형식 숫자 · 새 형식 숫자 · 원문 재전송 · 실제 변경 넷을 넣어 저장값을 본다.
- **응답이 먼저 기록돼 기록 지점을 앞당기려 했다.** 송신 결과를 담으려면 송신 확인 시점이 맞다(D1). 앞당기지 않는다. 화면이 먼저 온 응답을 짝지어 푼다(RULES.md §2).

## §3 FE

- **SSE: EventSource 는 실패 응답의 상태·본문을 주지 않는다.** fetch 스트림·WebSocket 은 다르다(SKILL.md 3단계 2).
  - 연결이 닫힌 뒤(CLOSED)에만 같은 URL 에 상태 확인 요청을 보낸다. 연결 전에 보내면 스트림이 하나 더 열린다.
  - 상태 확인 응답이 2xx 면 본문을 읽지 않고 즉시 끊는다.
- **401 에서 멈췄다.** §0 D10. 갱신 경로를 먼저 탄다.
- **503 에서 멈췄다.** 테넌트 조회 장애는 일시적이다. 문구를 띄우고 재연결을 이어 간다.
- **파서가 계약 밖 값을 조용히 버렸다.** 버린 건수를 개발 콘솔에 남긴다. §0 D2.
- **시간 초과를 서버 시각으로 판정했다.**
  - 서버·브라우저 시계 오차가 판정에 섞인다. 시간 초과는 브라우저 수신 시각이다.
  - 반대로 소요는 서버 `at` 차이다. 브라우저 수신 시각에는 팬아웃·스트림 지연이 섞인다. **두 시계**를 섞지 않는다.
- **응답이 요청보다 먼저 와서 둘 다 짝 없음이 됐다.**
  - 「응답은 앞선 요청과만 짝」만 두면 응답은 「요청 없음」, 요청은 대기 → 시간 초과로 거짓을 말한다. 먼저 온 응답 창으로 푼다(RULES.md §2). 방향을 넓히지 않는다.
  - 소요가 음수로 나온다. 0 으로 자르지 않고 비운다(RULES.md §6).
  - 모니터와 현황판이 이 판정을 따로 쓰면 갈린다. 판정 순서 함수 하나를 두 어댑터가 부르고, 계약 테스트로 묶는다.
- **요청이 밀려난 응답이 action·소요를 잃었다.** 짝을 처음 맺을 때 요청 정보를 응답 항목에 기억한다(RULES.md §3).
- **멈춘 동안 상한을 줄였다.** 받은 버퍼와 멈춘 화면 버퍼를 함께 자른다. 새 메시지 수는 "다시 이어 볼 때 새로 보일 수"와 같아야 한다.
- **필터로 빠진 메시지의 상세를 닫았다.** 버퍼에 있으면 연 채로 두고 안내한다(RULES.md §13).
- **숫자가 바뀔 때마다 머리 띠가 흔들렸다.** 숫자 칸 폭을 미리 잡는다(UI.md §10).
- **화면 밖 행을 브라우저 찾기·e2e 선택자로 찾았다.** 가상 스크롤이라 DOM 에 없다. 검색칸으로 거른 뒤 찾는다. 가이드에 적는다.
- **popover 가 여럿 열렸다.** 한 묶음으로 관리해 하나만 연다. hover 로 열지 않는다.
- **모의 피드가 파서를 우회했다.** 모의 피드는 계약과 같은 이벤트 이름·`data` 문자열을 핸들러에 흘린다. 우회하면 파서 결함을 캡처가 숨긴다.
- **모의 피드가 운영 번들에 들어갔다.** mock 모드에서만 동적으로 불러온다.
- **참여자마다 색을 줬다.** 수백 참여자에서 색이 겹치고, 새로고침마다 색이 바뀐다. 역할색 2개로 둔다(RULES.md §14).
- **참여자 후보에 표시 상한을 뒀다.** 상한 밖 참여자는 검색어를 알아야만 고를 수 있다. 가상 스크롤로 보이는 줄만 그린다. 쉬는 패널도 같은 이유로 빼지 않는다.
- **1초 틱마다 목록 전체가 다시 그려졌다.**
  - 재판정이 새 객체를 만들면 내용이 같아도 모든 카드가 다시 그려진다. 이전 객체를 다시 쓴다(RULES.md §15).
  - 칸마다 로캘 포맷터를 새로 만들면 그것만으로 프레임 예산을 넘는다.
  - 수백 참여자 모의 피드(`?parties=N`)로 직접 띄워 본다. 단위 테스트로는 안 보인다.
- **두 화면의 머리 높이가 달라 오갈 때 튀었다.** 높이 토큰 하나를 두 화면이 최소 높이로 쓴다(UI.md §10).
- **차트 viewBox 를 고정 크기로 두고 늘렸다.** 축 글자·선 두께가 창 폭에 따라 바뀐다. 실제 폭을 재어 viewBox 폭으로 쓴다(RULES.md §17).
- **상수의 모양과 함수 인자의 모양이 달랐다.**
  - 타입 검사가 없는 화면 파일에서 상수 객체를 함수에 그대로 넘기면, 키 이름이 달라도 오류 없이 `undefined` 로 그려진다. 예: 차트 틀 상수의 여백 키와 함수가 읽는 키가 다르다.
  - 상수 → 함수 인자 변환은 타입이 있는 모듈 한 곳에서 한다. 그 경로를 테스트가 지난다.
- **현황판이 두 번째 수신부·두 번째 판정을 만들었다.**
  - 모니터와 현황판이 같은 메시지에 다른 결과를 낸다. 한쪽만 고치면 갈린다. 수신부와 판정 함수를 함께 쓴다(UI.md §14).

## §4 검증

- **전체 스위트로 판정했다.** 외부 자원(DB·캐시·브로커)이 필요한 테스트가 섞여 무관한 실패를 회귀로 본다. 대상만 좁게 돌린다. 애매하면 baseline 을 먼저 잰다.
- **출력을 파이프로 넘겼다.** 종료코드가 파이프 끝 명령의 것이 된다. 출력은 파일로 받고 종료코드로 판정한다.
- **직렬화 고정 기대값을 코드 출력에서 복사했다.** 그러면 지금 결함이 박제된다. 명세에서 다시 쓴다. 명세에 없는 부분(들여쓰기 등)은 「구현 실측(현행 고정)」이라고 출처를 적는다.
- **테스트가 레드를 못 냈다.** 핵심 판정(결과 판정·짝 규칙·마스킹 키)을 일부러 틀리게 고쳐 레드가 나는지 본다. 확인 뒤 되돌린다.
- **단언을 낮춰 통과시켰다.** 문구가 바뀌어 레드면 기대 문구 하나를 고친다. `contains`·`notNull` 로 내리지 않는다.

## §5 가이드

- **페이지를 열자마자 찍었다.**
  - 모의 피드는 동적으로 불러와 버퍼를 채운다. 로드 직후에는 목록이 비어 있다.
  - 건수가 **0 보다 커질** 때까지 실제 시간으로 기다린 뒤 가짜 시계를 앞으로 돌린다. 「숫자가 보인다」로 기다리면 `총 0건` 에도 맞아 빈 화면을 찍는다.
- **모의 피드가 첫 묶음을 타이머 뒤에 냈다.** 캡처는 가짜 시계를 멈춘 채 기다린다. 멈춘 시계에서는 타이머가 돌지 않아 첫 묶음이 오지 않는다. 첫 묶음은 피드를 시작할 때 동기로 낸다(SKILL.md 3단계 7).
- **난수를 고정하지 않아 ID·순서가 매번 바뀌었다.** 페이지 스크립트보다 먼저 `Math.random`·UUID 생성을 seed 난수로 바꾼다.
- **포인터가 남아 hover 모양이 찍혔다.** 찍기 전에 포인터를 대상 밖으로 치운다.
- **화면 설정이 이전 실행 값으로 찍혔다.** 저장값을 매 장면 페이지 로드 전에 넣는다.
- **로그인·연결 실패 화면을 모의 모드로 찍으려 했다.** 모의 모드는 그 경로를 건너뛴다. 그 절은 표와 글로 쓴다.
- **문구를 화면에서 다시 타이핑했다.** 오타가 생긴다. 상수 파일에서 옮긴다.
- **캡처에 실제 값이 들어갔다.** 실제 환경을 찍지 않는다. 합성값만 쓴다.
